# AI 태그 추천 설계

> 작성일 2026-10-05 · 담당: 김민서 · 관련: Tier C "AI 태그 추천" (강성찬 BASE-20, 나민서 AI-02·D-7, 김민서 AI-1·P-16·SCALE-4)
> 원칙 (세 문서 공통): **AI는 제안만 한다. 사용자가 골라야 반영되고, AI가 실패해도 글쓰기·자동 저장·발행에는 영향이 없다.**

## 2. 구조

```
[AI 태그 추천] 버튼
 → TagSuggestService
     ① 권한·동의·한도 확인
     ② 입력 정리 (§4)  → 정리된 입력의 해시
     ③ 캐시 확인 (§5)  → 있으면 바로 응답 (한도 차감 없음)
     ④ TagSuggesterRouter가 공급자 선택 (§3)
          GeminiTagSuggester  ──(무료 한도 소진·장애)──▶  OllamaTagSuggester
     ⑤ 응답 검증 (§6) → 캐시에 저장 → 응답
```

| 클래스 | 역할 |
|---|---|
| `TagSuggester` (인터페이스) | `List<String> suggest(TagSuggestInput input)` |
| `GeminiTagSuggester` | Gemini API 호출, JSON 스키마로 출력 형식 지정 |
| `OllamaTagSuggester` | 자체 서버의 Ollama 호출, `format`에 JSON 스키마 지정 |
| `DisabledTagSuggester` | 기능을 끈 경우 (버튼 숨김) |
| `TagSuggesterRouter` | 공급자 상태(Redis)를 보고 어느 구현을 쓸지 결정 |

설정값 (`application.yml`, 비밀값은 환경 변수):

```yaml
blog:
  ai:
    tag-suggest:
      enabled: true
      prompt-version: 1            # 프롬프트를 바꾸면 올린다 → 캐시 키가 바뀜
      gemini:
        model: gemini-flash-lite   # 실제 모델 이름은 AI Studio에서 무료 한도가 넉넉한 것으로
        daily-limit: 450           # AI Studio에 보이는 하루 한도보다 조금 낮게
        timeout: 10s
        max-input-chars: 8000
      ollama:
        base-url: http://ollama:11434
        model: qwen2.5:1.5b         # §8 측정: 2,000자 약 6초
        num-thread: 4              # 서버의 "성능 코어 수" 이하로. 모든 코어를 쓰면 140배 느려졌다 (§8)
        timeout: 30s
        max-input-chars: 2000
        max-concurrency: 1
# GEMINI_API_KEY 는 환경 변수로만
```

## 3. 공급자 전환 (Gemini 무료 → Ollama)

### 3-1. Gemini 무료 등급의 특징

| 항목 | 내용 |
|---|---|
| 한도 | 분당 요청 수(RPM), 하루 요청 수(RPD), 분당 토큰 수가 모델마다 다르다. **Google이 문서에 숫자를 고정해 두지 않고 AI Studio에서 실시간으로 보여주며, 2026년에 여러 번 줄었다** (2026년 9월 기준 일부 Flash 모델은 하루 약 20회, Flash-Lite는 약 500회라는 보고가 있다) |
| 한도 초과 | HTTP 429 |
| 결론 | 한도를 코드에 박지 않고 설정값으로 둔다. **우리가 센 횟수**와 **실제 429 응답** 두 가지로 판단한다 |

### 3-2. 라우터 규칙

```
요청이 오면:
 ① Redis ai:gemini:exhausted 가 있으면          → Ollama
 ② Redis ai:gemini:cooldown 이 있으면           → Ollama
 ③ 오늘 Gemini 호출 수 ≥ gemini.daily-limit     → exhausted 표시 후 Ollama   (429를 받기 전에 미리 전환)
 ④ 그 외                                         → Gemini

Gemini 응답이:
 · 429 (하루 한도)        → ai:gemini:exhausted 를 다음 한도 초기화 시각까지 설정 → 같은 요청을 바로 Ollama로
 · 429 (분당 한도)        → ai:gemini:cooldown 60초 → 같은 요청을 바로 Ollama로
 · 429 (종류를 모름)      → cooldown 60초. 같은 날 3번 연속이면 exhausted로
 · 타임아웃·5xx          → cooldown 60초. 이 요청은 실패로 응답 (시간이 이미 10초 지나서 Ollama까지 기다리게 하지 않음)
 · 성공                   → 오늘 호출 수 +1
```

| Redis 키 | 값 |
|---|---|
| `ai:gemini:count:{날짜}` | 오늘 Gemini 호출 수. 날짜는 Gemini 한도가 초기화되는 기준 시간대로 계산 (구현 시 AI Studio에서 초기화 시각 확인) |
| `ai:gemini:exhausted` | 하루 한도 소진 표시, 다음 초기화 시각까지 |
| `ai:gemini:cooldown` | 일시 중단, 60초 |
| `ai:ollama:inflight` | 동시에 처리 중인 Ollama 요청 수 (`max-concurrency` 넘으면 "잠시 후 다시 시도해 주세요") |

### 3-3. 시간 제한

| 공급자 | 타임아웃 | 이유 |
|---|---|---|
| Gemini | 10초 (나민서 AI 공통 규칙) | |
| Ollama | **30초** | §8 측정: 2,000자 입력에 약 6초. 화면에 "자체 AI로 추천 중이라 조금 걸려요" 표시 |

어느 쪽이든 실패하면 "지금은 추천할 수 없어요"만 보여주고 글쓰기에는 영향이 없다.

## 4. 입력 정리 — 토큰 줄이기

LLM에 보내기 전에 서버가 정리한다. 같은 내용이면 같은 결과가 나오도록 **정리된 입력으로 캐시 키를 만든다** (§5).

```
① Markdown 기호 제거: 제목 기호(#), 강조(**), 목록 기호, 인용(>)
② 이미지 문법 통째로 제거, 링크는 글자만 남기고 주소 제거
③ 코드 블록: 언어 이름 + 앞 5줄만 남김 (언어·프레임워크 단서는 유지)
④ 연속 공백·줄바꿈을 하나로, NFC 정규화, 소문자는 바꾸지 않음
⑤ 공급자별 최대 글자 수로 자름: Gemini 8,000자 / Ollama 2,000자
⑥ 정리 후 100자 미만이면 LLM을 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"
```

| 프롬프트 구성 (고정된 것이 앞) | 내용 |
|---|---|
| 1. 지시문 (고정) | "이 블로그 글의 핵심 주제를 나타내는 태그를 최대 N개 고르세요. **글에 나오지 않는 기술은 넣지 마세요.** 태그는 영어 소문자와 하이픈만. JSON으로만 답하세요." |
| 2. 기존 인기 태그 (하루 1번 바뀜) | Gemini: 상위 **50개** (토큰 절약을 위해 100개에서 줄임) / Ollama: 상위 50개 중 **글에 실제로 나오는 것만**. "이 중 맞는 것이 있으면 그 표기를 그대로 쓰세요". Redis `ai:tag:popular:{날짜}`에 하루 보관 |
| 3. 이미 붙인 태그 | "이것은 제외" |
| 4. 제목 + 정리된 본문 (매번 다름) | |

- 고정된 부분을 앞에 두면 공급자 쪽의 같은 앞부분 재사용(Ollama는 같은 앞부분을 다시 계산하지 않음)에 유리하다.
- 출력은 태그 배열만 받고 최대 출력 토큰을 작게(100) 잡는다.

## 5. Redis 캐싱 — LLM 결과 재사용 (A-8)

### 5-1. 두 단계 캐시

| 단계 | 키 | 맞으면 | 보관 |
|---|---|---|---|
| **① 같은 내용** | `ai:tag:v{prompt-version}:{SHA-256(정리된 입력)}` | 정리된 입력이 완전히 같으면 저장된 추천을 그대로 | 30일 |
| **② 거의 같은 내용** | `ai:tag:post:{postId}` = `{정리된 입력, 추천, 공급자, 시각}` | 같은 글의 지난번 정리된 입력과 지금 입력의 **3글자 단위 유사도(Jaccard)가 0.9 이상**이면 저장된 추천을 재사용 | 7일 |

```
요청 → 입력 정리 → ① 같은 내용 캐시 → 없으면 ② 같은 글의 비슷한 내용 → 없으면 LLM 호출 → ①②에 저장
응답할 때마다: 이미 붙인 태그를 빼고 남은 자리만큼만 보여준다 (캐시에는 태그를 빼기 전 결과를 저장)
```

| 규칙 | 이유 |
|---|---|
| 캐시 키에 **이미 붙인 태그를 넣지 않는다** | 태그 하나를 붙였다고 다시 LLM을 부르지 않게. 빼는 것은 응답할 때 한다 |
| 캐시 키에 **인기 태그 목록을 넣지 않는다** | 하루마다 바뀌어서 넣으면 캐시가 매일 무효가 된다. 프롬프트 형식을 바꿀 때만 `prompt-version`을 올린다 |
| 캐시로 응답하면 **하루 20회에서 빼지 않는다** | LLM을 부르지 않았으므로. 응답에 `cached: true` |
| **[다시 추천]** | ②(비슷한 내용)를 건너뛰고 새로 묻는다. ①(완전히 같은 내용)은 그대로 쓰되, 저장된 결과가 Ollama가 만든 것이고 지금 Gemini를 쓸 수 있으면 Gemini로 다시 만든다 |
| 저장하지 않는 것 | 실패·빈 결과, 검증(§6)에서 모두 걸러진 결과 |
| ② 저장 크기 | 정리된 입력은 최대 8,000자(약 24KB). 글당 1개, 7일 뒤 자동 삭제 |
| 다른 사람과 공유 | ①은 내용이 같으면 사용자와 상관없이 재사용된다 (같은 글을 복사해 올린 경우 등). 키는 내용의 해시라서 내용 자체는 키에 남지 않는다 |

### 5-2. 기대 효과

| 상황 | LLM 호출 |
|---|---|
| 같은 글에서 버튼을 여러 번 누름 | 첫 1번만 |
| 태그를 하나 붙인 뒤 다시 누름 | 0번 (캐시 결과에서 붙인 태그만 뺌) |
| 오타 몇 개를 고친 뒤 다시 누름 | 0번 (② 비슷한 내용) |
| 긴 글에 문장 하나를 더한 뒤 다시 누름 | 0번 (② 비슷한 내용, 유사도 0.93) |
| 글을 많이 고친 뒤 다시 누름 | 1번 |

### 5-3. 검증 결과 (2026-10-05, 프로토타입)

**① 입력 정리와 같은 내용 판정** — 원문 567자 → 정리 398자 (30% 감소)

| 변경 | ① 해시 | 판정 |
|---|---|---|
| 완전히 같음 / 공백·줄바꿈만 다름 / 이미지 주소만 바뀜 | 같음 | ① 재사용 |
| 정리 후 23자인 짧은 글 | — | LLM을 부르지 않음 |

**② 비슷한 내용 판정** (3글자 Jaccard, 기준 0.9)

| 변경 | 짧은 글(정리 후 304자) | 긴 글(정리 후 4,437자) |
|---|---|---|
| 오타 2개 수정 | 0.97 → 재사용 | 0.99 → 재사용 |
| 문장 1개 추가 | 0.87 → LLM 호출 | 0.93 → 재사용 |
| 문단 10% 교체 | 0.76 → LLM 호출 | 0.87 → LLM 호출 |
| 본문 절반 교체 | 0.56 → LLM 호출 | 0.70 → LLM 호출 |
| 전혀 다른 글 | 0.05 → LLM 호출 | 0.03 → LLM 호출 |

계산 시간은 긴 글에서도 1ms 이내.

> 처음에는 SimHash(64비트, 다른 비트 3개 이하)로 설계했는데, 짧은 글에서는 오타 2개만 고쳐도 거리가 8이 나와 재사용되지 않았다. 지난번 정리된 입력을 저장해 두고 실제 텍스트끼리 유사도를 계산하는 방식으로 바꿨다.

## 6. 응답 검증

| 단계 | 처리 |
|---|---|
| 형식 | 두 공급자 모두 **JSON 스키마**로 출력 형식을 강제한다: `{ "tags": [string, …] }`, 최대 5개. Ollama는 스키마의 `description`을 모델에 전달하지 않는다는 보고가 있어, 필요한 설명은 지시문에 넣는다 |
| 파싱 실패 | 실패로 처리 (캐시에 저장하지 않음) |
| 정규화 | 강성찬 C-TAG-1 태그 규칙 (소문자, 앞뒤 공백 제거, 중복 제거, 길이) |
| 거르기 | 이미 붙인 태그, 금칙어(09 필터), 규칙에 맞지 않는 태그 |
| 결과 0개 | "추천할 태그를 찾지 못했어요" |

## 7. 개인정보와 동의

### 7-1. Gemini 무료 등급의 데이터 사용 (2026-10-05 확인)

Gemini API 추가 약관에 따르면, **무료 등급(Unpaid Services)에서는 보낸 내용과 응답을 Google이 제품·머신러닝 기술을 개선하는 데 사용하고, 사람이 읽고 검토할 수 있다** (검토 전에 계정·API 키 정보와 분리). 유료 등급에서는 개선에 사용하지 않는다.

### 7-2. 동의

처음 [AI 태그 추천]을 누르면:

```
AI 태그 추천을 사용할까요?
· 글 제목과 본문 앞부분이 Google Gemini(무료 등급)로 전송됩니다.
  Google은 이 내용을 서비스 개선에 사용할 수 있고, 사람이 검토할 수도 있습니다.
· Gemini를 쓸 수 없을 때는 우리 서버의 AI(Ollama)로 처리하며, 이때는 외부로 전송되지 않습니다.
· 개인정보·비밀번호·회사 기밀이 들어간 글에는 사용하지 마세요.
                                            [동의하고 추천받기] [취소]
```

| 항목 | 규칙 |
|---|---|
| 저장 | `member.ai_consent_at` (동의 시각). 동의 문구가 바뀌면 다시 묻는다 (`ai_consent_version`은 개인 확장) |
| 철회 | 설정 화면에서 동의 취소 → `ai_consent_at = null` |
| 처리방침 | 개인정보 처리방침에 "외부 AI 서비스(Google Gemini)로의 전송"과 무료 등급의 데이터 사용 방식 추가 |
| 보내지 않는 것 | 다른 사람의 글, 이메일·닉네임 등 회원 정보 |

## 8. Ollama 실측

측정 환경: MacBook Air(Apple Silicon, 성능 코어 4 + 효율 코어 4), Docker(arm64, CPU만), Ollama 0.35.1, `qwen2.5:1.5b`(986MB). 측정 중 다른 작업으로 컴퓨터 부하 약 13. **배포 서버에서 다시 재야 한다.**

### 8-1. 스레드 수 — 가장 중요한 설정

| `num_thread` | 생성 속도 | 짧은 글 총 시간 |
|---|---|---|
| 8 (기본값 = 모든 코어) | **0.4토큰/초** | 약 90초 |
| **4 (성능 코어 수)** | **55토큰/초** | **3.6초** |
| 2 | 50토큰/초 | 2.9초 |

기본값은 느린 효율 코어까지 모두 써서 서로 기다리느라 약 140배 느려졌다. JSON 스키마 강제 여부와는 상관없었다 (스키마 / JSON 모드 / 형식 없음 모두 0.4토큰/초). **서버의 성능 코어 수 이하로 설정한다.**

### 8-2. 입력 길이별 시간 (`num_thread=4`)

| 정리된 입력 | 입력 토큰 | 총 시간 |
|---|---|---|
| **2,000자 (설정값)** | 약 1,000 | **5.6~6.9초** |
| 4,000자 | 약 1,900 | 7.3~7.4초 |
| 8,000자 | 약 3,750 | 20~28초 |

생성(태그 5개, 약 35토큰)은 1초 안팎이고 대부분이 입력 처리 시간이다. 2,000자면 타임아웃 30초 안에 넉넉하다. 서버 성능이 비슷하면 4,000자까지 늘려도 된다.

### 8-3. 품질

| 프롬프트 | 결과 (글 주제: JPA N+1) |
|---|---|
| "기존 태그 중 맞는 것이 있으면 그것을 쓰세요" + 인기 태그 15개 | **목록 앞에서 5개를 그대로 베낌** (`spring, spring-boot, jpa, java, docker` — docker는 글과 무관) |
| §4 지시문 ("글에 나오지 않는 기술은 넣지 마세요") + 인기 태그 20개 | `jpa, n+1, batch-size, entity-graph, fetch-join` 등 **글에 맞는 태그**, 베끼기 없음 |
| §4 지시문 + 글에 나오는 인기 태그만 | `jpa, hibernate, n+1, batch size, entity graph` |

- 작은 모델은 지시문에 크게 좌우된다. §4 지시문을 쓴다.
- **"영어 소문자와 하이픈만" 규칙은 자주 어긴다** (`JPA`, `N+1 문제`, `batch size`). 그래서 §6 서버 정규화가 반드시 필요하다.
- JSON 형식은 모든 요청에서 스키마대로 나왔다 (`format`에 JSON 스키마).

## 9. API와 화면

```
POST /api/posts/{postId}/tag-suggestions
{ "title": "…", "contentMd": "…", "currentTags": ["spring"], "refresh": false }
→ 200 { "tags": ["jpa", "transaction", "spring-boot"], "provider": "gemini", "cached": false,
        "truncated": true, "remainingToday": 17 }
```

| 응답 | 경우 |
|---|---|
| 403 | 남의 글, 이메일 인증 전 |
| 409 `AI_CONSENT_REQUIRED` | 아직 동의하지 않음 → 동의 창 |
| 422 `CONTENT_TOO_SHORT` | 정리 후 100자 미만 |
| 429 `AI_DAILY_LIMIT` | 개인 하루 20회 초과 |
| 503 `AI_UNAVAILABLE` | Gemini·Ollama 모두 실패, Ollama 동시 처리 초과, 기능 꺼짐 |

```
태그  [spring ×] [입력…]          [✨ AI 태그 추천]  (오늘 17회 남음)
       추천: (+ jpa) (+ transaction) (+ spring-boot)        [다시 추천]
       본문 앞부분을 보고 추천했어요 · AI 제안이에요
```

## 10. 공통 완료 기준

| # | 기준 |
|---|---|
| 1 | 버튼을 누를 때만 호출되고, 추천은 사용자가 눌러야 태그에 추가된다 |
| 2 | 동의하지 않으면 아무것도 전송되지 않는다 |
| 3 | Gemini 한도가 다 되거나 429가 오면 같은 요청이 Ollama로 처리되고, 한도가 초기화될 때까지 Ollama를 쓴다 |
| 4 | 같은 내용으로 다시 누르면 LLM을 부르지 않고 캐시로 응답하며, 하루 횟수가 줄지 않는다 |
| 5 | 이미 붙인 태그, 금칙어, 규칙에 맞지 않는 태그는 추천에 나오지 않는다 |
| 6 | 두 공급자가 모두 실패해도 글쓰기·자동 저장·발행은 정상이다 |
| 7 | API 키는 환경 변수로만 주입되고 로그에 남지 않으며, 글 내용도 로그에 남지 않는다 |
