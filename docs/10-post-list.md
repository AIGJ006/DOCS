# 전체 글 목록과 개인 블로그 페이지 설계

> 작성일 2026-10-02 · 관련 요구사항: C-READ-1(전체 글 목록), C-BLOG-1(개인 블로그). 연관: [05 발행](./05-publish.md) §3, [06 공개 범위](./06-visibility.md) §3
> 두 화면은 **같은 글 카드, 같은 개수(9개), 같은 [더 보기]**를 쓴다.
> **공통 범위 (2026-10-07 회의 O5):** 공통은 *무엇을 보여 주는가*(카드에 들어갈 정보, 9개씩 + [더 보기], 날짜 형식, 로딩·빈 목록·오류 상태와 문구)와 640px 썸네일 생성이다. *어떻게 보이는가*(색·글꼴·레이아웃·카드 배치 개수·썸네일 비율·빈 썸네일 색)는 각자 자유이고, 이 문서의 해당 값은 참고용 예시다. 화면은 React, 목록은 REST API로 받는다 (Q2·H7).

## 1. 결정 사항

| # | 안건 | 결정 | 이유 |
|---|---|---|---|
| L-1 | 정렬·표시 기준인 "발행 시각" | **`first_public_at`**(처음 공개된 시각) 최신순, 같으면 글 ID 큰 순. 카드의 "발행 날짜"도 같은 값 | 비공개로 발행했다가 나중에 공개한 글이 목록 뒤쪽에 묻히지 않는다 (05 P-3). 공개로 바로 발행한 글은 `published_at`과 같다 |
| L-2 | 한 번에 불러오는 개수 | **9개.** 10개를 조회해서 마지막인지 판단 | 버튼을 눌렀는데 빈 결과가 오는 일이 없다 |
| L-3 | 본문 첫 세 줄 | **화면 기준 3줄** + 짧아도 3줄 높이 확보. 요약을 **200자**로 늘리고 코드 블록·이미지·표는 빼고 만든다 | 넓은 카드의 영문 글은 150자로 3줄이 안 찬다. 개발 글은 앞부분이 코드인 경우가 많다 |
| L-4 | 배치 | (예시) 1024px 이상 3개 / 640~1023px 2개 / 640px 미만 1개. **각자 자유 (2026-10-07 O5)** | 360px 화면에 3개를 두면 썸네일이 너무 작다 |
| L-5 | 날짜 표시 | 24시간 이내 "N시간 전"(1시간 이내 "N분 전"), 그 이후 `2026.10.02` | |
| L-6 | 뒤로 가기 | 불러온 카드와 스크롤 위치를 복원 (`sessionStorage`, 30분) | [더 보기]를 여러 번 누른 뒤 글을 보고 돌아와도 처음부터 다시 누르지 않는다 |
| L-7 | 썸네일 빈 영역 색 | (예시) 옅은 회색 `#F1F3F5`, 다크 모드는 어두운 회색. **각자 자유 (2026-10-07 O5)** | 흰 카드 위의 흰 영역은 보이지 않아 카드가 깨진 것처럼 보인다 |
| L-8 | 썸네일 용량 | 사진을 올릴 때 **브라우저가 640px 썸네일도 함께 만들어** 올리고, 카드에는 그것을 쓴다 | 원본 9장(약 3.6MB)은 모바일에서 무겁다. 썸네일 9장은 약 0.4MB |
| L-9 | 개인 블로그 | 전체 목록과 같은 카드·개수·[더 보기], 상단에 프로필 | |

## 2. 글 카드

```
┌──────────────────────────┐
│                          │
│     썸네일 (예: 16:9)      │  ← 없으면 같은 크기의 빈 영역 (비율·색은 각자 자유)
│                          │
├──────────────────────────┤
│ JPA N+1 문제를 fetch jo…  │  ← 제목 1줄
│ 지연 로딩으로 연관 엔티티를  │
│ 조회할 때 쿼리가 N번 더     │  ← 본문 미리보기 3줄 (항상 3줄 높이)
│ 실행되는 문제가 있다. 이…   │
│ 2026.10.02 · 💬 3         │  ← 발행 날짜 · 댓글 수
│ 🙂 김민서        ♥ 12      │  ← 작성자 · 좋아요 수
└──────────────────────────┘
```

| 요소 | 데이터 | 규칙 |
|---|---|---|
| 썸네일 | `post.thumbnail_url` (640px 썸네일, §6) | `loading="lazy"`, `alt`는 제목. 비율(예: `aspect-ratio: 16 / 9`, `object-fit: cover`)은 각자 자유 (O5) |
| 썸네일 없음 | — | 같은 크기의 빈 영역. 색(예: 라이트 `#F1F3F5`, 다크 `#2B2F33`)은 각자 자유 (O5) |
| 제목 | `post.title` | 1줄, 넘치면 `…`. `title` 속성으로 전체 제목 |
| 본문 미리보기 | `post.excerpt` | `line-clamp: 3`, 넘치면 `…`. **내용이 짧아도 3줄 높이(`min-height`)를 확보**해서 카드 높이를 맞춘다. 요약이 비어 있으면(코드만 있는 글 등) 빈 3줄 |
| 발행 날짜 | `post.first_public_at` | L-5 형식. `<time datetime="…">`로 원래 시각도 넣는다 |
| 댓글 수 | `post.comment_count` | 삭제되지 않은 댓글 수, 0이어도 표시 |
| 작성자 | 프로필 사진: `image` LEFT JOIN(`uploader_id = member.id`, `purpose = 'PROFILE'`, `status = 'ATTACHED'`, `detached_at IS NULL`)의 `thumb_storage_key`(없으면 `storage_key`) → 앱이 공개 주소 + 키로 주소를 만든다(2026-10-07 결정, [03 E-21](./03-erd.md)). `member.nickname` | 작은 프로필 사진(없으면 기본 아이콘) + 닉네임. 누르면 `/@블로그주소` |
| 좋아요 수 | `post.like_count` | 0이어도 표시 |
| 누르는 영역 | — | 카드 전체 → 글 상세, 작성자 영역만 → 블로그. 키보드로도 이동 가능 (카드 안 링크 2개) |

### 2-1. 요약(`excerpt`) 만들기 — [05 §7](./05-publish.md) ②의 세부 규칙

```
정화된 HTML에서
 1. 코드 블록(<pre>), 이미지, 표, 수식은 통째로 뺀다
 2. 제목·문단·목록의 글자만 꺼낸다 (인라인 코드·링크는 글자로 남긴다)
 3. 줄바꿈과 연속 공백을 공백 하나로
 4. 앞 200자 (단어 중간에서 잘리면 그 단어 앞에서 자른다)
```

## 3. 배치 (예시 — 각자 자유, 2026-10-07 O5)

| 화면 폭 | 한 줄에 | 9개를 불러오면 |
|---|---|---|
| 1024px 이상 | 3개 | 3줄 |
| 640~1023px | 2개 | 4줄 반 (마지막 줄 1개) |
| 640px 미만 | 1개 | 9줄 |

같은 줄의 카드는 높이가 같다 (썸네일 비율 고정 + 제목 1줄 + 미리보기 3줄 높이 고정). 공통으로 지킬 것은 "페이지 가로 스크롤이 없다"뿐이다.

## 4. [더 보기]

### 4-1. 동작

```
처음 열기 : 최신 9개. React 화면이 API(§4-2)로 받아 그린다 (2026-10-07 회의 Q2·H7)
[더 보기] : 마지막 카드보다 이전 글 9개를 아래에 이어 붙인다
더 없으면 : 버튼이 사라지고 "모든 글을 다 봤어요"
```

### 4-2. API

```
GET /api/posts?cursor={cursor}&size=9                     ← 전체 글 목록
GET /api/members/{handle}/posts?cursor={cursor}&size=9    ← 개인 블로그
```

```json
{
  "items": [
    { "id": 42, "url": "/@kim755030/posts/42", "title": "JPA N+1 정리",
      "excerpt": "지연 로딩으로 연관 엔티티를 조회할 때 …", "thumbnailUrl": "https://…/thumb.webp",
      "firstPublicAt": "2026-10-02T14:03:12.123Z", "commentCount": 3, "likeCount": 12,
      "author": { "handle": "kim755030", "nickname": "김민서", "profileImageUrl": null } }
  ],
  "nextCursor": "eyJ2IjoxLCJrIjpbMTc5MDc1NTIwMDEyMzQ1NiwzN119"
}
```

| 규칙 | 내용 |
|---|---|
| 커서 | **서버만 해석하는 불투명 값** (2026-10-07 회의 O8). 마지막 카드의 정렬 키를 JSON `{"v":1,"k":[시각, id]}`로 만들어 Base64URL(패딩 없음)로 감싼다. 위 예시는 `{"v":1,"k":[1790755200123456,37]}`. 클라이언트는 받은 값을 그대로 돌려보낼 뿐 만들거나 풀지 않는다 |
| 시각 정밀도 | `k`의 시각은 **정수 마이크로초**(epoch, UTC). PostgreSQL `timestamptz` 정밀도와 같아서 같은 초·같은 밀리초 안의 글도 빠지지 않는다. 서버는 풀어서 `WHERE (first_public_at, id) < (:t, :id)` |
| 다른 목록 | 태그·피드·검색·트렌딩·댓글 등 모든 커서 목록이 이 형식을 쓴다. 정렬 키가 다르면 `k`에 그 키를 넣고(예: `(published_at, id)`), 정렬 종류·스냅샷처럼 기능에 필요한 값은 같은 JSON에 필드를 더한다(예: `s`, `snap`). 형식이 바뀌면 `v`를 올린다 |
| 마지막 판단 | **10개를 조회**해서 10개면 9개만 보내고 `nextCursor`를 준다. 9개 이하면 `nextCursor: null` → 버튼 숨김 |
| `size` | 클라이언트가 무엇을 보내도 서버는 9로 고정 |
| 잘못된 커서 | Base64URL·JSON으로 풀리지 않음, 모르는 `v`, 필드 누락·타입 오류, 다른 목록의 커서 → 400 `INVALID_CURSOR` (오류 본문은 O8 공통 형식 `{ code, message, errors, details }`) |
| 첫 페이지 | `cursor` 없이 요청 |

### 4-3. 중복·누락이 없는 이유

| 보는 도중에 | 결과 |
|---|---|
| 새 글이 올라옴 | 커서보다 최신이라 이어 붙는 목록에 끼어들지 않는다. 새로 고치면 맨 위에 보인다 |
| 글이 삭제·비공개됨 | 커서는 "값"(시각, ID)이라 그 행이 사라져도 기준이 흔들리지 않는다. 이미 화면에 있는 카드는 남고, 누르면 404 |
| 글이 수정됨 | `first_public_at`은 바뀌지 않으므로 순서가 바뀌지 않는다 |
| 비공개 글이 처음 공개됨 | 그 순간이 `first_public_at`이 되어 맨 위에 생긴다. 커서보다 최신이라 이어 붙는 목록에 끼어들지 않는다 |
| (이중 안전장치) | 브라우저가 이어 붙일 때 이미 있는 글 ID는 건너뛴다 |

### 4-4. 로딩·실패·뒤로 가기

| 상황 | 처리 |
|---|---|
| 불러오는 중 | 버튼을 "불러오는 중…"으로 바꾸고 비활성화 |
| 실패 | "불러오지 못했어요 [다시 시도]" (같은 커서로 다시 요청) |
| 뒤로 가기 | 불러온 카드 목록·`nextCursor`·스크롤 위치를 `sessionStorage`에 30분 보관하고, 돌아오면 복원. 보관값이 없거나 30분이 지나면 처음 9개부터 (L-6) |

## 5. 개인 블로그 페이지 (`/@블로그주소`)

```
┌────────────────────────────────────────────┐
│ (프로필 이미지) 김민서 @kim755030             │
│ 백엔드 개발을 공부하고 있어요.   · 공개 글 24 │
├────────────────────────────────────────────┤
│ [카드] [카드] [카드]                          │
│ [카드] [카드] [카드]     ← §2와 같은 카드 (작성자 영역만 생략)
│ [카드] [카드] [카드]                          │
│              [더 보기]                       │
└────────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 상단 | 프로필 사진(§2 작성자와 같은 `image` JOIN), 닉네임, `@블로그주소`, 소개, 공개 글 수 (보는 사람 기준으로 센다, 06 §3) |
| 목록 | §2 카드에서 작성자 영역만 뺀 것. 9개, [더 보기] |
| 정렬 | `first_public_at DESC, id DESC` |
| 대상 | 공개·발행 글만(06 R-2a 공용 조건: 휴지통·관리자 숨김·탈퇴 신청 작성자 글 제외). 내 블로그여도 비공개 글·숨긴 글은 안 보인다 — 내 글 관리에서만 (06 V-8) |
| `FRIENDS` 적용자 | 친구가 보면 친구 공개 글도 포함하고 `published_at DESC, id DESC`로 정렬, 커서의 `k`도 `(published_at, id)` (§4-2 형식, 06 §6-3) |
| 없는 블로그 주소 | 404. 대문자 주소는 소문자로 301 (08 §6) |
| 빈 상태 | 남이 볼 때 "아직 공개한 글이 없어요" / 본인이 볼 때 "첫 글을 써 보세요 [글쓰기]" |
| 개인 확장 | 나민서 카테고리 사이드바·페이지 번호·고정 글, 김민서 시리즈 탭 |

## 6. 썸네일 (L-8)

[04 §4-1](./04-draft-and-image.md) 업로드 흐름에 썸네일 만들기를 더한다.

```
② [브라우저] 원본: 긴 변 최대 1920px, WebP 0.8, EXIF 제거
            썸네일: 가로 최대 640px, WebP 0.8         ← 추가 (GIF는 첫 장면으로 정지 이미지)
③ POST /api/images/presign {contentType, size, thumbSize}  → 업로드 주소 2개 (원본, 썸네일)
④ 두 파일을 각각 업로드
⑤ complete: 서버가 두 파일 모두 검사 (형식·크기·해상도). 썸네일은 가로 640px 이하, 1MB 이하
```

| 항목 | 규칙 |
|---|---|
| 저장 키 | 원본 `images/2026/10/{uuid}.webp`, 썸네일 `images/2026/10/{uuid}_thumb.webp` (`image.thumb_storage_key`) |
| 카드 | `post.thumbnail_url` = 본문 **첫 번째 업로드 이미지의 썸네일** 주소 (발행할 때 지정) |
| 글 상세·링크 미리보기(OG) | 원본 사용 |
| 썸네일이 없는 옛 사진 | 원본 주소로 대체 |
| 정리 | 버려진 사진을 지울 때 썸네일 파일도 함께 지운다 (04 §4-4) |

## 7. 성능

| 항목 | 설계 | 기준 |
|---|---|---|
| 쿼리 수 | **목록당 1번** (글 + 작성자 + 프로필 사진 JOIN). 카드에 태그가 없어 태그 조회 불필요. 댓글·좋아요 수는 미리 저장된 값 | N+1 없음 (나 NFR-07) |
| 조회 컬럼 | 본문(`content_md`, `content_html`) 제외, 카드 컬럼만 | |
| 인덱스 | 전체 목록 `ix_post_feed`, 블로그 `ix_post_blog` (V1 `erd/V1__common_schema.sql`). 쿼리 WHERE에 두 인덱스의 조건(`hidden_at IS NULL` 포함)이 모두 있어야 한다 (06 R-2b) | 인덱스만으로 정렬·범위 조회 |
| 전송량 | 카드 9장 썸네일 약 0.4MB, `loading="lazy"` | 김 PERF-8 |

```sql
-- 전체 글 목록 (첫 페이지는 커서 조건 없이)
SELECT p.id, p.title, p.excerpt, p.thumbnail_url, p.first_public_at, p.comment_count, p.like_count,
       m.handle, m.nickname,
       COALESCE(pi.thumb_storage_key, pi.storage_key) AS profile_image_key  -- 주소 = 공개 주소 + 키 (앱이 만듦)
FROM post p
JOIN member m ON m.id = p.author_id
LEFT JOIN image pi ON pi.uploader_id = m.id AND pi.purpose = 'PROFILE'
                  AND pi.status = 'ATTACHED' AND pi.detached_at IS NULL   -- 회원당 하나 (uq_image_profile_current)
WHERE p.status = 'PUBLISHED' AND p.visibility = 'PUBLIC'
  AND p.deleted_at IS NULL AND p.hidden_at IS NULL  -- ix_post_feed WHERE와 같은 조건 (2026-10-07 회의 H1)
  AND m.withdrawn_at IS NULL                       -- VisibilityFilter(06 R-2a) 조건 전체: PUBLISHED·PUBLIC·deleted_at·hidden_at·withdrawn_at
  AND (p.first_public_at, p.id) < (:cursorFirstPublicAt, :cursorId)  -- §4-2 커서를 서버가 풀어서 넣음
ORDER BY p.first_public_at DESC, p.id DESC
LIMIT 10;   -- 9개 + 다음 페이지가 있는지 확인용 1개
```
