## 2. 공통 최소 요구사항

### 2-1. Tier A — 공통 필수 (세 문서 모두 최우선 순위)

모두 구현하고, 공통 ERD·아키텍처에 반드시 들어간다. C-FRIEND-1·C-ACT-1은 세 문서 공통은 아니지만 2026-10-07 회의에서 공통으로 추가했다.

| ID | 기능 | 공통 완료 기준 (관찰 가능) | 출처 (강 / 나 / 김) |
|---|---|---|---|
| C-AUTH-1 | 로그인·로그아웃 | 이메일 가입 + Google + GitHub. **같은 로그인 수단(같은 이메일 가입, 같은 소셜 계정)으로는 계정이 두 개 생기지 않는다** (수단이 다르면 별도 계정). 이메일 인증 전에는 쓰기 불가, 로그아웃 뒤 쓰기 요청은 거부된다. 로그인은 세션 쿠키(Spring Session + Redis), 가입 때 이용약관·개인정보 동의를 버전과 함께 `member_agreement`에 저장 ([07 문서](./07-auth.md) §9) | BASE-01·02 / USR-01·02 / AUTH-1 |
| C-AUTH-2 | 프로필 수정 | 닉네임·소개·프로필 이미지를 **본인만** 수정. 블로그 주소(아이디)는 가입 후 변경 불가 ([08 문서](./08-blog-address.md)). 닉네임은 2~10자 한글·영문·숫자, 대소문자 무시 중복 불가, 금칙어·예약어 불가, 바꾼 뒤 30일 변경 불가 ([09 문서](./09-nickname.md)). 소개 0~200자 글자만, 프로필 이미지 256×256(소셜 가입 시 소셜 사진 복사 가능), 하나라도 실패하면 전부 취소. 이메일 가입은 비밀번호 변경 가능 ([11 문서](./11-profile.md)) | BASE-04 / USR-04, BLG-02·03 / BLOG-2 |
| C-BLOG-1 | 개인 블로그 페이지 `/@아이디` | 그 사람의 공개·발행 글만 전체 글 목록과 같은 카드·정렬·9개·[더 보기]로 보이고, 상단에 프로필이 있다 ([10 문서](./10-post-list.md) §9) | BASE-04 / BLG-05 / BLOG-1P |
| C-POST-1 | 글 작성 | 제목·본문(Markdown 원문 저장). 본문의 스크립트는 실행되지 않는다: CommonMark+GFM 렌더링 → 직접 쓴 HTML은 글자로 → OWASP 허용 목록 정화 → CSP. 외부 링크는 새 탭 + `noopener noreferrer nofollow ugc`, 외부 이미지는 링크로 ([12 문서](./12-content-sanitize.md) §11) | BASE-07 / PST-01·04 / WRITE-1 |
| C-POST-2 | 임시저장·자동 저장 | 임시글을 다시 열어 이어 쓸 수 있다. 자동 저장은 **IndexedDB → Redis → PostgreSQL 3단계**, 수동 저장·발행은 즉시 DB 반영 ([04 문서](./04-draft-and-image.md)) | BASE-09 / PST-07 / WRITE-2 |
| C-POST-3 | 발행·수정 | 발행한 글은 누구나 읽고, 다시 발행하면 반영된다. 주소·최초 발행일·반응 수는 유지되고, 수정 중에는 독자에게 마지막 발행본이 보이며, 연달아 눌러도 한 번만 발행된다 ([05 문서](./05-publish.md) §10) | BASE-08 / PST-02 / WRITE-3 |
| C-POST-4 | 공개 범위 | `PUBLIC` / `PRIVATE` (친구 공개 `FRIENDS`는 공통 규격·선택 구현). 공개가 아닌 글은 상세 404이고 홈·블로그·태그·검색·sitemap 어디에도 나오지 않는다. 새 글은 `member.default_visibility`로 시작 ([06 문서](./06-visibility.md) §8) | BASE-12 / PST-06 / WRITE-4 |
| C-POST-5 | 글 삭제 | 삭제한 글은 즉시 모든 목록·상세에서 사라지고 **휴지통에 30일** 보관된 뒤 자동으로 완전 삭제된다. 복구하면 원래 상태·위치로 돌아온다. 빈 임시글은 바로 삭제 ([13 문서](./13-delete-withdraw.md) §5) | BASE-08 / PST-03 / MANAGE-2 |
| C-READ-1 | 전체 글 목록 (홈) | 공개·발행 글만 `first_public_at` 최신순(같으면 ID 큰 순)으로 한 줄 3개, 9개씩 카드로 보이고, [더 보기]로 이어 붙여도 중복·누락이 없다 ([10 문서](./10-post-list.md) §9) | OPEN-03 / HOM-06 / READ-1 |
| C-READ-2 | 글 상세 | 없는 글, 남의 비공개·임시 글은 **404**. | — / PST-08 / READ-2 |
| C-MANAGE-1 | 내 글 관리 | 임시·발행 글 목록, 본인 글만 보인다. | BASE-09 / `/manage/posts` / MANAGE-1 |
| C-OWN-1 | 본인 소유 권한 | 남의 글 수정·삭제 요청은 서버에서 거부되고 글은 바뀌지 않는다. 화면에서 숨기는 것만으로 막지 않는다. | 비기능-보안 / NFR-04·13 / OWN-1 |
| C-FRIEND-1 | 친구 맺기 | 친구 요청 → 상대가 수락하면 상호 친구(`friendship`, `PENDING`/`ACCEPTED`). `FRIENDS` 공개 범위와 친구 알림은 선택 기능(기본 비활성) ([06 문서](./06-visibility.md) §6) | 회의 추가 (2026-10-07) |
| C-ACT-1 | 마지막 로그인·최근 활동 표시 | 본인 계정 화면에 직전 로그인 일자·방식(로그인 때 갱신 전 `auth_identity.last_login_at` 값을 세션에 담아 표시). 친구(`ACCEPTED`)에게 최근 활동을 "오늘·어제·N일 전·1주 이상"으로 표시(`member.last_active_at`), `member.last_active_visible`을 끄면 내 것이 숨겨지고 나도 남의 것을 못 본다 | 회의 추가 (2026-10-07) |

### 2-2. Tier B — 공통 포함 권장 (세 문서 모두 있고, 2명이 최우선 순위)

강성찬·나민서는 MVP(P1·MUST)로, 김민서는 "공통 후보"로 둔 기능이다. 구현 비용은 작고 **ERD 설계 비교 포인트(다대다·자기참조·복합 키)**가 생기므로 공통 ERD에 넣는 것을 제안한다.

| ID | 기능 | 공통 완료 기준 | 출처 (강 / 나 / 김) | ERD 포인트 |
|---|---|---|---|---|
| C-TAG-1 | 태그 + 태그별 글 목록 | 대소문자·공백 정규화, 중복 태그 없음. 최대 개수는 각자 설정값 | BASE-10 / PST-10 / TAG-1 | N:M (`post_tag`) |
| C-IMG-1 | 이미지 업로드 | jpg·png·gif·webp, 10MB 이하, 저장 파일명은 서버가 생성, 확장자 위장 거부. 브라우저 압축·EXIF 제거 후 Presigned URL로 직접 업로드, 본문에는 URL만 ([04 문서](./04-draft-and-image.md)) | BASE-11 / PST-05 / IMG-1 | 저장소 추상화 |
| C-CMT-1 | 댓글 + 답글 | 회원만 작성, 본인만 수정·삭제. 답글이 있는 댓글은 "삭제된 댓글"로 남김. **공통은 1단계**, 깊이 확장은 개인 | BASE-16·17 / CMT-01~03 / CMT-1 | 자기참조 (`parent_id`) |
| C-LIKE-1 | 글 좋아요 | 1인 1글 1회, 다시 누르면 취소. 동시에 여러 번 눌러도 1건 | BASE-14 / SOC-01 / LIKE-1 | 복합 PK, 동시성 |
| C-VIEW-1 | 조회수 | 새로고침으로 부풀지 않는다 (작성자 본인 제외). **중복 판정 기준은 개인 설정값** | BASE-14 / PST-09 / P-11 | 집계 컬럼 |

### 2-3. Tier C — 공통 2차 후보 (모두 있지만 우선순위가 엇갈림)

화면·기능 구현 우선순위는 1차 공통이 끝난 뒤 다시 정한다. 테이블(팔로우·알림·신고·조회 통계)은 통합 V1(`erd/V1__common_schema.sql`)에 이미 들어 있다 (2026-10-07 회의 M1).

| 기능 | 강 | 나 | 김 | 메모 |
|---|---|---|---|---|
| 검색 (제목·본문, 공개 글만) | P1 | MUST | 2차 후보 | 셋 다 PostgreSQL. `pg_trgm` 한국어 부분 일치로 통일 가능 |
| 인앱 알림 | P1 | MUST | 2차 개인 | 셋 다 "본인 행동은 알리지 않음", "앱 안 알림만" — 사건 기반으로 설계 |
| 팔로우·구독 + 피드 | P2 | SHOULD | 2차 개인 | 대상이 "회원"(강·김) vs "블로그"(나) |
| 인기 글 / 트렌딩 | P1 | MUST | 3차 | 점수식이 다름 → 각자 |
| AI 태그 추천 | P2 | MUST(Step 6) | 3차 | 셋 다 "제안만, 실패해도 발행 성공" |
| 신고·관리자 숨김 | P2 | MUST(Step 8) | 3차 | |
| 회원 탈퇴 | P1 | COULD | 3차 | 화면·기능은 Tier C. **데이터 정책은 확정**: 30일 유예 → 익명 처리 ([13 문서](./13-delete-withdraw.md) §3) |
| 다크 모드 | P3 | MUST | 3차 | 화면 요소, ERD 무관 |

## 3. 공통 원칙

1. **공통 ERD는 바꾸지 않고, 개인 확장은 테이블·컬럼을 추가만 한다.** (김민서 §5-1 원칙 채택)
2. 개인 확장을 더해도 **공통 완료 기준은 그대로 만족**한다.
3. 권한은 두 겹: 화면에서 숨기고(나민서 2.2) + 서버(Service)에서 다시 검사한다. 남의 비공개 리소스는 403이 아니라 **404**.
4. 본문은 **Markdown 원문**을 저장하고, HTML은 서버가 렌더링 + 허용 목록 기반 sanitize 후 저장·출력한다. (에디터 종류는 자유)
5. 부가 기능(알림·AI·조회 집계)이 실패해도 글쓰기·읽기는 성공한다.
6. DB 스키마는 Flyway 마이그레이션으로만 바꾼다. 기준선은 통합 V1(`erd/V1__common_schema.sql`).
7. 수치(태그 최대 개수, 조회수 중복 기준, 페이지 크기 등)는 **설정값**으로 두어 각자 다르게 쓸 수 있게 한다.
