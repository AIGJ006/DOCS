# 닉네임 설계

> 작성일 2026-10-02 · 관련 요구사항: C-AUTH-2(프로필 수정). 연관: [07 로그인](./07-auth.md), [08 블로그 주소](./08-blog-address.md)
> 팀 결정: **2~10자, 한글·영어·숫자만(특수기호 불가), 중복 불가, 욕설·부적절한 단어 필터.**

---

## 1. 결정 사항

| # | 안건 | 결정 | 이유 |
|---|---|---|---|
| N-1 | 자음·모음만 (`ㅋㅋ`, `ㅗ`) | **불가.** 완성된 한글(`가`~`힣`)만 허용 | 욕설 표현(`ㅗ`)과 금칙어 우회(`ㅅㅂ`)에 쓰인다 |
| N-2 | 공백 | **불가** | `김 민서`처럼 보기에 비슷한 닉네임으로 사칭할 수 있다 |
| N-3 | 숫자만 (`12345`) | **불가.** 한글이나 영문이 1자 이상 있어야 한다 | 회원 번호로 오해할 수 있다 |
| N-4 | 대소문자 | **중복 판정에서는 무시**(`Kim` = `kim`), 화면에는 입력한 대로 표시 | 대소문자만 다른 닉네임으로 사칭하는 것을 막는다 |
| N-5 | 금칙어 검사 | 부분 검사 + 숫자 제거 + 숫자→영문 치환, 예외 목록. **어떤 단어인지는 알려주지 않는다** | 알려주면 필터를 피하는 방법을 가르쳐 주는 셈이다 |
| N-6 | 예약어 | **포함만 돼도 불가** (관리자·운영자·admin 등) | 운영진·서비스 사칭 방지 |
| N-7 | 변경 제한 | **바꾼 뒤 30일 동안 다시 바꿀 수 없다** | 독자의 혼란, 사칭 후 바로 바꿔 숨는 것을 막는다 |
| N-8 | 이전 닉네임 | **바로 해제** (다른 사람이 바로 쓸 수 있다) | 바꿀 수 없는 신원은 블로그 주소(`@handle`)가 맡는다. 일정 기간 묶어 두는 기능은 개인 확장 |
| N-9 | `@블로그주소` 함께 표시 | 글 상세 작성자 영역, 댓글 | 닉네임이 바뀌어도 같은 사람인지 확인할 수 있다 |
| N-10 | 소셜 이름 미리 채우기 | 허용되지 않는 문자를 지우고 10자로 잘라 채운다. 규칙에 안 맞으면 빈칸 | |
| N-11 | 탈퇴한 사람의 닉네임 | **탈퇴 유예 30일 동안은 묶어 두고, 익명 처리할 때 해제**(`nickname = null`) — [13 문서](./13-delete-withdraw.md) D-8에서 확정 | 복구 가능 기간과 맞춘다 |

## 2. 형식

| 항목 | 규칙 |
|---|---|
| 문자 | 완성된 한글 `가`~`힣`, 영문 `a-z` `A-Z`, 숫자 `0-9` |
| 길이 | **2~10자** (글자 수 기준: 한글 1자 = 1, 영문 1자 = 1) |
| 필수 | 한글 또는 영문 1자 이상 |
| 불가 | 자음·모음만, 공백, 특수문자, 이모지 |

```
^[가-힣a-zA-Z0-9]{2,10}$   그리고   [가-힣a-zA-Z] 를 1자 이상 포함
```

**입력값 정리 (검사 전에 항상):**
1. 앞뒤 공백 제거
2. **유니코드 정규화(NFC).** macOS에서 복사한 한글은 자음·모음이 분리된 형태(NFD)일 수 있어서, 정규화하지 않으면 정상 닉네임 `김민서`가 형식 오류가 된다. 정규화한 값을 저장한다.

## 3. 검사 순서와 오류 코드

```
입력 → ① 정리(공백 제거, NFC) → ② 형식 → ③ 글자 포함 → ④ 예약어 → ⑤ 금칙어 → ⑥ 중복
```

| 단계 | 실패 코드 | 화면 문구 |
|---|---|---|
| ② 형식 | `NICKNAME_INVALID_FORMAT` | "한글·영문·숫자로 2~10자까지 쓸 수 있어요 (공백·특수문자 불가)" |
| ③ 글자 포함 | `NICKNAME_LETTER_REQUIRED` | "한글이나 영문을 1자 이상 넣어 주세요" |
| ④ 예약어 | `NICKNAME_RESERVED` | "사용할 수 없는 닉네임이에요" |
| ⑤ 금칙어 | `NICKNAME_BANNED_WORD` | "사용할 수 없는 단어가 들어 있어요" (어떤 단어인지 알려주지 않음) |
| ⑥ 중복 | `NICKNAME_DUPLICATE` | "이미 사용 중인 닉네임이에요" |

모든 검사는 **`NicknamePolicy` 한곳**에서 한다. 가입(이메일·소셜)과 프로필 수정이 같은 정책을 쓴다. 화면 검사는 안내용이고, 서버가 가입·수정 요청을 받을 때 다시 검사한다.

## 4. 금칙어 필터

### 4-1. 목록

| 항목 | 규칙 |
|---|---|
| 출처 | 공개된 한국어·영어 비속어 목록을 가져와 **팀이 검토한 뒤** 사용. 비하·성적 표현 포함 |
| 변형 표기 | 목록에 흔한 변형 표기도 넣는다 (예: `fack`, `씨발`·`시발`). 숫자→영문 치환은 `sh1t` → `shit` 같은 경우만 잡고, `f4ck`(→ `fack`)은 변형 표기가 목록에 있어야 잡힌다 |
| 예외 목록 | 금칙어가 들어 있지만 정상인 단어 (예: `시발점`, `시발역`) |
| 관리 위치 | 설정 파일 `banned-words.txt`, `banned-words-exceptions.txt`. 운영자 화면이 생기면 DB로 옮긴다 (Tier C) |

### 4-2. 검사 방법

입력을 소문자로 바꾼 뒤 아래 **변형 4가지 중 하나라도** 금칙어를 포함하면 거부한다. 각 변형에서 예외 단어는 먼저 지운다.

| 변형 | 예 | 잡는 우회 |
|---|---|---|
| 그대로 | `씨발놈` | — |
| 숫자 제거 | `시1발왕` → `시발왕`, `병1신` → `병신` | 숫자 끼워 넣기 |
| 숫자 → 영문 (0→o, 1→i, 3→e, 4→a, 5→s, 7→t) | `sh1t` → `shit` | 숫자로 글자 바꾸기 |
| 1 → l | 숫자 `1`을 영문 `l` 자리에 쓴 경우 | `1`과 `l` 혼용 |

- 공백·특수문자 우회(`시 발`, `시.발`)와 자음·모음 우회(`ㅅㅂ`)는 §2 형식 규칙에서 이미 막힌다.
- **같은 필터를 블로그 주소에도 적용한다** ([08 §4-2](./08-blog-address.md)).
- 댓글·글 본문 필터는 공통 범위 밖이다 (Tier C 신고와 함께 검토).

## 5. 예약어

아래 단어를 **포함만 해도** 쓸 수 없다. 대소문자를 무시하고, 금칙어와 같은 변형 4가지로 검사한다.

```
관리자 운영자 운영진 운영팀 고객센터 공식 매니저 스태프
admin administrator official staff manager system root
(서비스 이름이 확정되면 추가)
```

`관리자김`, `admin123`, `Official`, `운영팀장` 모두 거부된다. 예약어는 운영자 계정에만 허용한다 (Tier C).

## 6. 중복

| 항목 | 규칙 |
|---|---|
| 기준 | 대소문자를 무시한다. `Kim`이 있으면 `kim`, `KIM`은 쓸 수 없다. `KIM2`는 다른 닉네임 |
| DB 보장 | `CREATE UNIQUE INDEX uq_member_nickname ON member (lower(nickname))` — 동시에 같은 닉네임으로 가입·변경해도 한 명만 성공 |
| 중복 확인 API | `GET /api/nicknames/availability?nickname=…` → `{ available, code }`. 입력이 0.5초 멈추면 호출, 같은 IP 1분에 30번 |
| 동시 요청에서 진 쪽 | "방금 다른 분이 이 닉네임을 사용했어요" |

## 7. 가입할 때

| 경우 | 처리 |
|---|---|
| 이메일 가입 | 직접 입력 (미리 채우지 않음) |
| 소셜 가입 (가입 마무리 화면) | 소셜 이름에서 허용되지 않는 문자를 지우고 10자로 잘라 미리 채운다. 결과가 §3 검사를 통과하지 못하면 빈칸으로 두고 "닉네임을 입력해 주세요" |

| 소셜 이름 | 미리 채워지는 값 |
|---|---|
| `Kim Min-seo` | `KimMinseo` |
| `김민서 (Minseo)` | `김민서Minseo` |
| `Christopher Columbus` | `Christophe` (10자로 자름) |
| `A` | (빈칸: 2자 미만) |
| `Kim` (이미 사용 중) | (빈칸: 중복) |

## 8. 변경

| 항목 | 규칙 |
|---|---|
| 누가 | 본인만 (C-AUTH-2) |
| 제한 | 바꾼 뒤 **30일** 동안 다시 바꿀 수 없다. `member.nickname_changed_at` 기준. 프로필 화면에 "다음 변경 가능일: 11월 1일" 표시, 그 전에는 입력칸 비활성화 + 서버에서 `409 NICKNAME_CHANGE_TOO_SOON` |
| 가입 직후 | 가입할 때 정한 닉네임은 변경으로 세지 않는다 (`nickname_changed_at = null`) — 가입 후 바로 한 번은 바꿀 수 있다 |
| 이전 닉네임 | 바로 해제된다 (N-8) |
| 같은 닉네임으로 다시 저장 | 아무것도 바뀌지 않고, 30일 제한도 시작되지 않는다 |
| 대소문자만 바꾸기 (`kim` → `Kim`) | 변경으로 본다 (30일 제한 시작). 중복 검사에서 자기 자신은 제외 |

## 10. 스키마

[03-erd.md](./03-erd.md)에 반영했다.

```sql
nickname            varchar(10),          -- 익명 처리된 탈퇴 회원만 null (13 문서)
nickname_changed_at timestamptz,
CONSTRAINT ck_member_nickname CHECK (nickname ~ '^[가-힣a-zA-Z0-9]{2,10}$' AND nickname ~ '[가-힣a-zA-Z]'),
...
CREATE UNIQUE INDEX uq_member_nickname ON member (lower(nickname));
```

금칙어·예약어는 DB 제약조건으로 표현하기 어려워 `NicknamePolicy`에서 검사한다.

## 11. 공통 완료 기준

| # | 기준 |
|---|---|
| 1 | 2~10자의 한글·영문·숫자만 쓸 수 있고, 자음·모음만, 공백, 특수문자, 이모지, 숫자만으로 된 닉네임은 거부된다 |
| 2 | 자음·모음이 분리된(NFD) 한글을 붙여넣어도 정상 닉네임으로 저장된다 |
| 3 | 대소문자만 다른 닉네임은 중복으로 거부되고, 동시에 같은 닉네임을 요청해도 한 명만 성공한다 |
| 4 | 금칙어는 숫자를 끼워 넣거나(`시1발`) 숫자로 글자를 바꿔도(`sh1t`) 거부되고, 예외 단어(`시발점`)는 허용된다 |
| 5 | 예약어가 포함된 닉네임(`관리자김`, `admin123`)은 거부된다 |
| 6 | 닉네임을 바꾸면 30일 동안 다시 바꿀 수 없다 |
| 7 | 거부 메시지는 어떤 금칙어에 걸렸는지 알려주지 않는다 |

§2~§8의 예시는 이 규칙을 코드로 구현해 실행한 결과다 (2026-10-02, 금칙어는 테스트용 일부 목록).
