# 블로그 주소(아이디) 설계

> 작성일 2026-10-02 · 관련 요구사항: C-BLOG-1(개인 블로그 `/@아이디`), C-AUTH-2(주소 변경 불가). 연관: [07 로그인](./07-auth.md)
> 팀 결정: 블로그 주소는 **이메일 `@` 앞부분으로 만든다.** 소셜 가입은 **두 글자 접두어 + `-`**를 붙이고, 전부 **소문자**로 관리한다. 가입할 때 **한 번만 직접 고칠 수 있고**, 가입 후에는 바꿀 수 없다.

---

## 1. 결정 사항

| # | 안건 | 결정 | 이유 |
|---|---|---|---|
| H-1 | 소셜 가입 구분 | **두 글자 접두어 + `-`**: Google `go-`, GitHub `gi-` | Google과 GitHub이 둘 다 `g`로 시작해서 한 글자로는 구분이 안 된다 |
| H-2 | 대소문자 | **전부 소문자** | 대문자로 구분하면 눈으로 거의 같은 주소(`GOkim` / `gokim`)로 사칭할 수 있고, `I`(대문자 i)와 `l`(소문자 L)이 구별되지 않으며, 사람들은 주소를 소문자로 입력한다 |
| H-3 | 이메일과 소셜 주소가 겹치지 않게 | 이메일에서 만든 주소에는 **`-`가 절대 들어가지 않는다** (`.`·`-`는 `_`로 바꿈). `-`는 소셜 접두어에만 쓴다 | `gokim@…`(이메일 가입) → `gokim`, Google의 `kim@…` → `go-kim`. 대문자 없이도 구분된다 |
| H-4 | 이메일 노출 | 이메일로 **미리 채워 주고, 가입할 때 한 번만 직접 고칠 수 있다.** 가입 후에는 변경 불가 | 블로그 주소로 이메일 주소를 짐작해 스팸·피싱에 쓸 수 있다. 원하지 않는 사람에게 선택지를 준다 |
| H-5 | 이미 있는 주소 | 뒤에 `_2`, `_3`…을 붙인다 | 같은 수단 안에서도 이메일 앞부분이 같을 수 있다 (`kim755030@naver.com` / `kim755030@daum.net`) |

## 2. 주소 형식

```
[접두어-]본문
  접두어: 없음(이메일 가입) | go-(Google) | gi-(GitHub)        ← 나중에 na-(네이버), ka-(카카오)
  본문:   영문 소문자·숫자·밑줄(_), 3~36자, 처음과 끝은 영문 소문자나 숫자
```

정규식 (DB CHECK와 애플리케이션 검증이 같은 규칙):

```
^((go|gi)-)?[a-z0-9][a-z0-9_]{1,34}[a-z0-9]$
```

| 예 | 결과 | 이유 |
|---|---|---|
| `kim755030`, `go-kim755030`, `gi-kim_min` | ✅ | |
| `GOkim`, `Kim755030` | ❌ | 대문자 |
| `kim-min` | ❌ | 접두어가 아닌 `-` |
| `xx-kim` | ❌ | 정해지지 않은 접두어 |
| `go-ki`, `ab` | ❌ | 본문 3자 미만 |
| `_kim`, `kim_`, `go-_kim` | ❌ | 본문의 처음·끝이 `_` |
| `gi-` + 37자 | ❌ | 본문 36자 초과 (전체 최대 39자) |

**접두어와 가입 수단의 일치**(이메일 가입은 접두어 없음, Google은 `go-`, GitHub은 `gi-`)는 가입 Service에서 검사한다. 로그인 수단은 `auth_identity`에 있어서 `member`의 CHECK로는 확인할 수 없기 때문이다.

## 3. 이메일로 주소 만들기 (미리 채우는 값)

```
1. 이메일의 @ 앞부분을 가져온다
2. + 뒤는 버린다                          kim+blog       → kim
3. 소문자로 바꾼다                        Kim.Min-Seo    → kim.min-seo
4. . 과 - 는 _ 로 바꾼다                  kim.min-seo    → kim_min_seo     ← 이메일 주소에는 - 가 생기지 않음
5. 영문 소문자·숫자·_ 외의 문자는 지운다    김민서         → (빈 값)
6. _ 가 연달아 나오면 하나로, 처음·끝의 _ 는 지운다    _kim__min_ → kim_min
7. 30자로 자른다 (끝이 _ 가 되면 그것도 지운다)
8. 3자 미만이 되면 → user_ + 숫자 6자리(난수)       ab@…, 김민서@… → user_483920
9. 가입 수단의 접두어를 붙인다              Google → go-kim_min_seo
10. 예약어이거나 이미 있는 주소면 _2, _3 … 중 비어 있는 첫 번호를 붙인다
```

### 예시 (위에서부터 차례로 가입했다고 가정)

| 가입 수단 | 이메일 | 미리 채워지는 주소 |
|---|---|---|
| 이메일 | kim755030@naver.com | `kim755030` |
| 이메일 | kim755030@daum.net | `kim755030_2` (이미 있음) |
| Google | kim755030@gmail.com | `go-kim755030` |
| GitHub | kim755030@naver.com | `gi-kim755030` |
| 이메일 | kim755030@gmail.com | `kim755030_3` |
| 이메일 | gokim@naver.com | `gokim` (`go-kim`과 다름) |
| 이메일 | Kim.Min-Seo+blog@naver.com | `kim_min_seo` |
| 이메일 | _kim__min_@x.com | `kim_min` |
| 이메일 | admin@x.com | `admin_2` (예약어) |
| 이메일 | ab@x.com | `user_483920` (3자 미만) |
| Google | 김민서@한국.kr | `go-user_483920` (영문이 없음) |
| GitHub | 12345678+octocat@users.noreply.github.com | `gi-12345678` |

위 예시는 이 규칙을 코드로 구현해 실행한 결과다 (2026-10-02).

## 4. 가입할 때 한 번 고치기 (H-4)

### 4-1. 화면

**이메일 가입 화면**
```
이메일        [ kim755030@naver.com        ]
블로그 주소   devlog.com/@[ kim755030      ]   ✓ 사용할 수 있어요
              이메일 앞부분으로 미리 채웠어요. 이메일을 드러내고 싶지 않으면 바꿔 주세요.
              ⚠ 블로그 주소는 가입 후 바꿀 수 없어요.
```
- 이메일을 입력하는 동안 주소 칸이 자동으로 채워진다. **사용자가 주소 칸을 직접 고치면 그 뒤로는 자동으로 바꾸지 않는다.**

**소셜 가입 마무리 화면** ([07 §5](./07-auth.md))
```
블로그 주소   devlog.com/@go-[ kim755030   ]   ✓ 사용할 수 있어요
```
- 접두어 `go-`·`gi-`는 **고정 글자로 보여주고 고칠 수 없다.** 사용자는 본문만 고친다.

### 4-2. 입력 규칙

| 항목 | 규칙 |
|---|---|
| 입력 | 대문자로 입력해도 소문자로 바꿔서 보여준다. 한글 자판 상태여도 영문으로 입력되게 한다 (나민서 v0.23) |
| 문자 | 영문 소문자·숫자·`_`만. `-`는 입력할 수 없다 (접두어 전용) |
| 길이 | 본문 3~36자 |
| 예약어 | §5 목록은 사용할 수 없다 |
| 금칙어 | 닉네임과 같은 금칙어 필터를 적용한다 ([09 문서 §4](./09-nickname.md)) |
| 중복 확인 | 입력이 0.5초 멈추면 `GET /api/handles/availability?handle=…` → `{ available, reason, suggestion }`. 같은 IP 1분에 30번 |
| 최종 확인 | 가입 버튼을 누를 때 서버가 다시 검사한다 (화면 확인은 참고용) |
| 동시에 같은 주소로 가입 | DB `UNIQUE`가 막는다. 늦은 쪽에는 "방금 다른 분이 이 주소를 사용했어요. `kim755030_2`는 어떠세요?" |

중복 확인 API는 "이 주소가 사용 중인지"만 알려준다. 블로그 주소는 어차피 공개 정보라서 가입 여부를 따로 드러내지 않는다.

## 5. 예약어

블로그 주소는 `/@` 뒤에 오므로 `/login` 같은 시스템 경로와 겹치지는 않는다. 예약어는 **운영자·서비스로 오해받을 수 있는 주소**를 막기 위한 것이다.

```
admin administrator root system official support help about terms privacy
api login logout signup settings me write search tag tags notifications manage
static assets images mail www blog user users null undefined devlog teamblog
```

- 목록은 설정 파일로 관리하고, 비교할 때는 **본문**(접두어를 뺀 부분)을 기준으로 한다. 그래서 `go-admin`도 막힌다.
- 서비스 이름이 확정되면 그 이름도 추가한다.

## 6. 가입 후

| 항목 | 규칙 |
|---|---|
| 변경 | 불가 (C-AUTH-2). 프로필 수정 화면에서도 읽기 전용으로 보여준다 |
| 대문자로 접속 | `/@Kim755030` → `/@kim755030`으로 **301 리다이렉트** |
| 없는 주소 | 404 |
| 탈퇴한 계정의 주소 | **다시 쓸 수 없다.** 옛 링크로 다른 사람의 블로그가 열리는 사칭을 막기 위해서다. 탈퇴 30일 뒤 회원 행을 익명 껍데기로 남기고 `handle`만 보존한다 ([13 문서](./13-delete-withdraw.md) D-9·D-10) |
| 화면 표시 | `@kim755030`, `@go-kim755030` |

## 7. 스키마

[03-erd.md](./03-erd.md)의 `member.handle` 제약조건을 이 규칙으로 바꿨다.

```sql
CONSTRAINT ck_member_handle CHECK (handle ~ '^((go|gi)-)?[a-z0-9][a-z0-9_]{1,34}[a-z0-9]$')
```

- 이전 규칙(`^[a-z0-9][a-z0-9_-]{1,38}$`)은 GitHub 아이디를 그대로 쓰던 때의 것이다. 이제 주소를 이메일로 만들므로 더 엄격한 규칙으로 바꿨다.
- 새 소셜 로그인을 추가하면 CHECK의 `(go|gi)`에 접두어를 추가한다 (예: `(go|gi|na)`, E-10과 같은 방식).

## 8. 공통 완료 기준

| # | 기준 |
|---|---|
| 1 | 이메일 가입·Google·GitHub이 같은 이메일 앞부분을 써도 주소가 겹치지 않는다 (`kim755030` / `go-kim755030` / `gi-kim755030`) |
| 2 | 이메일에서 만든 주소에는 대문자와 `-`가 없다 |
| 3 | 같은 주소로 동시에 가입해도 한 명만 그 주소를 가진다 |
| 4 | 가입할 때 주소를 한 번 고칠 수 있고, 가입 후에는 어떤 경로로도 바꿀 수 없다 |
| 5 | 예약어(접두어를 뺀 본문 기준)와 형식에 맞지 않는 주소로는 가입할 수 없다 |
| 6 | 대문자로 입력한 주소는 소문자 주소로 리다이렉트된다 |
