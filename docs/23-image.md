# 이미지 업로드: 남은 결정

> 작성일 2026-10-04 · 수정 2026-10-06 (저장소 MinIO 반영, 이미지 주소 P4, 검증 L13·L24·M12) · 작성 강성찬 · 관련 요구사항: C-IMG-1(이미지 업로드). 연관: [04 임시저장·사진](./04-draft-and-image.md) §4·§6, [10 목록](./10-post-list.md) §6, [11 프로필](./11-profile.md) §4, [12 본문 정화](./12-content-sanitize.md) §4·§6
> **이미 정해진 것은 다시 적지 않는다**: 업로드 흐름(브라우저 압축·EXIF 제거·640px 썸네일 → presign → 직접 업로드 → complete 서버 재검사), 저장 키 `images/{yyyy}/{MM}/{uuid}.{ext}`, 캐시 1년, 1분 20장, 오프라인 대기열(`local:`), 정리 배치(TEMP 24시간·연결 끊긴 지 7일), 비공개 글 사진은 주소를 알면 보임, 프로필 256×256.
> 이 문서는 남은 것만 정한다: **저장소 운영 규칙·검증, 이미지 주소, 사용자별 용량 한도, 대체글, GIF.** 저장소 제품은 팀이 **MinIO**로 정했다(2026-10-06, [04 §6-1](./04-draft-and-image.md)).

## 2. 저장소: MinIO (I-1)

### 2-1. 구성과 위험 관리

| 항목 | 내용 |
|---|---|
| 제품 | **MinIO** (S3 API, Presigned PUT은 SigV4). 팀 결정 2026-10-06 — [01 결정 기록](./01-common-requirements.md), [04 §6-1](./04-draft-and-image.md) |

### 2-2. 설정

로컬 `compose.yaml` 예시는 [04 §6-1](./04-draft-and-image.md)에 있다 (여기에 다시 적지 않는다). 버킷·익명 읽기 정책·앱 전용 키는 `scripts/check-storage.sh`의 `mc` 명령을 그대로 쓴다.

| 항목 | 규칙 | 이유 |
|---|---|---|
| 버킷 | 하나 (`blog`). 사진은 `images/…` 아래에만 둔다 (04 §4-2 저장 키) | 익명 읽기 범위를 경로 하나로 묶는다 |
| 키 | 기본(root) 계정을 앱에서 쓰지 않는다. **앱 전용 키**는 `s3:PutObject`·`GetObject`·`DeleteObject`만, 환경 변수로만 (02 §5 비밀값) | 키가 새어도 버킷 정책·목록·다른 버킷은 건드리지 못한다 |
| 버킷 읽기 | **파일 하나 읽기(`GetObject`)만 익명 허용**, `images/*` 경로만 | 04 결정 2(주소를 알면 볼 수 있음) |
| 버킷 목록 | **익명 목록 조회(`ListBucket`) 금지** | 목록이 열리면 비공개 글의 사진 주소까지 모두 드러난다. "주소는 UUID라 추측할 수 없다"(04 결정 2)는 목록이 닫혀 있어야 성립한다 |
| 업로드 | Presigned PUT만 (SigV4, path-style). 익명 쓰기 금지 | |
| CORS | 우리 사이트 출처(origin)에서 `PUT`만, 헤더는 `Content-Type`. 로컬은 `MINIO_API_CORS_ALLOW_ORIGIN` | 브라우저 직접 업로드. **운영에서 CORS를 설정할 수 없으면** 앱 서버 경유 업로드(04 §4-1 `LocalImageStorage`의 `PUT /api/images/{id}/content`)로 바꾼다 — 서버 부하는 늘지만 규칙은 같다 |
| 관리 콘솔 | 외부에 열지 않는다. 로컬도 S3 포트(9000)만 연다 | |
| 백업 | 운영은 NHN 저장소의 백업 정책을 배포 담당이 확인해 적는다. 로컬은 백업하지 않는다 | |

### 2-4. 이미지 주소 (I-5, 검증 P4·L33)

**문제.** 본문 Markdown과 복사 컬럼(`post.thumbnail_url`, `member.profile_image_url`)은 사진을 **절대 주소**로 담는다. 12 §4·§6은 "CDN 주소로 시작하는 `src`"만 우리 사진으로 보므로, 공개 주소를 바꾸면 옛 글의 사진이 **외부 이미지 링크**로 바뀐다. 공개 주소는 이미 하나가 아니다: 로컬 `http://localhost:9000/blog`, 운영 NHN MinIO 주소, (개인 확장) CloudFront 주소.

**결정.** 절대 주소는 그대로 쓴다. 대신 "우리 사진" 판별과 출력 주소를 설정값으로 분리한다.

| 항목 | 규칙 |
|---|---|
| 공개 주소 | `blog.image.public-base-url` (지금 쓰는 주소 하나). 사진 주소 = 공개 주소 + `/` + 저장 키. 04 §4-1 `ImageStorage.publicUrl(key)`가 이 값으로 만든다 |
| 옛 주소 목록 | `blog.image.legacy-base-urls` (예전에 쓴 공개 주소들). 본문에 남아 있으므로 **지우지 않는다** |
| 우리 사진 판별 | 주소가 공개 주소 또는 옛 주소 중 하나로 시작하고, **나머지가 저장 키 모양**(`images/{yyyy}/{MM}/{uuid}(_thumb)?.{ext}`)일 때만. 판별·키 추출은 `ImageUrls.keyOf(url)` 한 곳에서 한다. 업로더 확인 제안(§6-1)을 받아들이면 "글 작성자가 올린 사진" 조건이 더해진다 |
| 렌더링 (12 §2 ② AST 변환) | 우리 사진이면 `src`를 **공개 주소 + 키**로 바꿔 쓴다. 그래서 정화 허용 목록(12 §4 `startsWith(CDN)`)과 CSP `img-src`는 공개 주소 하나만 알면 된다 |
| 사진 연결 (04 §4-4) | 본문에서 주소를 뽑을 때 `keyOf`로 **키를 비교**한다 (주소 문자열 비교 금지). GIF 판별(§5-2)도 같은 함수 |
| 원문 (`content_md`) | 바꾸지 않는다. 사용자가 쓴 글을 서버가 몰래 고치지 않는다 |
| 다른 환경 주소 | 로컬 주소가 운영 글에 붙여 넣어지면 운영 목록에 없으므로 외부 이미지 링크가 된다 (의도한 동작) |

**공개 주소를 바꾸는 순서** (예: NHN 주소 → CloudFront):

1. 새 주소가 같은 파일을 내주는지 확인한다 (옛 주소도 계속 열려 있어야 한다).
2. 설정: `public-base-url` = 새 주소, `legacy-base-urls`에 옛 주소 추가. CSP `img-src`에 새 주소 추가 (옛 주소는 4까지 함께 둔다).
3. `RENDER_VERSION`을 올려 발행 글을 다시 렌더링한다 (12 §7-7). `content_html`의 사진 주소가 새 주소로 바뀐다.
4. 복사 컬럼을 한 번 갱신한다: `UPDATE post SET thumbnail_url = :new || substr(thumbnail_url, length(:old) + 1) WHERE thumbnail_url LIKE :old || '/%'` (`member.profile_image_url`도 같은 식).
5. 다시 렌더링이 끝나면 CSP에서 옛 주소를 뺀다.

**검토한 다른 방법.** (B) 본문에 키만 적기(`![](img:…)`) — 에디터 미리보기·복사·내보내기가 깨진다. (C) 상대 경로 `/images/…`를 앱이 저장소로 넘기기 — 모든 사진 요청이 앱을 거쳐 캐시·CDN 효율이 떨어진다. 둘 다 기각.

**CloudFront(강성찬 개인 확장, 02 §2).** 공통 기간에는 쓰지 않고 NHN MinIO 공개 주소를 그대로 쓴다. 도입하면 위 순서대로 바꾼다. 사진 주소가 바뀌지 않으므로(UUID) `immutable` 캐시(04 §4-2)는 그대로 둔다.

## 3. 사용자별 용량 (I-2)

| 항목 | 규칙 |
|---|---|
| 한도 | **1GB** (`blog.image.quota-bytes`), **하루 200장** (`blog.image.daily-limit`, 한국 시간 0시 기준) |
| 세는 것 | 그 사람이 올린 **모든 이미지 행**의 원본 + 썸네일 크기 (`TEMP`, 연결됨, 연결이 끊겨 정리를 기다리는 것 모두). 프로필 이미지 포함 |
| 돌아오는 시점 | 정리 배치가 파일을 **실제로 지울 때** (TEMP 24시간, 연결 끊긴 지 7일, 04 §4-4). 글을 지워도 바로 돌아오지 않는다 |
| 검사 시점 | `POST /api/images/presign`에서 "지금 사용량 + 이번에 올릴 크기(원본 + 썸네일)" |
| 넘으면 | `409 STORAGE_QUOTA_EXCEEDED` / 하루 200장을 넘으면 `429 DAILY_UPLOAD_LIMIT` |
| 동시 요청 | presign 트랜잭션에서 **회원 행을 잠그고**(`SELECT … FROM member WHERE id = :me FOR UPDATE`) 합계를 구한 뒤 TEMP 행을 신고한 크기로 넣는다. 그래서 여러 장을 동시에 요청해도 한도를 넘지 않는다 |
| 실제 크기 | complete에서 실제 크기를 기록한다. 신고한 크기보다 크면 04 §4-1 ⑤ 규칙대로 거부·삭제 |
| 하루 장수 | Redis `img:daily:{memberId}:{yyyyMMdd}` `INCR`, TTL 2일. presign에서 센다 (실패한 업로드도 1장으로 센다 — 반복 요청 방지) |

```sql
-- presign: 지금 사용량 (ix_image_uploader 사용)
SELECT coalesce(sum(size_bytes + coalesce(thumb_size_bytes, 0)), 0)
FROM image WHERE uploader_id = :me;
```

## 4. 대체글 (I-3)

| 항목 | 규칙 |
|---|---|
| 넣을 때 | 에디터가 `![](주소)`로 넣는다. **대체글 자리를 비워 둔다.** 원래 파일 이름을 넣지 않는다 |
| 발행 설정 창 | 대체글이 빈 사진이 있으면 안내: "대체글이 없는 사진이 2장 있어요 [대체글 넣기]" → 사진마다 작은 미리보기 + 입력칸. 입력하면 본문 Markdown의 `![…]`에 반영 |
| 강제 여부 | **발행을 막지 않는다** |
| 빈 대체글 | `alt=""`로 그린다 → 화면 낭독기가 꾸밈 이미지로 보고 건너뛴다 (`alt` 속성을 아예 빼면 낭독기가 파일 주소를 읽는다) |
| 길이 | 권장 125자 이내 (넘어도 거부하지 않음, 안내만) |
| 글 카드 썸네일 | `alt` = 글 제목 (10 §2 그대로) |
| 프로필 이미지 | 바로 옆에 닉네임이 있으므로 `alt=""` |
| 안내 문구 | 입력칸 아래 "사진을 볼 수 없는 분께 읽어 줄 설명이에요. 예: 'fetch join 전후 쿼리 수 비교 그래프'" |

`original_name`은 저장 키에 쓰지 않는 것(04 §4-2)에 더해 **화면 어디에도 보여주지 않는다.**

## 5. GIF (I-4)

### 5-1. 업로드

| 항목 | 규칙 |
|---|---|
| 변환 | 원본은 **압축·크기 조정·변환 없이 그대로** (04 ② 그대로). 썸네일은 첫 장면 640px WebP (10 §6 그대로) |
| 크기 | 10MB 이하 (공통) |
| 해상도 | **가로·세로 각 1920px 이하.** 브라우저에서 움직이는 GIF를 줄일 수 없으므로, 넘으면 고르는 순간 "GIF는 가로·세로 1920px까지 올릴 수 있어요" |
| 프레임 수 | **300장 이하** |
| 서버 검사 (complete) | 위 해상도·프레임 수를 다시 확인한다. 파일 전체를 디코딩하지 않고 머리말과 프레임 구분만 읽는다(`ImageReader.getNumImages`). 넘으면 거부·삭제 |
| 움직이는 다른 형식 | 움직이는 WebP·PNG(APNG)는 브라우저 압축 과정(캔버스)에서 **첫 장면만 남는다.** 움직임을 살리는 형식은 GIF뿐이다 (업로드 화면에 안내) |
| 메타데이터 | GIF에는 사진의 촬영 위치(EXIF)가 들어가지 않는다. 그 밖의 메타데이터(XMP)는 서버가 파일을 고치지 않으므로 남을 수 있다 (알려진 한계) |

### 5-2. 본문에서 보여주기

```
처음:  [첫 장면 정지 이미지]  ▶ GIF          ← 썸네일(640px)을 원래 크기로 표시
누름:  [원본 GIF가 움직임]
JS 없음: 정지 이미지를 누르면 원본 GIF가 새 탭에서 열림
```

12 §2 ② AST 변환에 **GIF 규칙 하나를 추가**한다 (12 §4 허용 목록은 바꾸지 않음).

```html
<!-- 입력: ![로딩 화면](https://cdn…/images/2026/10/7f3e….gif) -->
<a href="https://cdn…/images/2026/10/7f3e….gif" title="움직이는 이미지 재생"
   target="_blank" rel="noopener noreferrer nofollow ugc">
  <img src="https://cdn…/images/2026/10/7f3e…_thumb.webp" alt="로딩 화면" loading="lazy" decoding="async">
</a>
```

| 항목 | 규칙 |
|---|---|
| 판별 | 우리 저장소 주소(§2-4 `keyOf`)이고 `.gif`로 끝나는 이미지. 썸네일 주소는 저장 키 규칙(`{uuid}_thumb.webp`, 10 §6)으로 만든다 |
| 재생 | 우리 서버의 `/js/gif-play.js` (CSP `script-src 'self'`를 지킴): `a[href$=".gif"] > img`를 찾아 ▶ 표시를 붙이고, 누르면 기본 동작(새 탭)을 막고 `img.src`를 원본 GIF로 바꾼다. 다시 누르면 정지 장면으로 |
| ▶ 표시 | CSS `a[href$=".gif"]::after` (class를 쓰지 않음 → 정화 허용 목록을 바꿀 필요가 없다) |
| 접근성 | 링크 이름은 대체글, 대체글이 비었으면 `title`("움직이는 이미지 재생"). 키보드 Enter로 재생 |
| 글 카드 썸네일 | 첫 장면 (10 §6 그대로) |
| 링크 미리보기(OG) | 원본 GIF (10 §6 "OG는 원본" 그대로) |

## 6. 업로더 확인·탈퇴 정리·캐시

### 6-1. 업로더 확인 (검증 M12)

사진은 올린 사람의 것이다. 남이 올린 사진 주소를 내 글에 붙여 넣어 그 사진을 지우게 하거나(정리 배치), 용량을 떠넘기거나, 남의 비공개 글 사진을 다시 공개하는 일을 막는다.

**기존 결정 변경 제안**이다 (04 §4-1 ⑤·05 §7 ⑥·12 S-6). 지금 05 ⑥은 본문의 사진을 모두 연결하고, 12 S-6은 우리 저장소 사진을 모두 `<img>`로 그린다. 받아들이면 아래 표의 문서에 반영을 요청한다.

| 단계 | 규칙 | 반영 요청 |
|---|---|---|
| `complete`·`content` | `uploader_id ≠ 나`면 404 | 04 §4-1 ⑤ |
| 발행 사진 연결 | 본문의 우리 사진(§2-4 `keyOf`) 중 **`uploader_id = 글 작성자`인 것만** `post_image`로 연결하고 `ATTACHED`. 남이 올린 사진 주소는 외부 이미지처럼 링크로 그린다 (12 S-6) | 05 §7 ⑥ |
| 렌더링 | §2-4의 "우리 사진" = 주소 판별 + **글 작성자가 올린 사진**. 렌더링(05 ②, 미리보기 12 §7-6, 다시 렌더링 12 §7-7) 때 본문의 키를 모아 `SELECT storage_key FROM image WHERE storage_key = ANY(:keys) AND uploader_id = :author` 한 번으로 확인한다 (`uq_image_storage_key`) | 12 §2 ② |
| 용량 (§3) | 내가 올린 것만 내 용량에 센다 | 이 문서 |

### 6-2. 탈퇴 30일 뒤 (`ImageWithdrawalPurgeStep`, order 40, 검증 L13)

13 §3-3 4번, [44 §4](./44-withdraw.md) order 40. order 10(내 글 완전 삭제)이 먼저 실행되어 내 글의 `post_image` 행은 이미 CASCADE로 지워져 있다.

```sql
-- 프로필 사진 연결 해제 (profile_image_url 비우기는 order 90 익명화)
UPDATE member SET profile_image_id = NULL WHERE id = :me;
-- 내가 올린 사진 전부 정리 대상으로. TEMP는 detached_at과 무관하게 원래 규칙(24시간)으로 지워진다
UPDATE image SET detached_at = now() WHERE uploader_id = :me AND detached_at IS NULL;
```

| 항목 | 규칙 |
|---|---|
| 파일 삭제 | 이 단계에서 하지 않는다. 외부 호출이라 트랜잭션 밖에서 정리 배치(04 §4-4)가 지운다 |
| 남의 글에 쓰인 내 사진 | §6-1 때문에 생기지 않는다 (남이 올린 사진은 연결되지 않음) |
| `image` 행 | 정리 배치가 파일을 지운 뒤 행도 지운다. 그 전까지 `uploader_id`는 익명 처리된 회원 행을 가리킨다 (FK RESTRICT, 회원 행은 지우지 않으므로 문제없음) |
| 남는 기간 | 13 §3-3 4번대로 연결이 끊긴 지 7일 → **탈퇴 신청 뒤 최대 약 38일**. 13 §5 회원 탈퇴 3번 "30일 뒤 … 사진이 남지 않는다"와 어긋난다 → §10 제안 |

### 6-3. 지운 사진의 캐시 (검증 L24)

| 어디 | 남는 기간 | 처리 |
|---|---|---|
| 저장소 (MinIO) | 정리 배치가 지우면 바로 404 | — |
| 독자 브라우저 | 최대 1년 (`immutable`, 04 §4-2) | 지울 방법이 없다. **허용 한계로 둔다**: 그 사진을 이미 본 브라우저에만 남고, 주소는 UUID라 추측할 수 없으며, 목록 조회도 막혀 있다(§2-2) |
| CDN (CloudFront, 강성찬 개인 확장) | 최대 1년 | 정리 배치가 저장소 파일을 지운 뒤 **같은 배치에서 무효화 요청**(원본·썸네일 경로를 묶어서). 실패하면 경로를 남겨 다음 배치에서 다시 요청 |

13 §5 회원 탈퇴 3번의 "사진이 남지 않는다"는 **우리 저장소와 CDN 기준**이고 브라우저 캐시는 제외한다 (13에 각주 요청, §10).
