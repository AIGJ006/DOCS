## 1. 결정 사항

| # | 안건 | 결정 | 이유 |
|---|---|---|---|

| M-10 | 검색·일괄 처리 | 공통에서 제외 (개인 확장) | 1차 범위를 작게 유지 |

## 3. 탭별 항목

### 3-1. 임시글 (`status = DRAFT`, 삭제 안 됨)

| 요소 | 규칙 |
|---|---|
| 제목 | 비어 있으면 회색으로 "(제목 없음)" |
| 시각 | "마지막 저장 10월 3일 14:03" (`updated_at`, 24시간 이내는 "N분 전") |
| 버튼 | [이어 쓰기] → 에디터 / [삭제] → §4 |
| 공개 범위 | 표시하지 않는다 (임시글에는 의미 없음, 06 §2) |

### 3-2. 발행 글 (`status = PUBLISHED`, 삭제 안 됨)

| 요소 | 규칙 |
|---|---|
| 공개 범위 | 제목 앞 🌐 / 🔒 (글자 "공개"/"비공개"를 스크린 리더용으로 함께) |
| 수정 중 | `post_draft`가 있으면 [수정 중] 배지 |
| 날짜 | "발행 2026.10.01" (`published_at`), 다시 발행했으면 "· 수정됨 10월 3일" (`edited_at`) |
| 숫자 | 👁 조회수 ♥ 좋아요 💬 댓글 (M-8, 비정규화 컬럼 그대로) |
| 버튼 | [보기] → 글 상세 / [수정] 또는 수정 중이면 [이어서 수정] [변경 취소] / [공개 범위 ▾] 즉시 변경(06 §4) / [삭제] → §4 |
| 숨김 | 관리자가 숨긴 글은 "운영 정책에 따라 숨겨짐" 배지 (상세는 43 문서) |
| 필터 | [전체] [공개] [비공개] (M-7), 주소 `&visibility=public|private` |

### 3-3. 휴지통 (`deleted_at IS NOT NULL`)

| 요소 | 규칙 |
|---|---|
| 제목 | 원래 상태를 함께: "(임시글이었음)" / "(발행 글이었음)" |
| 시각 | "삭제 10월 2일 · 27일 뒤 완전 삭제" (`deleted_at + 30일`까지 남은 날, 13 §2-2) |
| 버튼 | [복구] → 원래 탭·원래 위치로 (13 D-4) / [영구 삭제] → 확인창 (13 §2-2) |
| 정렬 | `deleted_at` 최신순 |
| 안내 | 탭 위에 "휴지통의 글은 30일 뒤 자동으로 완전히 삭제돼요" |

## 4. 버튼 동작 (기존 문서의 처리를 이 화면에서 부른다)

| 버튼 | 확인창 | 처리 | 끝난 뒤 화면 |
|---|---|---|---|
| [삭제] | "휴지통으로 옮길까요? 30일 뒤 완전히 삭제돼요" (13) | `DELETE /api/posts/{id}` | 목록에서 빠지고 휴지통 개수 +1. 빈 임시글은 "빈 글이라 바로 삭제했어요" |
| [복구] | 없음 | `POST /api/posts/{id}/restore` | 휴지통에서 빠지고 "복구했어요 [발행 글 탭에서 보기]" |
| [영구 삭제] | "영구 삭제하면 되돌릴 수 없어요. 댓글·좋아요도 함께 지워져요" (13) | `DELETE /api/posts/{id}/permanent` | 목록에서 빠짐 |
| [공개 범위 ▾] | 공개 → 비공개는 없음 / 비공개 → 공개는 "모든 사람이 볼 수 있게 돼요" | `PATCH /api/posts/{id}/visibility` (06 §4) | 배지만 바뀜 (다시 발행 아님, "수정됨" 안 생김) |
| [변경 취소] | "수정 중인 내용을 버리고 발행된 글로 되돌릴까요?" | 작업본 삭제 (04 §2-5) | [수정 중] 배지가 사라짐 |
| [새 글] | 없음 | `DRAFT` 행 생성 후 에디터 (04 §2-5) | 에디터 |

- 모든 처리는 **화면을 새로 고치지 않고** 그 줄만 바꾼다(JS). JS가 없으면 폼 POST 후 같은 탭으로 돌아온다(SSR).
- 실패하면 그 줄 아래에 이유를 보여준다 (예: 이미 휴지통에 있는 글 → 목록을 다시 불러온다).

## 5. API

```
GET /api/me/posts?tab=drafts|published|trash&visibility=public|private&cursor=…
→ { items: [ … ], nextCursor, counts: { drafts: 3, published: 24, trash: 1 } }
```

| 규칙 | 내용 |
|---|---|
| 대상 | `author_id = 현재 사용자` 고정. 요청의 다른 값은 무시 |
| 개수 | 20개 (10 §4-2처럼 21개를 조회해 마지막 판단), 클라이언트가 보낸 크기는 무시 |
| 커서 | 임시글·발행 글: `(updated_at, id)` / 휴지통: `(deleted_at, id)` |
| 개수(counts) | 첫 요청에만 계산 (쿼리 1번, `GROUP BY`), [더 보기]에서는 생략 |
| 응답 항목 | `id, title, status, visibility, editing(작업본 유무), hidden, updatedAt, publishedAt, editedAt, deletedAt, purgeAt, viewCount, likeCount, commentCount` |
| 본문 | 읽지 않는다 (`content_md`, `content_html` 제외) |

> **커서와 자동 저장:** 목록을 보는 사이 다른 탭의 자동 저장이 반영되면(`updated_at` 변경) 그 글이 위로 올라가서 [더 보기]에 한 번 더 나올 수 있다. 브라우저가 이미 있는 ID는 건너뛴다 (10 §4-3의 이중 안전장치와 같은 방식).

## 6. 성능

| 항목 | 기준 |
|---|---|
| 쿼리 | 목록 1번 + (첫 요청만) 개수 1번 + 작업본 유무(`post_draft` LEFT JOIN, 목록 쿼리에 포함) |
| 인덱스 | 임시글·발행 글 `ix_post_manage(author_id, status, updated_at DESC)`, 휴지통 `ix_post_trash` (03) |
| 응답 시간 | 300ms 이내 (02 §6) |

## 7. 공통 완료 기준 (C-MANAGE-1)

| # | 기준 |
|---|---|
| 1 | 본인의 임시글·발행 글(공개·비공개)·휴지통 글만 보이고, 다른 사람의 글은 어떤 경우에도 보이지 않는다 |
| 2 | 주소나 요청에 다른 사용자 값을 넣어도 본인 글만 보인다 |
| 3 | 비회원이 들어오면 로그인 화면으로 가고, 로그인 후 이 화면으로 돌아온다 |
| 4 | 각 글에 상태(임시·🌐 공개·🔒 비공개·수정 중·숨김)가 보이고, 휴지통 글에는 완전 삭제까지 남은 날이 보인다 |
| 5 | [발행 글]의 [공개]/[비공개] 필터가 맞는 글만 보여준다 |
| 6 | 20개를 넘으면 [더 보기]로 이어지고 같은 글이 두 번 보이지 않는다 |
| 7 | [삭제]·[복구]·[영구 삭제]·[공개 범위]·[변경 취소]가 13·06·04 문서의 규칙대로 동작한다 |
| 8 | 목록 쿼리는 본문 컬럼을 읽지 않는다 |
