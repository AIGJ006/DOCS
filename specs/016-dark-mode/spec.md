## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 방문하면 기기 설정에 맞는 테마로 보인다 (Priority: P1)

방문자가 아무것도 고르지 않아도 기기를 다크로 쓰면 처음부터 다크로, 라이트로 쓰면 라이트로 보인다. 다크 사용자에게 페이지를 열 때 밝은 화면이 번쩍이지 않는다. (45 T-1·T-2·T-5, §5 #1·#3)

**Why this priority**: 다크 모드의 기본 가치다. 버튼 없이도 대부분의 사용자가 원하는 테마를 바로 얻는다.

**Independent Test**: 기기 설정을 다크로 둔 새 브라우저(저장된 선택 없음)로 여러 페이지를 열어 처음부터 다크인지, 첫 화면에 밝은 배경이 보이지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 테마를 고른 적 없는 방문자, 기기 설정 다크, **When** 아무 페이지를 열면, **Then** 다크 테마로 보인다. (45 #1)
2. **Given** 같은 조건, **When** 페이지가 처음 그려지는 순간을 확인하면, **Then** 밝은 화면이 잠깐도 보이지 않는다. (45 #3)
3. **Given** 기기 설정 라이트, **When** 처음 방문하면, **Then** 라이트 테마로 보인다.
4. **Given** 브라우저 저장소 접근이 막힌 환경, **When** 페이지를 열면, **Then** 오류 없이 기기 설정을 따른다.

---

### User Story 2 - 테마를 직접 고르고, 그 선택이 유지된다 (Priority: P1)

방문자(비회원 포함)는 헤더 맨 오른쪽 버튼으로 시스템 → 라이트 → 다크를 차례로 고른다. 고른 테마는 새로 고침·다른 페이지 이동 뒤에도 유지되고, "시스템"을 고르면 기기 설정 변경을 바로 따라간다. (45 T-1·T-3·T-4, §5 #2·#5)

**Why this priority**: 기기 설정과 다른 테마를 원하는 사용자에게 필요한 최소 조작이다.

**Independent Test**: 버튼을 눌러 세 상태를 순환하고 각 상태에서 새로 고침·페이지 이동 후 유지되는지, "시스템" 상태에서 기기 설정을 바꿔 즉시 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "시스템" 상태, **When** 버튼을 누를 때마다, **Then** 라이트 → 다크 → 시스템 순서로 바뀌고 즉시 화면에 적용되며, 버튼에는 아이콘(🖥/☀️/🌙)과 함께 현재 상태를 알리는 글자 설명이 있다.
2. **Given** 다크를 고른 방문자, **When** 새로 고치거나 다른 페이지로 이동하면, **Then** 다크가 유지된다. (45 #2)
3. **Given** "시스템" 상태, **When** 기기 설정을 라이트에서 다크로 바꾸면, **Then** 새로 고치지 않아도 다크로 바뀐다. (45 #5)
4. **Given** 라이트로 고정한 상태, **When** 기기 설정을 다크로 바꾸면, **Then** 라이트가 그대로 유지된다.
5. **Given** 다크를 고른 회원, **When** 로그아웃하면, **Then** 테마 선택은 지워지지 않는다. (T-8)
6. **Given** 다크를 고른 회원, **When** 다른 기기로 로그인하면, **Then** 그 기기에서는 그 기기의 선택(없으면 기기 설정)을 따른다(기기마다 따로 저장).

### User Story 3 - 다크에서도 글과 화면 요소가 잘 읽힌다 (Priority: P2)

라이트·다크 모두에서 본문 글자·보조 글자·테두리·아이콘이 충분한 대비를 갖고, 사진은 원래 색 그대로, 코드 강조와 상태 배지도 테마에 맞게 보인다. (45 T-6·T-7, §4, §5 #6)

**Why this priority**: 테마 전환이 동작해도 다크에서 회색 글자가 안 읽히면 쓸모가 없다. 다만 P1의 전환 동작이 먼저 있어야 검사할 수 있다.

**Independent Test**: 자동 대비 검사 도구로 주요 화면(홈 목록·개인 블로그·글 상세·에디터·설정)을 라이트·다크 각각 검사한다.

**Acceptance Scenarios**:

1. **Given** 라이트와 다크 각각, **When** 주요 화면을 자동 대비 검사 도구로 검사하면, **Then** 본문 글자는 4.5:1 이상, 큰 글자·아이콘·입력칸 테두리는 3:1 이상이다. (45 #6)
2. **Given** 다크 테마, **When** 본문 사진·썸네일·프로필 사진을 보면, **Then** 색을 뒤집거나 어둡게 하지 않고 원래 그대로 보인다.
3. **Given** 다크 테마, **When** 코드 블록이 있는 글을 보면, **Then** 코드 강조가 다크용 색 구성으로 보인다.
4. **Given** 다크 테마, **When** 공개·비공개·수정 중 배지를 보면, **Then** 색만이 아니라 글자·아이콘으로도 구분된다.
5. **Given** 다크 테마, **When** 썸네일이 없는 글 카드를 보면, **Then** 빈 영역이 카드 배경과 구분되는 색으로 보인다.

### Edge Cases

- 브라우저 저장소 접근이 막히거나(사생활 보호 모드 등) 저장된 값이 알 수 없는 값이면? → 오류 없이 "시스템"으로 처리해 기기 설정을 따른다.
- "시스템" 상태에서 페이지를 연 채 기기 설정이 바뀌면? → 새로 고치지 않아도 따라 바뀐다. 라이트·다크로 고정한 상태면 바뀌지 않는다.
- 쓰는 에디터가 다크 테마를 지원하지 않으면? → 에디터만 라이트로 두고 주변은 다크로 둔다.
- 링크 미리보기(메신저·SNS)와 메일은? → 테마와 상관없이 라이트 기준이다.
- 썸네일 빈 영역·브랜드 색 값을 개인 서비스가 바꾸면? → 이름(토큰)은 그대로 두고 값만 바꾸며, 바꾼 값도 대비 기준(FR-012)을 만족해야 한다.
- 테마를 바꿀 때 움직임 줄이기 설정을 켠 사용자는? → 전환 애니메이션 자체가 없으므로 영향이 없다.
- 탭 여러 개에서 서로 다른 테마를 고르면? → 각 탭은 마지막으로 저장된 선택을 다음에 열 때 따른다(원문에 탭 간 실시간 동기화 규정 없음, Assumptions 참고).

## Requirements *(mandatory)*

### Functional Requirements

**선택과 저장**

- **FR-001**: System MUST 모든 화면에서 테마를 시스템 설정 / 라이트 / 다크 세 가지 중 하나로 보여 줘야 한다. 적용 범위: 이 spec은 **규격만 공통**이다 — 다크 모드를 만드는 서비스는 이 동작 규칙(FR-002~FR-010)과 대비 기준(FR-012)을 지키고, 만들지 않는 서비스는 공통 완료 기준·테스트에서 빠진다. 지금 구현 대상은 나민서 서비스(MUST)다 (T-1, 01 §2-3 Tier C, Clarifications 2026-10-08).
- **FR-002**: System MUST 테마를 고른 적 없는 방문자에게 기기의 라이트·다크 설정을 따르는 "시스템"을 기본으로 적용해야 한다. (T-2, 45 #1)
- **FR-003**: System MUST 테마 선택을 서버나 계정이 아니라 방문자의 브라우저(기기마다 따로)에 저장해, 비회원도 쓸 수 있게 해야 한다. 브라우저 저장소에 접근할 수 없거나 저장된 값이 알 수 없는 값이면 오류 없이 기기 설정을 따른다. 계정에 저장해 기기 간에 맞추는 것은 개인 확장이다. (T-3, 45 §2)
- **FR-004**: 모든 페이지의 헤더 맨 오른쪽 같은 자리에 테마 전환 버튼이 있어야 하며, 누를 때마다 시스템 → 라이트 → 다크 → 시스템 순서로 바뀐다. 버튼은 아이콘(🖥/☀️/🌙)과 함께 보조 기술이 읽는 이름·툴팁으로 현재 상태를 글자로 알린다. (T-4) (2026-10-10 민서 결정: 설정 화면 라디오로 옮김) — 머리말 버튼은 없애고 설정 화면 "화면 테마"에서 시스템 설정 따르기(기본)·라이트 모드·다크 모드 중 고른다.
- **FR-005**: System MUST 고른 테마를 즉시 적용하고 저장해, 새로 고침·다른 페이지 이동 뒤에도 유지해야 한다. (45 §2, 45 #2)
- **FR-006**: System MUST "시스템" 상태에서는 기기 설정이 바뀌면 새로 고치지 않아도 따라 바뀌게 하고, 라이트·다크로 고정한 상태에서는 기기 설정 변경을 무시해야 한다. (45 §2, 45 #5)
- **FR-007**: System MUST 로그아웃할 때 테마 선택을 지우지 않아야 한다(개인 정보가 아님. 로그아웃 때 지우는 것은 임시 글 데이터뿐 → specs/001-account-auth, specs/002-post-authoring). (T-8)

**깜빡임 방지와 보안 정책**

- **FR-008**: System MUST 페이지의 첫 화면을 그리기 전에 테마를 정해, 다크 테마 사용자에게 밝은 화면이 잠깐도 보이지 않게 해야 한다. (T-5, 45 #3)
- **FR-009**: System MUST 테마 결정과 전환을 페이지 안에 직접 쓴 스크립트 없이 우리 사이트가 제공하는 파일만으로 해, 사이트 보안 정책("스크립트는 우리 사이트 파일만", → specs/002-post-authoring FR-049) 위반이 없어야 한다. (T-5, 45 #4)
- **FR-010**: 테마가 바뀔 때 색이 서서히 바뀌는 애니메이션을 넣지 않아야 한다(첫 화면 번쩍임의 원인이 되고, 움직임 줄이기 사용자에게 불편하다). (45 §2)

**색 토큰과 대비**

- **FR-011**: 화면 색은 정해진 색 토큰(배경, 카드·헤더·상자 면, 본문 글자, 보조 글자, 구분선·테두리, 링크·강조 글자, 흰 글자가 올라가는 버튼 배경, 삭제·오류, 썸네일 빈 영역, 코드 블록 배경, 키보드 포커스 테두리)으로만 정의하고, 화면 요소는 색 값을 직접 쓰지 않아야 한다. 토큰마다 라이트·다크 값을 한곳에 두어 다크 값을 바꾸면 모든 화면에 반영된다. 토큰 **이름** 11개(45 §3: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-brand`, `--color-brand-fill`, `--color-danger`, `--thumb-empty`, `--color-code-bg`, `--color-focus`)는 세 사람의 공통 규격이고, 값은 각자 바꾼다(2026-10-07 O5는 "어떻게 보이는가"만 자유). Tier A 공통 부품이 쓰는 `--card-*` 이름은 이 이름으로 바꾼다 (T-6, 45 §3, Clarifications 2026-10-08)
- **FR-012**: System MUST 라이트·다크 모두에서 본문 글자의 배경 대비를 4.5:1 이상, 큰 글자·아이콘·입력칸 테두리·포커스 테두리의 대비를 3:1 이상(WCAG 2.2 AA)으로 유지해야 한다. 각자 정하는 링크·강조 글자 색은 배경 대비 4.5:1, 버튼 배경 위 흰 글자는 4.5:1을 확인한다. (T-7, 45 §3·§4, 45 #6)
- **FR-013**: 원문의 공통 기본 색 값은 아래와 같고, 개인 서비스는 이름을 바꾸지 않고 값만 바꿀 수 있어야 한다(2026-10-07 O5: 색은 각자 자유). 다크 배경은 순수 검정 대신 `#121212`를 기본으로 한다. (T-6, 45 §3)

  | 토큰 용도 | 라이트 | 다크 |
  |---|---|---|
  | 페이지 배경 | `#FFFFFF` | `#121212` |
  | 카드·헤더·상자 | `#FFFFFF` | `#1E1E1E` |
  | 본문 글자 | `#212529` | `#E9ECEF` |
  | 날짜·보조 글자 | `#6C757D` | `#ADB5BD` |
  | 구분선·카드 테두리 | `#DEE2E6` | `#343A40` |
  | 링크·강조 글자 / 버튼 배경 | 각자 | 각자 (다크에서는 더 밝게) |
  | 삭제·오류 | `#C92A2A` | `#FF6B6B` |
  | 썸네일 빈 영역 (예시) | `#F1F3F5` | `#2B2F33` |
  | 코드 블록 배경 | `#F8F9FA` | `#1A1B1E` |
  | 키보드 포커스 테두리 | `#1C7ED6` | `#74C0FC` |

- **FR-014**: 썸네일이 없는 글 카드의 빈 영역은 썸네일 빈 영역 토큰 색으로 카드 배경과 구분되어 보여야 한다. 구체적인 색 값은 각자 자유다(→ specs/005-post-reading). (10 L-7, 2026-10-07 O5)

**요소별 규칙**

- **FR-015**: System MUST 본문 사진·썸네일·프로필 사진을 다크 테마에서도 색을 뒤집거나 어둡게 하지 않고 그대로 보여야 한다. (45 §4)
- **FR-016**: 사진이 없는 회원의 기본 프로필 아이콘(8가지 배경색)은 다크 테마에서도 글자와 4.5:1 이상의 대비를 가져야 한다(→ specs/001-account-auth FR-051). (11 §4-3, 45 §4)
- **FR-017**: 코드 강조는 라이트용·다크용 색 구성 두 가지를 현재 테마에 맞춰 적용해야 한다. 본문의 표·인용·체크리스트는 토큰 색(테두리·보조 글자)만 쓴다. (45 §4)
- **FR-018**: 에디터는 다크 테마를 지원하면 현재 테마와 같게 켜고, 지원하지 않으면 에디터만 라이트로 두되 주변 화면은 현재 테마를 따른다. 에디터 선택은 각자다. (45 §4)
- **FR-019**: 상태 배지(공개·비공개·수정 중 등)는 색만으로 구분하지 않고 글자·아이콘을 함께 보여야 한다. (45 §4)
- **FR-020**: 스크롤바·기본 입력칸 등 브라우저가 그리는 요소도 현재 테마를 따르도록 페이지가 라이트·다크 두 테마를 지원한다고 브라우저에 알려야 한다. (45 §4)
- **FR-021**: 링크 미리보기(메신저·SNS가 가져가는 요약)와 메일은 테마와 상관없이 라이트 기준이어야 한다. (45 §4)

### Key Entities *(include if feature involves data)*

- **테마 선택**: 방문자 브라우저에 저장되는 값 하나("시스템" / "라이트" / "다크", 없으면 시스템). 서버·계정·DB에 저장하지 않는다(ERD 변경 없음).
- **적용 테마**: 테마 선택과 기기 설정으로 정해지는 실제 테마(라이트 / 다크).
- **색 토큰**: 이름 하나에 라이트·다크 값 한 쌍. 화면 요소는 이름만 참조한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기기 설정이 다크인 첫 방문자에게 첫 화면이 그려지는 순간 밝은 배경이 보이는 경우가 0건이다(주요 화면 녹화로 확인).
- **SC-002**: 라이트·다크를 고른 뒤 새로 고침·다른 페이지 이동을 했을 때 선택이 유지되는 비율이 100%다.
- **SC-003**: 테마 기능으로 인한 사이트 보안 정책(스크립트 허용 범위) 위반 보고가 0건이다.
- **SC-004**: 자동 대비 검사 도구로 주요 화면(홈 목록·개인 블로그·글 상세·에디터·설정)을 라이트·다크 각각 검사했을 때 대비 기준 위반이 0건이다.
- **SC-005**: "시스템" 상태에서 기기 설정을 바꾸면 새로 고치지 않고 테마가 바뀌는 비율이 100%다.
- **SC-006**: 다크 테마에서 본문 사진·썸네일·프로필 사진의 색이 바뀌어 보이는 경우가 0건이다.

## Assumptions

- 범위: 다크 모드는 01 §2-3의 Tier C(강 P3 / 나 MUST / 김 3차) 화면 요소이며 ERD와 무관하다. 원문(45)은 담당 나민서의 초안이다. 규격만 공통이고 구현은 원하는 서비스만 한다(FR-001, Clarifications 2026-10-08).
- 화면 구성은 2026-10-07 Q2·H7로 React + REST API로 확정되었으므로, 45가 전제한 "SSR이든 SPA든" 중 SPA 방식(React 앱의 첫 HTML `<head>`에 테마 결정 파일을 넣는 방식)만 해당한다고 가정한다.
- 공통 = 무엇을 보여 주는가, 각자 자유 = 어떻게 보이는가(색·글꼴·레이아웃·빈 썸네일 색, 2026-10-07 O5). 따라서 이 spec의 색 값은 공통 기본값·예시이고, 대비 기준(FR-012)과 동작 규칙(FR-002~FR-010)은 구현하는 모든 서비스가 지킨다고 가정한다.
- 개인 확장: 계정에 테마를 저장해 기기 간 동기화.
- 각자 확인할 것: 강성찬·김민서 에디터의 다크 테마 지원 여부(45 "다른 담당자와 맞출 것").
- 대비 검사에 쓸 자동 도구는 원문이 정하지 않았다. 일반적인 웹 접근성 대비 검사 도구를 쓴다고 가정한다.
- 탭 여러 개 사이의 실시간 테마 동기화는 원문에 없어 범위 밖으로 둔다.
- 원문 간 충돌 처리: ① 45 §5 #7(2026-10-03)은 썸네일 빈 영역을 라이트 `#F1F3F5`·다크 `#2B2F33`으로 고정한 공통 완료 기준이었으나, 2026-10-07 O5와 10 L-7이 "빈 썸네일 색은 각자 자유"로 정했으므로 값은 예시로만 두고 완료 기준에서 뺐다(FR-014). ② 45 §5 #8·§2의 "JS가 꺼져 있을 때" 동작은 2026-10-07 Q2·H7(React 결정, 다른 문서의 "JS 없을 때 SSR 대체" 규칙 삭제)과 맞지 않아 삭제했다(User Story 4·FR-022, Clarifications 2026-10-08). ③ 45 "다른 담당자와 맞출 것"의 "화요일 안건 1(SSR/SPA)"은 Q2로 결정되었다.

## Implementation Notes (for /speckit-plan)

원문의 기술 결정 요약 ([45](../../docs/45-dark-mode.md)).

- **저장** (T-3, [45 §2](../../docs/45-dark-mode.md)): `localStorage` 키 `theme` = `'system' | 'light' | 'dark'`(없으면 system). 접근 실패는 `try/catch`로 시스템 설정만 따른다. ERD 변경 없음.
- **깜빡임 방지** (T-5, [45 §2](../../docs/45-dark-mode.md)): `<head>`에서 외부 파일 `/js/theme-init.js`(1KB 미만)를 `defer` 없이 CSS보다 먼저 동기 실행 → `document.documentElement.dataset.theme = 'light'|'dark'`, `dataset.themeChoice = saved || 'system'`. 판정: 저장값이 light/dark면 그 값, 아니면 `matchMedia('(prefers-color-scheme: dark)')`. 인라인 스크립트는 CSP `script-src 'self'`([12 §8](../../docs/12-content-sanitize.md))가 막으므로 쓰지 않는다. React는 같은 `theme-init.js`를 `index.html` `<head>`에 넣는다.
- **변경 감지**: "시스템" 상태에서 `matchMedia` 변경 이벤트로 `data-theme` 갱신. 버튼은 `localStorage` 저장 + 즉시 `data-theme` 변경, `aria-label`·툴팁 (T-4).
- **CSS** ([45 §3](../../docs/45-dark-mode.md)): CSS 변수 `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-brand`, `--color-brand-fill`, `--color-danger`, `--thumb-empty`, `--color-code-bg`, `--color-focus`. 선택자 `:root, [data-theme="light"] { … }`, `[data-theme="dark"] { … }`, JS 없을 때의 `@media (prefers-color-scheme: dark)` 규칙은 선택(FR-022 삭제). 전환 `transition` 없음.
- **요소** ([45 §4](../../docs/45-dark-mode.md)): highlight.js 테마 `github.css` / `github-dark.css`를 `data-theme`에 맞춰 적용, `<meta name="color-scheme" content="light dark">`, 에디터(예: Toast UI)는 다크 테마 지원 시 같은 `data-theme`로 켬.
- **관련 규칙**: 기본 프로필 아이콘 8색 대비([11 §4-3](../../docs/11-profile.md)), 썸네일 빈 영역([10 L-7](../../docs/10-post-list.md)), 로그아웃 시 지우는 데이터([07 §7](../../docs/07-auth.md)).
