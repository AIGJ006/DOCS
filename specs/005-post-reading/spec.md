## User Scenarios & Testing *(mandatory)*

### User Story 1 - 홈에서 최신 공개 글 둘러보기 (Priority: P1)

누구나(비회원 포함) 홈에서 공개·발행된 글을 처음 공개된 순서의 최신순으로 9개씩 카드로 본다. [더 보기]를 누르면 그다음 9개가 아래에 이어 붙고, 보는 도중 글이 새로 올라오거나 사라져도 같은 글이 두 번 나오거나 빠지지 않는다.

**Why this priority**: C-READ-1(Tier A)이다. 플랫폼에 들어온 사람이 가장 먼저 보는 화면이다.

**Independent Test**: 공개 글 20개, 비공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글을 섞어 두고 홈을 열어 공개 글만 9개씩 정렬되어 나오는지, [더 보기] 도중 새 글을 발행·기존 글을 삭제해도 중복·누락이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개·발행 글과 그렇지 않은 글이 섞여 있을 때, **When** 홈을 열면, **Then** 공개·발행 글만(휴지통·관리자 숨김·탈퇴 신청 작성자 글 제외) 최초 공개 일자 최신순, 같으면 글 번호 큰 순으로 9개가 카드로 보인다 (C-READ-1 #1).
2. **Given** 남은 글이 있을 때, **When** [더 보기]를 누르면, **Then** 마지막 카드보다 이전 글 9개가 아래에 이어 붙고, 더 없으면 버튼이 사라지며 "모든 글을 다 봤어요"가 보인다. 빈 결과를 받는 클릭은 없다 (C-READ-1 #2).
3. **Given** 사용자가 2페이지까지 본 상태일 때, **When** 그 사이 새 글이 발행되고 이미 본 글 하나가 삭제·비공개되면, **Then** 이어 붙는 목록에 같은 글이 두 번 나오거나 빠지는 글이 없다. 이미 화면에 있던 카드는 남고 누르면 404다 (C-READ-1 #3).
4. **Given** 홈 카드일 때, **When** 화면을 보면, **Then** 썸네일(640px), 제목 1줄, 본문 미리보기 3줄, 발행 날짜·댓글 수, 작성자·좋아요 수가 보이고, 썸네일이 없는 카드도 높이가 같다 (C-READ-1 #4).
5. **Given** 375px 폭의 휴대폰일 때, **When** 홈을 보면, **Then** 페이지 가로 스크롤이 없다 (C-READ-1 #5).
6. **Given** 사용자가 이어 보기 위치 값을 고치거나 다른 목록의 값을 보낼 때, **When** 목록을 요청하면, **Then** 잘못된 위치 오류로 거부된다 (C-READ-1 #7).

### User Story 2 - 글 상세 읽기 (Priority: P1)

독자는 글 주소로 들어와 제목, 작성자, 날짜, 본문, 태그, 좋아요·조회수, 작성자 카드, 댓글을 한 화면에서 본다. 볼 수 없는 글은 없는 글과 똑같이 404다.

**Why this priority**: C-READ-2(Tier A)다. 글을 읽을 수 없으면 플랫폼의 의미가 없다.

**Independent Test**: 공개 글을 비회원으로 열어 모든 요소가 보이는지, 다시 발행한 글에만 "수정됨"이 붙는지, 비공개·임시·휴지통 글과 없는 글 주소가 같은 404인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개·발행 글일 때, **When** 비회원이 상세 주소를 열면, **Then** 제목, `닉네임 @블로그주소` 작성자 영역, 최초 공개 일자, 본문, 입력 순서대로의 태그, 좋아요 수·조회수, 작성자 카드, 댓글이 보인다 (40 §2, §7 #5·#12).
2. **Given** 없는 글, 남의 비공개·임시 글, 휴지통 글, 남이 보는 숨긴 글, 탈퇴 신청 작성자의 글일 때, **When** 상세 주소를 열면, **Then** 모두 404이고 상태 코드·본문·미리보기 문구가 같다 (C-READ-2, 40 §7 #1).
3. **Given** 다시 발행한 글일 때, **When** 상세를 보면, **Then** 날짜 옆에 "수정됨 · 10월 3일"이 보이고, 공개 범위만 바꾼 글에는 보이지 않는다 (40 §7 #4).
4. **Given** 상세를 열었을 때, **When** 조회수를 확인하면, **Then** 상세를 연 것만으로는 조회수가 바뀌지 않는다 (40 R-7, §7 #7).
5. **Given** 댓글이 30개인 글일 때, **When** 상세를 열면, **Then** 최상위 댓글 첫 20개(각 답글 처음 3개 포함)와 댓글 수가 보이고 [댓글 더 보기]가 있다 (40 §2).
6. **Given** 알림에서 특정 댓글 링크로 들어올 때, **When** 상세가 열리면, **Then** 그 댓글부터 보이고, 정규 주소에는 댓글 표시 값이 들어가지 않는다 (40 §7 #11).

### User Story 3 - 개인 블로그 페이지 (Priority: P1)

`/@블로그주소`에서 그 사람의 프로필과 공개 글을 홈과 같은 카드·정렬·9개·[더 보기]로 본다. 작성자 본인이 봐도 비공개 글은 나오지 않는다.

**Why this priority**: C-BLOG-1(Tier A)이다. 1인 1블로그의 얼굴이다.

**Independent Test**: 공개 글 12개와 비공개 글 3개가 있는 회원의 블로그를 본인·남으로 열어 상단 프로필·공개 글 수, 카드 9개 + [더 보기], 비공개 글 미노출을 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글과 비공개 글이 있는 회원일 때, **When** 누구든 그 블로그를 열면, **Then** 그 사람의 공개·발행 글만 홈과 같은 카드(작성자 영역 제외)·정렬·9개·[더 보기]로 보인다 (C-BLOG-1 #1).
2. **Given** 블로그 페이지일 때, **When** 상단을 보면, **Then** 프로필 사진(없으면 기본 아이콘), 닉네임, `@블로그주소`, 소개, 보는 사람 기준의 공개 글 수가 보인다 (C-BLOG-1 #2).
3. **Given** 작성자 본인일 때, **When** 자기 블로그를 열면, **Then** 비공개 글과 숨긴 글은 나오지 않는다 (C-BLOG-1 #3).
4. **Given** 존재하지 않거나 탈퇴 신청·익명 처리된 블로그 주소일 때, **When** 열면, **Then** 404다. 대문자가 섞인 주소는 소문자 주소로 영구 이동한다 (10 §5, 42 §9).
5. **Given** 공개 글이 하나도 없을 때, **When** 남이 열면 "아직 공개한 글이 없어요", 본인이 열면 "첫 글을 써 보세요 [글쓰기]"가 보인다.

### User Story 4 - 작성자가 자기 글을 볼 때 (Priority: P2)

작성자는 자기 글 상세에서 독자와 같은 모습을 확인하면서, 자기에게만 보이는 상태 표시와 [수정]·[공개 범위]·[삭제] 버튼을 쓴다. 임시글 주소를 열면 에디터로, 수정 중인 글은 마지막 발행본과 "수정 중" 안내를 본다.

**Why this priority**: 작성자 경험을 다듬는 기능으로, 독자 화면(US2)이 먼저 있어야 한다.

**Independent Test**: 같은 작성자로 공개 글, 비공개 글, 수정 중인 글, 임시글, 숨긴 글, 휴지통 글의 상세 주소를 차례로 열어 표시를 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자의 수정 중인 발행 글일 때, **When** 상세를 열면, **Then** 독자와 같은 마지막 발행본과 상단 안내 "수정 중인 내용이 있어요(10월 3일 14:03 저장) [이어서 수정] [변경 취소]"가 보인다 (40 R-5, §7 #3).
2. **Given** 작성자의 임시글일 때, **When** 그 상세 주소를 열면, **Then** 에디터로 이동한다 (40 R-4).
3. **Given** 작성자의 비공개 발행 글일 때, **When** 상세를 열면, **Then** 독자와 같은 모습에 🔒 비공개 표시와 "나만 볼 수 있는 글이에요"가 보이고, 날짜는 최초 발행 일자다 (40 R-6, §2-1).
4. **Given** 관리자가 숨긴 작성자의 글일 때, **When** 작성자가 상세를 열면, **Then** "운영 정책에 따라 숨겨진 글이에요. 다른 사람에게는 보이지 않아요" 안내와 함께 보인다 (40 §2-1).
5. **Given** 휴지통에 있는 글일 때, **When** 작성자가 상세 주소를 열면, **Then** 404다 (40 §2-1).
6. **Given** 작성자가 자기 글을 볼 때, **When** 버튼을 확인하면, **Then** [수정]·[공개 범위 ▾]·[삭제]가 보이고 [좋아요]·[신고]·[팔로우]는 없으며 조회 기록도 되지 않는다 (40 §7 #6·#7·#13).

### User Story 5 - 주소 처리와 링크 미리보기 (Priority: P2)

글 주소를 잘못 옮겨 적어도 볼 수 있는 글이면 올바른 주소로 이동하고, 메신저·SNS에 공유하면 제목·요약·대표 사진이 담긴 미리보기가 나온다. 볼 수 없는 글은 존재를 드러내지 않는다.

**Why this priority**: 공유·검색 유입을 위한 기능이다. 핵심 읽기(US2) 위에 붙는다.

**Independent Test**: 공개 글을 다른 블로그 주소로 열어 올바른 주소로 이동하는지, 비공개 글을 같은 방식으로 열면 404인지, 공개 글의 미리보기 정보와 볼 수 없는 글의 공통 문구를 확인한다.

**Acceptance Scenarios**:

1. **Given** 볼 수 있는 글을 다른 사람의 블로그 주소로 열 때, **When** 서버가 처리하면, **Then** 올바른 주소로 영구 이동한다 (40 R-3, §7 #2).
2. **Given** 볼 수 없는 글을 다른 블로그 주소로 열 때, **When** 서버가 처리하면, **Then** 이동하지 않고 404다 (작성자가 드러나지 않음).
3. **Given** 글 번호 자리가 숫자가 아닐 때, **When** 열면, **Then** 404다.
4. **Given** 공개 글 주소를 메신저에 붙여 넣을 때, **When** 미리보기가 만들어지면, **Then** 제목, 요약 앞 160자, 첫 사진 원본(없으면 서비스 기본 이미지)이 보인다 (40 §5, §7 #10).
5. **Given** 볼 수 없는 글이나 작성자 본인이 보는 비공개 글일 때, **When** 미리보기·검색 엔진 정보를 보면, **Then** 공통 문구와 검색 엔진 수집 금지 표시만 있다.

### User Story 6 - 편안한 목록 탐색 (Priority: P3)

[더 보기]를 여러 번 누른 뒤 글을 보고 뒤로 돌아와도 처음부터 다시 누를 필요가 없고, 불러오는 중·실패·빈 목록일 때 무엇을 해야 할지 안내를 받는다.

**Why this priority**: 사용성 개선이다. 목록(US1·US3)이 있어야 한다.

**Independent Test**: [더 보기]를 3번 누르고 스크롤한 뒤 글을 열었다가 뒤로 가서 카드·스크롤 위치가 복원되는지, 네트워크를 끊고 [더 보기]를 눌러 실패 안내와 [다시 시도]가 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** [더 보기]를 여러 번 누르고 스크롤한 상태일 때, **When** 글을 열었다가 30분 안에 뒤로 가면, **Then** 불러온 카드와 스크롤 위치가 그대로 복원된다 (10 L-6).
2. **Given** 30분이 지났거나 보관값이 없을 때, **When** 돌아오면, **Then** 처음 9개부터 보인다.
3. **Given** [더 보기]를 눌렀을 때, **When** 불러오는 중이면 버튼이 "불러오는 중…"으로 바뀌어 비활성화되고, 실패하면 "불러오지 못했어요 [다시 시도]"가 보이며 다시 시도는 같은 위치부터 요청한다.
4. **Given** 공개 글이 하나도 없을 때, **When** 홈을 열면, **Then** "아직 올라온 글이 없어요. 첫 글의 주인공이 되어 보세요 [글쓰기]"(비회원에게는 [로그인])가 보인다.

### Edge Cases

- 같은 시각(같은 밀리초)에 공개된 글이 여러 개여도 이어 보기에서 빠지지 않는다 (시각은 마이크로초까지 비교, 같으면 글 번호로 가름).
- 클라이언트가 한 번에 9개가 아닌 개수를 요청해도 항상 9개로 고정된다.
- 정확히 9개만 남았을 때 [더 보기]를 누르면 9개가 오고 버튼이 사라진다(빈 결과를 받는 클릭이 없다).
- 비공개로 발행했다가 나중에 처음 공개한 글은 그 순간이 공개 일자가 되어 홈 맨 위에 생기지만, 이미 이어 보는 목록에는 끼어들지 않는다. 새로 고치면 맨 위에 보인다.
- 글이 수정(다시 발행)되어도 최초 공개 일자는 바뀌지 않으므로 목록 순서가 바뀌지 않는다.
- 요약이 비어 있는 글(코드만 있는 글 등)은 빈 3줄 높이로 표시된다.
- 썸네일이 없는 옛 사진은 원본 주소로 대체해 카드에 쓴다.
- 썸네일이 없는 글 카드도 같은 크기의 빈 영역을 두어 높이가 같다.
- 댓글 수·좋아요 수가 0이어도 표시한다.
- 상세 주소 뒤의 추적용 값(`?utm_source=…`)은 정규 주소에 들어가지 않는다.
- 조회 기록 요청이 실패해도 상세 화면에는 영향이 없다 (01 §3-5).
- 세션 저장소 장애 중에는 로그인 정보를 읽지 못해 비회원으로 처리되지만 공개 글 읽기는 계속된다 (02 §2-1).
- 프로필 사진이 없는 작성자는 기본 아이콘으로 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

**전체 글 목록 (C-READ-1, 10 §1~§4)**

- **FR-001**: System MUST 홈에 공개·발행 글만 보여준다. 휴지통 글, 관리자 숨김 글, 탈퇴 신청한 작성자의 글은 제외한다. 노출 조건 자체는 → [specs/004-visibility-permission](../004-visibility-permission/spec.md) FR-009 공용 조건을 따른다.
- **FR-002**: 목록은 최초 공개 일자 최신순, 같으면 글 번호 큰 순으로 정렬하고, 카드의 발행 날짜도 같은 최초 공개 일자를 쓴다 (10 L-1).
- **FR-003**: System MUST 한 번에 9개씩 보여주고, 다음 글이 있는지를 미리 알아 빈 결과를 받는 [더 보기] 클릭이 생기지 않게 한다. 클라이언트가 다른 개수를 요청해도 9개로 고정한다 (10 L-2, §4-2).
- **FR-004**: [더 보기]는 마지막 카드보다 이전 글 9개를 아래에 이어 붙이고, 더 없으면 버튼을 없애고 "모든 글을 다 봤어요"를 보여준다 (10 §4-1).
- **FR-005**: 이어 보기 위치는 마지막 카드의 정렬 값(최초 공개 일자·글 번호)으로 정해져, 보는 도중 새 글 발행·삭제·비공개 전환·수정·첫 공개가 있어도 같은 글이 두 번 나오거나 빠지지 않아야 한다. 이미 화면에 있는 카드는 남고(누르면 404), 화면은 이미 있는 글 번호를 한 번 더 건너뛴다 (10 §4-3, C-READ-1 #3).
- **FR-006**: 이어 보기 위치 값은 서버만 해석하는 불투명한 값이며 클라이언트는 받은 값을 그대로 돌려줄 뿐이다. 시각은 마이크로초까지 담는다. 풀 수 없는 값, 모르는 형식 버전, 빠진 항목, 다른 목록의 값은 잘못된 위치 오류로 거부한다. 첫 페이지는 위치 값 없이 요청한다 (10 §4-2, 2026-10-07 O8). 이 형식은 태그·피드·검색·트렌딩·댓글 등 모든 이어 보기 목록이 함께 쓴다.

**글 카드 (10 §2, 2026-10-07 O5)**

- **FR-007**: 카드에는 썸네일, 제목, 본문 미리보기, 발행 날짜, 댓글 수, 작성자(작은 프로필 사진 또는 기본 아이콘 + 닉네임), 좋아요 수를 보여준다. 이 정보 구성은 공통이며, 색·글꼴·레이아웃·한 줄 카드 개수·썸네일 비율·빈 썸네일 색은 각자 정한다.
- **FR-008**: 썸네일은 본문 첫 번째 업로드 사진의 640px 썸네일이다(발행 때 지정, → [specs/002-post-authoring](../002-post-authoring/spec.md)). 썸네일이 없는 옛 사진은 원본으로 대체한다. 썸네일은 화면에 가까워질 때 불러오고, 대체글은 글 제목이다. 썸네일이 없으면 같은 크기의 빈 영역을 둔다 (10 §2, §6).
- **FR-009**: 제목은 1줄, 넘치면 말줄임표로 자르고 전체 제목을 마우스를 올리면 볼 수 있게 한다.
- **FR-010**: 본문 미리보기는 화면 기준 3줄, 넘치면 말줄임표. 내용이 짧거나 비어 있어도 3줄 높이를 확보해 같은 줄의 카드 높이를 맞춘다 (10 L-3).
- **FR-011**: 미리보기 요약은 정화된 본문에서 코드 블록·이미지·표·수식을 통째로 빼고, 제목·문단·목록의 글자만 꺼내(인라인 코드·링크는 글자로 남김), 줄바꿈·연속 공백을 공백 하나로 합친 뒤, 앞 200자(단어 중간이면 그 단어 앞)로 만든다. 요약은 발행할 때 만든다 (10 §2-1, → [specs/002-post-authoring](../002-post-authoring/spec.md)).
- **FR-012**: 날짜는 1시간 이내 "N분 전", 24시간 이내 "N시간 전", 그 이후 `2026.10.02` 형식으로 보여주고, 원래 시각도 기계가 읽을 수 있게 함께 담는다 (10 L-5).
- **FR-013**: 댓글 수는 삭제·숨김되지 않은 댓글 수, 좋아요 수와 함께 0이어도 표시한다.
- **FR-014**: 카드 전체를 누르면 글 상세로, 작성자 영역만 누르면 그 블로그로 간다. 두 링크 모두 키보드로 이동할 수 있다.
- **FR-015**: 페이지 가로 스크롤이 없어야 한다(375px ~ 데스크톱). 같은 줄의 카드는 높이가 같다. 한 줄 카드 개수는 각자 정한다(예시: 1024px 이상 3개, 640~1023px 2개, 640px 미만 1개) (10 L-4, §3, 02 §6).

**목록 상태·복원 (10 §4-4, §8)**

- **FR-016**: [더 보기]를 누르면 불러오는 동안 버튼을 "불러오는 중…"으로 바꾸고 비활성화한다. 실패하면 "불러오지 못했어요 [다시 시도]"를 보여주고 같은 위치로 다시 요청한다. 처음 목록을 불러오지 못하면 "글을 불러오지 못했어요 [다시 시도]"를 보여준다.
- **FR-017**: 홈에 글이 하나도 없으면 "아직 올라온 글이 없어요. 첫 글의 주인공이 되어 보세요 [글쓰기]"(비회원에게는 [로그인])를 보여준다.
- **FR-018**: 불러온 카드 목록, 다음 위치 값, 스크롤 위치를 이 탭에 30분 보관해 뒤로 가기로 돌아오면 복원한다. 보관값이 없거나 30분이 지나면 처음 9개부터 보여준다 (10 L-6).

**개인 블로그 (C-BLOG-1, 10 §5)**

- **FR-019**: `/@블로그주소` 페이지는 홈과 같은 카드(작성자 영역만 뺌), 같은 정렬, 9개, [더 보기]를 쓴다.
- **FR-020**: 상단에 프로필 사진(없으면 기본 아이콘), 닉네임, `@블로그주소`, 소개, 공개 글 수를 보여준다. 공개 글 수는 보는 사람 기준으로 센다(공통에서는 공개·발행 글 수) (10 §5, 06 §3).
- **FR-021**: 블로그 목록에는 그 사람의 공개·발행 글만 나온다. 내 블로그여도 비공개 글·숨긴 글은 나오지 않고 내 글 관리에서만 보인다 (06 V-8, → [specs/006-manage-delete](../006-manage-delete/spec.md)).
- **FR-022**: 없는 블로그 주소, 탈퇴 신청 중이거나 익명 처리된 블로그 주소는 404다. 대문자가 섞인 주소는 소문자 주소로 영구 이동한다 (10 §5, 42 §9, 블로그 주소 규칙은 → [specs/001-account-auth](../001-account-auth/spec.md)).
- **FR-023**: 공개 글이 없으면 남이 볼 때 "아직 공개한 글이 없어요", 본인이 볼 때 "첫 글을 써 보세요 [글쓰기]"를 보여준다.
- **FR-024**: (`FRIENDS` 적용자만) 친구가 보는 블로그에는 친구 공개 글도 포함하고 최초 발행 일자 최신순으로 정렬한다 (→ [specs/004-visibility-permission](../004-visibility-permission/spec.md) FR-048).

**글 상세 주소 처리 (40 R-1·R-3·R-4, §3)**

- **FR-025**: 글 주소는 `/@블로그주소/posts/{글 번호}`다 (01 Q4, 글 번호 기반).
- **FR-026**: 상세 요청은 다음 순서로 처리한다: ① 블로그 주소에 대문자가 있으면 소문자 주소로 영구 이동 → ② 글 번호가 숫자가 아니면 404 → ③ 글을 읽을 수 있는지 판정, 볼 수 없으면 404 (→ [specs/004-visibility-permission](../004-visibility-permission/spec.md)) → ④ 주소의 블로그가 글 작성자와 다르면 올바른 주소로 영구 이동 → ⑤ 작성자 본인이 자기 임시글을 열면 에디터로 이동 → ⑥ 상세 표시. 볼 수 없는 글에는 ④의 이동을 하지 않는다(작성자가 드러나지 않음).
- **FR-027**: 주소 뒤의 추가 값(추적용 값, 댓글 표시 값)은 정규 주소에 넣지 않고, 정규 주소를 페이지에 명시한다. 댓글 표시 값만 댓글 영역에 넘긴다 (40 §3).

**글 상세 화면 (40 §2)**

- **FR-028**: 제목은 페이지의 유일한 최상위 제목이고 글자 그대로(HTML로 해석하지 않음) 보여준다. 본문 제목은 한 단계 아래부터 시작한다 (→ [specs/002-post-authoring](../002-post-authoring/spec.md)).
- **FR-029**: 작성자 영역은 프로필 사진(없으면 기본 아이콘)과 `닉네임 @블로그주소`이며 누르면 그 블로그로 간다 (09 N-9, C-AUTH-2).
- **FR-030**: 표시 날짜는 공개 글이면 최초 공개 일자(목록 카드와 같은 날짜), 비공개 글(작성자만 봄)이면 최초 발행 일자다. 형식은 FR-012와 같다. 다시 발행한 글(재발행 일자가 있는 글)에만 "수정됨 · 10월 3일"을 붙이고, 공개 범위만 바꾼 글에는 붙이지 않는다 (40 R-6, 05 P-2, 06 V-6).
- **FR-031**: 본문은 발행 때 저장된 정화된 결과를 그대로 보여주고 조회할 때 다시 만들지 않는다. 코드 강조 도구는 코드 블록이 있을 때만 불러온다 (40 §2, 12).
- **FR-032**: 태그는 입력한 순서대로 `#이름`으로 보여주고, 각 태그는 그 태그의 글 목록으로 연결된다 (40 §2, → [specs/008-tag](../008-tag/spec.md)).
- **FR-033**: 태그 아래 반응 줄에 좋아요 수(맨 앞)와 [좋아요], "조회 1,234"(1만 이상은 "1.2만") 및 조회수 안내 문구, [신고]를 둔다. 버튼 표시 조건은 → [specs/004-visibility-permission](../004-visibility-permission/spec.md) FR-045, 좋아요·조회수 규칙은 → [specs/009-like-view](../009-like-view/spec.md), 신고는 → [specs/014-report-hide](../014-report-hide/spec.md). "내가 좋아요를 눌렀는지"는 상세를 열 때 함께 가져온다. 목록 카드에는 조회수를 보여주지 않는다 (31 W-8).
- **FR-034**: 작성자 카드에 프로필 사진·닉네임·`@블로그주소`, 소개(글자만, 줄바꿈 유지), [블로그 가기], [팔로우]를 둔다. [팔로우]는 내 글이면 없고, 비회원이 누르면 로그인 안내, 팔로우 중이면 [팔로잉 ✓]이다 (→ [specs/010-follow-feed](../010-follow-feed/spec.md)).
- **FR-035**: 댓글 영역 머리말에 댓글 수를 보여주고, 상세를 열면 최상위 댓글 첫 20개(각 답글 처음 3개 포함)가 바로 보이며 [댓글 더 보기]로 이어 본다. 특정 댓글 표시 값으로 들어오면 그 댓글부터 보여준다 (40 §2, → [specs/007-comment](../007-comment/spec.md)).
- **FR-036**: 본문의 GIF는 첫 장면 + ▶로 보이고 누르면 재생되도록 재생 기능을 상세 페이지에 포함한다 (→ [specs/003-image-upload](../003-image-upload/spec.md) FR-039).
- **FR-037**: 상세 페이지는 인라인 스크립트 없이 동작해야 한다(조회 기록·GIF 재생 모두 우리 서버가 제공하는 별도 파일) (40 §7 #8).

**작성자가 볼 때 (40 R-4·R-5, §2-1)**

- **FR-038**: 상태 표시([임시저장]·[🔒 비공개]·[수정 중])와 [수정](에디터로)·[공개 범위 ▾](전체 공개/나만 보기 즉시 변경)·[삭제](휴지통 확인 창) 버튼은 작성자에게만 보여준다 (→ [specs/004-visibility-permission](../004-visibility-permission/spec.md), [specs/006-manage-delete](../006-manage-delete/spec.md)).
- **FR-039**: 작성자가 보는 상태별 화면: 전체 공개 발행 글은 독자와 같음 + 작성자 버튼. 비공개 발행 글은 독자와 같은 모습 + 🔒 표시 + "나만 볼 수 있는 글이에요". 수정 중인 글은 **마지막 발행본** + "수정 중인 내용이 있어요(10월 3일 14:03 저장) [이어서 수정] [변경 취소]". 임시글은 에디터로 이동. 관리자 숨김 글은 "운영 정책에 따라 숨겨진 글이에요. 다른 사람에게는 보이지 않아요" 안내(사유 표시는 → [specs/014-report-hide](../014-report-hide/spec.md)). 휴지통 글은 404.
- **FR-040**: 독자는 글이 수정 중이어도 항상 마지막 발행본을 본다 (C-POST-3).

**조회 기록 (40 R-7·R-8, §4)**

- **FR-041**: 상세를 여는 것만으로는 조회수를 세지 않는다. 글이 화면에 보이는 상태로 1초가 지나면 화면이 별도로 한 번 조회 기록을 요청한다. 작성자 본인이 보는 상세에는 조회 기록 기능을 넣지 않는다(서버도 한 번 더 제외). 스크립트가 꺼진 독자는 세지 않는다. 조회 기록 실패는 상세에 영향을 주지 않는다. 화면의 조회수는 저장된 값을 그대로 보여준다(이번 방문의 +1을 기다리지 않음). 제외·중복 판정은 → [specs/009-like-view](../009-like-view/spec.md) (31 W-3·W-4).

**캐시·링크 미리보기·검색 엔진 (40 R-9·R-10, §5, 2026-10-07 H7)**

- **FR-042**: 상세 응답은 보는 사람마다 내용(좋아요 여부, 작성자 버튼 등)이 다르므로 공유 캐시에 저장되지 않게 하고, `PUBLIC`이 아닌 글의 응답은 어디에도 저장되지 않게 한다 (40 R-9, 06 R-5).
- **FR-043**: 화면은 클라이언트에서 그리더라도, 글 상세와 블로그 주소에 대해서는 서버가 링크 미리보기 정보와 404 상태 코드를 첫 응답에 넣어 준다 (2026-10-07 H7, 02 §6).
- **FR-044**: 공개 글의 링크 미리보기·검색 엔진 정보: 페이지 제목 "{제목} - {닉네임}", 설명은 요약 앞 160자, 정규 주소, 글 종류(article), 미리보기 제목·설명, 대표 이미지는 첫 사진의 **원본**(없으면 서비스 기본 이미지), 공개 시각은 최초 공개 일자, 수정 시각은 재발행 일자(있을 때만). 제목·요약은 속성 값으로 안전하게 이스케이프한다 (40 §5).
- **FR-045**: 비공개·임시·볼 수 없는 글은 공통 문구("볼 수 없는 글이에요" / "친구 공개·비공개 글이거나 삭제된 글입니다.")와 검색 엔진 수집 금지 표시만 내보낸다. 작성자 본인이 보는 비공개 글도 수집 금지다 (06 §3-1, 40 R-10).

### Key Entities *(include if feature involves data)*

- **글 카드**: 목록 한 칸에 보이는 글 요약. 글 번호·주소, 제목, 요약(최대 200자), 썸네일 주소, 최초 공개 일자, 댓글 수, 좋아요 수, 작성자(블로그 주소, 닉네임, 프로필 사진). 본문은 포함하지 않는다.
- **이어 보기 위치**: 마지막 카드의 정렬 값(최초 공개 일자[마이크로초], 글 번호)과 형식 버전을 담은 불투명 값. 목록 종류마다 정렬 값이 다를 수 있다.
- **개인 블로그 머리말**: 블로그 주소, 닉네임, 소개, 프로필 사진, 보는 사람 기준 공개 글 수.
- **글 상세 보기**: 제목, 정화된 본문, 작성자 정보, 표시 날짜·재발행 일자, 태그(입력 순서), 좋아요 수·내가 눌렀는지, 조회수, 작성자 카드(소개·내가 팔로우 중인지), 댓글 첫 20개·댓글 수, 작성자에게만 상태(임시/비공개/수정 중/숨김)와 작업본 저장 일자.
- **링크 미리보기 정보**: 공개 글은 제목·요약·대표 이미지·정규 주소·공개/수정 시각, 그 밖은 공통 문구 + 수집 금지.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 글 1만 건 기준으로 목록과 상세의 서버 응답이 300ms 이내다 (02 §6).
- **SC-002**: 목록 한 번을 불러오는 데 드는 데이터 조회 횟수가 카드 수에 비례하지 않는다(카드 9개든 1개든 같다). 목록 조회는 본문 전체를 읽지 않는다 (C-READ-1 #6).
- **SC-003**: 보는 도중 새 글 발행·삭제·비공개 전환이 일어나도 [더 보기]로 이어 본 목록에서 중복되거나 빠진 글이 0건이다.
- **SC-004**: [더 보기]를 눌렀을 때 빈 결과를 받는 경우가 0건이다.
- **SC-005**: 카드 9장의 썸네일 전송량이 약 0.4MB로, 원본을 쓸 때(약 3.6MB)보다 약 1/9이다 (10 L-8).
- **SC-006**: 375px 폭에서 페이지 가로 스크롤이 생기는 화면이 0개다.
- **SC-007**: 상세를 연 것만으로 조회수가 바뀌는 경우가 0건이고, 작성자 본인의 상세에 조회 기록 기능이 포함되는 경우가 0건이다.
- **SC-008**: 작성자 본인의 블로그 페이지에 비공개·숨긴 글이 나오는 경우가 0건이다.
- **SC-009**: 볼 수 없는 글과 존재하지 않는 글의 상세 응답(상태 코드·본문·미리보기 문구)이 구별되는 경우가 0건이다.
- **SC-010**: 뒤로 가기로 30분 안에 돌아온 경우 카드 목록과 스크롤 위치가 100% 복원된다.
- **SC-011**: 목록 카드의 날짜와 같은 글 상세의 날짜가 다른 경우가 0건이다(공개 글 기준).

## Assumptions

- C-READ-1·C-READ-2·C-BLOG-1은 Tier A 공통 필수다. 페이지 크기(9개)·뒤로 가기 보관 시간(30분) 같은 수치는 설정값으로 둘 수 있고 기본값은 원문을 따른다.
- 공통 화면 규칙은 "무엇을 보여 주는가"(카드 정보, 9개 + [더 보기], 날짜 형식, 로딩·빈 목록·오류·404 상태와 문구, 대체글)이고, "어떻게 보이는가"(색·글꼴·레이아웃·카드 배치 개수·썸네일 비율·빈 썸네일 색)는 각자 자유다 (2026-10-07 O5). 원문의 16:9·`#F1F3F5`·3/2/1개 배치는 예시다.
- 읽기 판정·노출 조건·404 정책은 → [specs/004-visibility-permission](../004-visibility-permission/spec.md), 본문 렌더링·요약 생성·카드 썸네일 지정은 → [specs/002-post-authoring](../002-post-authoring/spec.md), 썸네일 생성·GIF 재생은 → [specs/003-image-upload](../003-image-upload/spec.md), 휴지통·내 글 관리는 → [specs/006-manage-delete](../006-manage-delete/spec.md), 댓글·태그·좋아요/조회수·팔로우·신고는 각각 → specs/007·008·009·010·014가 맡는다. 이 스펙은 그것들이 목록·상세 화면에 붙는 자리와 화면 규칙을 맡는다.
- 개인 확장은 공통 화면에 "추가"만 한다: 나민서 카테고리 사이드바·페이지 번호·고정 글, 제목 위 카테고리 경로, 관련 글·이전/다음 글, 오른쪽 사이드바, 김민서 시리즈 탭 (10 §5, 40 §2). `FRIENDS` 친구 블로그 목록은 선택 구현이다.
- 40은 원문 상태가 "초안 (항목 확인 중)"이며 어떤 항목이 확인 중인지 적혀 있지 않다. 이 스펙은 40 본문과 이후 2026-10-07 회의 결정을 기준으로 썼다.
- 원문 간 충돌과 처리 (최근 결정 우선):
  - 40 §2·§7 #6은 [좋아요]·[신고]를 회원에게만 보이게 했으나, 2026-10-07 H6이 비회원·인증 전 회원에게도 보이고 누르면 안내하도록 바꿨다(01 결정 기록에 "40 §2·§7 #6 수정"으로 명시) → H6을 따른다 (→ 004 FR-045).
  - 40 §2·§7 #11은 "댓글 첫 20개를 상세 HTML에 포함(SSR)"이라 적었으나, 2026-10-07 H7로 화면은 클라이언트 렌더링 + 서버 API가 되었고 서버가 첫 응답에 넣는 것은 링크 미리보기 정보와 404 상태 코드로 정해졌다 → 이 스펙은 "상세를 열면 첫 20개가 바로 보인다"는 사용자 결과만 요구하고, 전달 방식은 계획에서 정한다.
  - 40 §2는 작성자 사진을 회원 테이블의 프로필 사진 주소 컬럼에서 읽지만, 이 컬럼은 2026-10-07에 삭제되었다 → 목록과 같이 사진 기록에서 가져온다 (51, 10 §2).
  - 40 R-8의 "조회 기록에서 관리자 제외"는 31에 추가 "요청" 상태이고 31에는 반영되지 않았다 → → [specs/009-like-view](../009-like-view/spec.md)에서 정한다.

## Implementation Notes (for /speckit-plan)

- **목록 API** ([10 §4-2](../../docs/10-post-list.md)): `GET /api/posts?cursor={cursor}&size=9`(홈), `GET /api/members/{handle}/posts?cursor={cursor}&size=9`(블로그). 응답 `{ items: [{ id, url, title, excerpt, thumbnailUrl, firstPublicAt, commentCount, likeCount, author: { handle, nickname, profileImageUrl } }], nextCursor }`. `size`는 서버가 9로 고정, 10개를 조회해 10개면 9개 + `nextCursor`, 아니면 `nextCursor: null`.
- **커서** ([10 §4-2](../../docs/10-post-list.md), [02 §5-1](../../docs/02-architecture.md) O8): JSON `{"v":1,"k":[epoch 마이크로초(UTC), id]}`를 패딩 없는 Base64URL로. 서버가 풀어 `WHERE (first_public_at, id) < (:t, :id)`. 잘못된 커서 `400 INVALID_CURSOR`(오류 본문 `{ code, message, errors, details }`). 다른 목록은 `k`에 그 정렬 키, 필요한 값은 `s`·`snap` 같은 필드 추가, 형식 변경 시 `v` 증가. `FRIENDS` 친구 블로그는 `k = (published_at, id)`.
- **목록 SQL** ([10 §7](../../docs/10-post-list.md)): 한 번의 쿼리 — `post p JOIN member m ON m.id = p.author_id LEFT JOIN image pi ON pi.uploader_id = m.id AND pi.purpose = 'PROFILE' AND pi.status = 'ATTACHED' AND pi.detached_at IS NULL`, `WHERE p.status = 'PUBLISHED' AND p.visibility = 'PUBLIC' AND p.deleted_at IS NULL AND p.hidden_at IS NULL AND m.withdrawn_at IS NULL AND (p.first_public_at, p.id) < (:t, :id) ORDER BY p.first_public_at DESC, p.id DESC LIMIT 10`. 프로필 사진 키는 `COALESCE(pi.thumb_storage_key, pi.storage_key)` → 앱이 `blog.image.public-base-url` + 키로 주소 생성(03 E-21, `uq_image_profile_current`). `content_md`·`content_html`은 읽지 않음. 인덱스 `ix_post_feed`·`ix_post_blog`(06 R-2b). 블로그는 `author_id` 조건 추가.
- **카드 컬럼** ([51 post](../../docs/51-erd-unified.md)): `post.excerpt`(VARCHAR(200)), `post.thumbnail_url`, `post.first_public_at`, `post.comment_count`, `post.like_count`(모두 미리 저장된 값), `member.handle`·`nickname`. 썸네일 키 `image.thumb_storage_key`(`{uuid}_thumb.webp`), NULL이면 원본. 카드 썸네일 `loading="lazy"`, `alt`=제목, 비율 예 `aspect-ratio: 16 / 9; object-fit: cover`, 미리보기 `line-clamp: 3` + `min-height`, 날짜 `<time datetime="…">`.
- **뒤로 가기** (10 L-6): `sessionStorage`에 카드 목록·`nextCursor`·스크롤 위치 30분.
- **상세 처리** ([40 §3](../../docs/40-post-detail.md)): `GET /@{handle}/posts/{id}` — 대문자 handle 301(08 §6) → id 숫자 아니면 404 → 글 + 작성자 JOIN 조회 → `PostAccessPolicy.canRead`(42 §3) → handle 불일치 301 → 작성자 임시글 `302 → /write/{id}` → 200. `<link rel="canonical">`에는 쿼리 문자열 제외, `?comment={id}`만 댓글 영역(21 §6 `around`)에 전달. 알림 링크 형식 `/@주소/posts/{글}?comment={id}#comment-{id}`.
- **상세 데이터** ([40 §2·§6](../../docs/40-post-detail.md)): 쿼리 최대 5번(글+작성자, 태그 `post_tag` → `tag.name` `position` 순, 내가 좋아요 눌렀는지 `EXISTS`, 내가 팔로우 중인지, 작성자일 때 `post_draft` 유무) + 댓글 첫 20개(21 §6, 21 CM-3). `content_md`는 읽지 않고 `content_html`만. 태그 링크 `/tags/{인코딩된 이름}`. 작성자 사진은 목록과 같은 `image` JOIN(40 §2의 `member.profile_image_url`은 삭제된 컬럼).
- **조회 기록** ([40 §4](../../docs/40-post-detail.md), [31 §4-1](../../docs/31-view-count.md)): `/js/post-view.js`(`<script src defer>`, 글 ID·CSRF 토큰은 `data-` 속성) → 1초 뒤 `POST /api/posts/{id}/views`(항상 204). 작성자 본인 상세에는 스크립트를 넣지 않음.
- **GIF·코드 강조**: `/js/gif-play.js`와 ▶ CSS 포함(23 §5-2), highlight.js는 코드 블록이 있을 때만(12 §7-2). CSP `script-src 'self'`.
- **캐시** (40 R-9, 06 R-5): 모든 상세 `Cache-Control: private, no-cache`, `PUBLIC`이 아니면 `private, no-store`.
- **메타 태그** ([40 §5](../../docs/40-post-detail.md)): `<title>{제목} - {닉네임}</title>`, `<meta name="description" content="{excerpt 앞 160자}">`, `<link rel="canonical" href="https://{도메인}/@{handle}/posts/{id}">`, `og:type=article`, `og:title`, `og:description`, `og:image`(첫 이미지 원본, 없으면 서비스 기본), `article:published_time={first_public_at}`, `article:modified_time={edited_at}`(있을 때만). 볼 수 없는 글은 06 §3-1 공통 OG + `<meta name="robots" content="noindex">`. React 화면이어도 상세·블로그 주소는 서버가 메타와 404 상태 코드를 넣음(H7).
- **성능 기준** ([02 §6](../../docs/02-architecture.md)): 목록·상세 서버 응답 300ms 이내(글 1만 건), N+1 없음.
