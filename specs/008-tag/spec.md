## User Scenarios & Testing *(mandatory)*

### User Story 1 - 발행할 때 태그 붙이기 (Priority: P1)

작성자는 발행 설정 창에서 태그를 입력한다. 같은 뜻의 입력(`Spring Boot`, `#spring-boot`, 전각 문자)은 같은 태그 하나가 되고, 입력한 순서대로 붙는다. 규칙에 어긋난 태그가 있으면 발행되지 않고 문제가 있는 태그를 모두 한 번에 알려 준다.

**Why this priority**: 공통 Tier B C-TAG-1의 핵심이다. 정규화 규칙이 흔들리면 같은 주제가 여러 태그로 갈라지고, 검색·AI 추천도 같은 규칙을 쓰므로 가장 먼저 확정되어야 한다.

**Independent Test**: 22 §2-1의 예시 입력을 모두 넣어 발행하고 결과 태그와 오류를 확인한다. 같은 새 태그로 10건을 동시에 발행해 태그가 하나만 생기는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행 설정 창, **When** `Spring Boot`, `spring-boot`, `#SPRING  BOOT`, `ｓｐｒｉｎｇ ｂｏｏｔ`를 입력하면, **Then** 모두 `spring-boot` 하나가 된다 (C-TAG-1 #1)
2. **Given** `C#`, `C++`, `Node.JS`, `.NET`, `스프링  부트`, **When** 입력하면, **Then** 각각 `c#`, `c++`, `node.js`, `.net`, `스프링-부트`가 된다
3. **Given** 태그 입력칸, **When** `Spring Boot`를 쓰고 Enter(또는 쉼표)를 누르면, **Then** 띄어쓰기에서 나뉘지 않고 정규화한 모양 `#spring-boot` 칩이 바로 보인다
4. **Given** `🔥hot`, `a/b`, `ㅋㅋ`, `...`, 31자 태그, 금칙어가 든 태그가 섞인 입력, **When** 발행하면, **Then** 발행되지 않고 문제가 있는 태그 모두가 각각의 이유와 함께 표시되며, 금칙어 태그는 어떤 단어 때문인지 알려 주지 않는다 (C-TAG-1 #2)
5. **Given** 중복을 지운 뒤 11개인 태그, **When** 발행하면, **Then** "태그가 너무 많다"는 이유로 발행되지 않는다 (C-TAG-1 #2)
6. **Given** `Spring`, `spring`, `jpa`를 이 순서로 입력, **When** 발행하면, **Then** `spring`, `jpa` 두 개가 이 순서로 붙는다 (C-TAG-1 #3)
7. **Given** 발행한 글을 다시 발행하려고 발행 설정 창을 열면, **Then** 지금 달린 태그가 순서대로 미리 채워져 있다
8. **Given** 같은 새 태그로 10건이 동시에 발행되면, **Then** 그 태그는 하나만 생긴다 (C-TAG-1 #8)
9. **Given** 발행된 글, **When** 태그만 바꿔 다시 발행하면, **Then** 글에 "수정됨"이 붙는다 (05 P-2)

### User Story 2 - 태그별 글 목록 보기 (Priority: P1)

독자는 태그를 눌러 `/tags/{이름}`에서 그 태그가 붙은 공개 글을 홈과 같은 카드·순서로 본다. 비공개 글에만 쓰인 태그와 아무도 쓰지 않은 태그는 똑같이 "아직 이 태그로 공개된 글이 없어요"로 보인다.

**Why this priority**: C-TAG-1 "태그별 글 목록"이자 공개 범위 노출 규칙(C-POST-4)이 직접 걸리는 화면이다.

**Independent Test**: 공개·비공개·임시·휴지통·숨김·탈퇴 신청 작성자의 글에 같은 태그를 붙이고, 비회원으로 태그 페이지를 열어 공개 글만 보이는지 확인한다. 허용 문자로 된 태그 주소를 모두 왕복시킨다.

**Acceptance Scenarios**:

1. **Given** 공개 글 12개에 붙은 `spring-boot`, **When** `/tags/spring-boot`를 열면, **Then** 머리말 "#spring-boot · 공개 글 12"와 함께 최초 공개 시각 최신순 9개 카드가 보이고 [더 보기]로 이어진다
2. **Given** 같은 태그가 붙은 비공개·임시·휴지통·관리자 숨김·탈퇴 신청 작성자의 글, **Then** 태그 목록과 공개 글 수 어디에도 나오지 않는다 (C-TAG-1 #4)
3. **Given** 비공개 글에만 쓰인 태그와 아무도 쓰지 않은 태그, **When** 각 태그 페이지를 열면, **Then** 두 응답이 똑같이 "아직 이 태그로 공개된 글이 없어요"다 (C-TAG-1 #5)
4. **Given** `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그, **When** 글 상세의 태그 링크를 누르면, **Then** 모두 해당 태그 페이지가 정상으로 열린다 (C-TAG-1 #6)
5. **Given** 정규화되지 않은 주소 `/tags/Spring%20Boot`, **When** 열면, **Then** `/tags/spring-boot`로 영구 이동한다 (C-TAG-1 #7)
6. **Given** 형식에 맞지 않는 이름(예: 이모지), **When** 태그 주소를 열면, **Then** 찾을 수 없음(404)이다
7. **Given** 검색창, **When** `#spring`처럼 `#`으로 시작하는 한 단어를 검색하면, **Then** `/tags/spring`으로 이동한다. `# spring`, `#`만, 정규화에 실패하는 입력은 보통 검색이 된다 (22 T-11)

### User Story 3 - 작성 중 태그 자동완성 (Priority: P2)

로그인한 작성자가 태그를 입력하면 내가 쓴 태그와 공개 글에 쓰인 태그가 앞부분 일치로 제안된다. 남의 비공개 글에만 쓰인 태그는 제안되지 않는다.

**Why this priority**: 같은 태그를 다시 쓰게 해 태그가 갈라지는 것을 줄이지만, 없더라도 태그 입력과 발행은 된다.

**Independent Test**: 다른 회원이 비공개 글에만 `이직준비` 태그를 쓴 상태에서 `이직`을 입력해 제안되지 않는지, 내 비공개 글의 태그는 제안되는지, 비회원 요청은 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 글에 `spring-boot`, 공개 글에 `spring`(30개)이 쓰인 상태, **When** `spr`를 입력하고 0.3초 멈추면, **Then** 내 태그가 먼저, 그다음 공개 글 수 많은 순으로 최대 10개가 제안된다
2. **Given** 남의 비공개 글에만 쓰인 `이직준비`, **When** `이직`을 입력하면, **Then** 제안되지 않는다 (22 T-9, C-TAG-1 #5)
3. **Given** 비회원, **When** 자동완성을 요청하면, **Then** 로그인 필요(401)다. 이메일 인증 전 회원은 쓸 수 있다 (2026-10-07 결정)
4. **Given** 한글 조합 중, **Then** 자동완성을 부르지 않는다
5. **Given** 후보가 없거나 요청이 실패·제한됨, **Then** 목록을 띄우지 않고 입력을 막지 않으며, Enter로 입력한 이름이 그대로 새 태그가 된다

---

### User Story 4 - 전체 태그 목록 보기 (Priority: P2)

독자는 `/tags`에서 공개 글에 많이 쓰인 태그 상위 100개를 본다.

**Why this priority**: 탐색 보조 화면이다. 태그별 목록(US2)이 있으면 없어도 핵심 가치는 유지된다.

**Independent Test**: 공개 글 수가 다른 태그 여러 개와 비공개 글에만 쓰인 태그를 만들고 `/tags`의 순서·포함 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 태그, **When** `/tags`를 열면, **Then** 공개 글 수 많은 순(같으면 이름 순)으로 상위 100개가 `#이름 글 수`로 보인다
2. **Given** 공개 글 수가 0인 태그(비공개 글에만 쓰였거나 글이 모두 지워짐), **Then** 목록에 나오지 않는다
3. **Given** 공개 글에 쓰인 태그가 하나도 없음, **Then** "아직 태그가 없어요"가 보인다

---

### User Story 5 - 블로그 안에서 태그로 거르기 (Priority: P3)

독자는 한 사람의 블로그 위쪽에 그 블로그의 태그와 글 수를 보고, 태그를 눌러 그 블로그의 해당 태그 글만 본다.

**Why this priority**: 개인 블로그 탐색 편의 기능이다. 블로그 페이지(→ specs/005-post-reading) 위에 덧붙는다.

**Independent Test**: 태그가 다른 공개 글 여러 개와 비공개 글이 있는 블로그를 열어 태그 줄의 순서·글 수와 `?tag=` 필터 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 블로그 페이지, **Then** 그 블로그 글에 쓰인 태그와 글 수가 글 수 많은 순으로 처음 10개 + [태그 더 보기]로 보인다
2. **Given** 태그 줄에서 `#jpa`를 누르면, **Then** "#jpa 글 5개 [필터 해제]"와 함께 그 태그의 글만 블로그 목록과 같은 카드·9개·[더 보기]로 보인다
3. **Given** 정규화되지 않은 필터 값 `?tag=JPA`, **Then** 정규화된 주소 `?tag=jpa`로 영구 이동한다
4. **Given** 그 블로그의 비공개 글에만 쓰인 태그, **Then** 블로그 태그 줄에 나오지 않는다 (공통 기준)

---

### Edge Cases

- 맨 앞 `#`은 여러 개여도 모두 지운다(`##jpa` → `jpa`). 뒤의 `#`은 남는다(`c#`)
- 맨 앞 `.`은 허용한다(`.net`). `.`·`..`·`-`만으로 된 이름은 한글·영문·숫자가 없어 태그가 될 수 없으므로 주소 경로 문제가 생기지 않는다 (22 §5-1)
- 자음·모음만 있는 입력(`ㅋㅋ`, `ㅅㅂ`)은 완성된 한글이 아니라 거부한다
- 허용되지 않는 문자(이모지, `/`, `@`)는 몰래 지우지 않고 거부한다 — 조용히 지우면 의도하지 않은 태그가 생긴다 (22 T-4)
- 자동완성 검색어를 정리한 결과가 비면 빈 목록을 돌려준다. 자동완성 검색어에는 금칙어 검사를 하지 않는다
- 자동완성 응답이 늦게 도착해 더 최근 입력의 응답보다 나중에 오면 버린다
- 발행하지 않고 발행 설정 창을 닫으면 입력한 태그는 그 브라우저에만 남고 서버에는 저장되지 않는다 (04 결정 3)
- 태그를 쓰던 글이 모두 지워져도 태그 자체는 남는다. 공개 글 수가 0이면 목록·자동완성에 보이지 않는다 (13 §2-5)
- 친구 공개(`FRIENDS`) 규격을 적용한 사람이라도 태그별 목록·전체 태그 목록에는 전체 공개 글만 나온다. 블로그 안 태그 줄은 블로그 목록과 같은 조건이라 친구가 볼 때는 친구 공개 글도 포함한다 (22 §5·§8)
- `#`이 든 태그는 주소에서 반드시 인코딩(`%23`)되어야 한다. 그대로 쓰면 브라우저가 주소의 조각으로 읽는다

## Requirements *(mandatory)*

### Functional Requirements

**정규화 (공용 규칙)**

- **FR-001**: 시스템은 모든 태그 입력 — 발행, 자동완성 검색어, 태그 주소, 블로그 태그 필터, 검색어 속 태그, AI 추천 결과 — 에 하나의 같은 정규화 규칙을 적용해야 한다 (22 §2, T-11)
- **FR-002**: 정규화는 다음 순서여야 한다: ① 호환 문자 정리(NFKC, 전각 → 반각) ② 보이지 않는 글자·방향 제어 문자·제어 문자 제거 ③ 앞뒤 공백 제거 ④ 맨 앞의 `#`을 모두 지우고 다시 앞뒤 공백 제거 ⑤ 언어 설정과 무관한 소문자화 ⑥ 공백 묶음을 `-` 하나로 ⑦ 연달아 있는 `-`를 하나로, 처음·끝의 `-` 제거 ⑧ 형식 검사 ⑨ 금칙어 검사 (22 §2)
- **FR-003**: 태그는 완성된 한글·영문 소문자·숫자와 기호 `-` `_` `.` `+` `#`만 쓸 수 있고, 한글·영문·숫자가 1자 이상 있어야 하며, 1~30자(유니코드 코드 포인트)여야 한다 (22 T-1)
- **FR-004**: 띄어쓰기는 하이픈으로 바꾸어야 한다 (`spring boot` → `spring-boot`) (22 T-2)
- **FR-005**: 맨 앞의 `#`은 지우고 뒤의 `#`은 남겨야 한다 (22 T-3)
- **FR-006**: 허용되지 않는 문자가 있으면 지우지 않고 `INVALID_TAG`로 거부해야 한다 (22 T-4)
- **FR-007**: 시스템은 닉네임과 같은 금칙어 필터(숫자 제거·숫자→영문 치환 등 변형 포함)를 태그에 적용하고, 걸리면 `TAG_BANNED_WORD`로 거부하되 어떤 단어인지는 알려 주지 않아야 한다 (22 T-5, 09 §4)
- **FR-008**: 30자를 넘으면 `TAG_TOO_LONG`으로 거부해야 한다 (22 §2-1)
- **FR-009**: 정규화는 22 §2-1 예시 표의 입력·결과·오류를 모두 그대로 만족해야 한다 (C-TAG-1 #1)

**한 글의 태그**

- **FR-010**: 한 글의 태그 목록에서 정규화한 뒤 같은 이름은 처음 나온 것만 남겨야 한다 (22 §2-2, C-TAG-1)
- **FR-011**: 태그는 입력한(중복 제거 후 남은) 순서를 저장하고 그 순서로 보여야 한다 (22 T-6, C-TAG-1 #3)
- **FR-012**: 한 글의 태그는 중복을 지운 뒤 0~10개여야 하고, 최대 개수는 설정값으로 바꿀 수 있어야 한다(기본 10). 넘으면 `TOO_MANY_TAGS`로 거부한다 (05 P-5, 22 §2-2)
- **FR-013**: 태그 검증에 실패하면 글을 발행하지 않고, 문제가 있는 태그를 모두 한 번에 각 태그의 위치와 이유와 함께 알려 주어야 한다 (22 §2-2, 05 §4, C-TAG-1 #2)
- **FR-014**: 태그는 발행할 때만 확정되어야 한다. 자동 저장 대상이 아니며, 발행하지 않고 닫으면 입력한 태그는 그 브라우저에만 남는다 (04 §6-2 결정 3, 22 §3)
- **FR-015**: 발행할 때 그 글의 태그를 입력한 목록으로 통째로 바꾸어야 한다. 같은 새 태그로 동시에 발행해도 태그는 하나만 생긴다 (22 §4, C-TAG-1 #8)
- **FR-016**: 태그만 바꿔도 다시 발행으로 취급해 "수정됨"을 남겨야 한다 → specs/002-post-authoring (05 P-2, 22 §3)
- **FR-017**: 태그를 쓰는 글이 하나도 없게 되어도 태그 자체는 지우지 않아야 한다. 공개 글 수가 0인 태그는 목록·자동완성에 보이지 않는다 (13 §2-5, 22 §4)
- **FR-018**: 태그를 붙이는 권한은 발행 권한과 같아야 한다 (비회원 401, 이메일 인증 전 403, 남의 글 404) → specs/004-visibility-permission (42 §10-2·§5-2)

**입력 화면 (발행 설정 창)**

- **FR-019**: 태그는 공개 범위를 고르는 발행 설정 창에서 입력해야 한다 (22 T-7)
- **FR-020**: 입력 화면은 다음을 제공해야 한다: Enter 또는 쉼표로 하나 추가(띄어쓰기로 나누지 않음), 입력 즉시 정규화한 모양을 칩으로 미리 보여 주기(안내용이며 서버가 다시 검사), 칩의 × 또는 빈 입력칸에서 Backspace로 삭제, 끌어서 순서 바꾸기와 키보드로 순서 바꾸기(칩에 초점 + Alt + 방향키), "2 / 10" 개수 표시, 다시 발행할 때 지금 태그를 순서대로 미리 채우기, 오류 칩은 색과 글자로 함께 표시(색만으로 구분하지 않음) (22 §3)

**태그별 글 목록**

- **FR-021**: 시스템은 태그별 글 목록 페이지를 제공해야 한다. 카드·9개·[더 보기]·정렬(최초 공개 시각 최신순, 같으면 번호 큰 순)은 전체 글 목록과 같다 → specs/005-post-reading (22 §5, 10)
- **FR-022**: 태그별 목록과 그 공개 글 수에는 발행·전체 공개이고 휴지통·관리자 숨김·작성자 탈퇴 신청에 해당하지 않는 글만 포함해야 한다. 친구 공개를 적용한 사람이라도 전체 공개 글만이다 (22 §5, 06 §3·R-2a, 2026-10-07 H1, C-TAG-1 #4)
- **FR-023**: 태그 페이지 주소는 태그 이름을 경로 조각으로 퍼센트 인코딩해 만들고(`#` → `%23`, 한글 인코딩, `+`·`.`은 그대로), 허용 문자로 된 모든 태그가 주소로 왕복되어야 한다 (22 §5·§5-1, C-TAG-1 #6)
- **FR-024**: 정규화되지 않은 태그 주소는 정규화된 주소로 영구 이동(301)해야 한다 (22 §5, C-TAG-1 #7)
- **FR-025**: 형식에 맞지 않는 이름의 태그 주소는 찾을 수 없음(404)이어야 한다 (22 §5)
- **FR-026**: 형식에 맞지만 공개 글이 없는 태그(아무도 안 쓴 태그, 비공개 글에만 쓰인 태그)는 정상 응답과 "아직 이 태그로 공개된 글이 없어요"를 보여야 하고, 두 경우의 응답이 같아야 한다 (22 T-10, 06 V-5, C-TAG-1 #5)
- **FR-027**: [더 보기] 불러오는 중에는 버튼을 "불러오는 중…"으로 비활성화하고, 실패하면 "불러오지 못했어요 [다시 시도]"를 보여야 한다 (22 §5, 10 §4-4)

**전체 태그 목록**

- **FR-028**: 시스템은 전체 태그 목록을 제공해야 한다: FR-022와 같은 조건의 공개 글 수 많은 순(같으면 이름 순) 상위 100개, 공개 글 수 0인 태그 제외, 하나도 없으면 "아직 태그가 없어요" (22 §6)
- **FR-029**: 전체 태그 목록은 10분마다 다시 계산한 결과를 보여 줄 수 있다 [NEEDS CLARIFICATION: 10분 재계산(22 §6)이면 어떤 글이 비공개·휴지통·숨김이 된 뒤 최대 10분 동안 그 글의 태그·글 수가 전체 목록에 남아, C-TAG-1 #5("비공개 글에만 쓰인 태그는 남의 전체 목록에 나오지 않는다")와 06 §8 #2("공개가 아닌 글은 글 수에 세지 않는다")를 잠시 어긴다 — 이 지연을 허용하는지, 공개 범위 변경·삭제·숨김 때 즉시 다시 계산해야 하는지] (22 §6)
- **FR-030**: 기간 기준 인기 태그("최근 많이 쓰인 태그")는 이 기능에 포함하지 않는다 → specs/012-trending-search (22 §6)

**자동완성**

- **FR-031**: 자동완성은 로그인한 회원만 쓸 수 있어야 한다. 비회원은 401 `LOGIN_REQUIRED`, 이메일 인증 전 회원은 허용한다 (22 §7, 2026-10-07 "태그 자동완성" 결정 — 42 §10-2 비회원 칸 수정)
- **FR-032**: 자동완성 검색어도 FR-002 정규화(금칙어 검사 제외)를 거친 뒤 태그 이름 앞부분 일치로 찾아야 한다. 정리 결과가 비면 빈 목록이다 (22 §7)
- **FR-033**: 자동완성 후보는 ① 내가 쓴 태그(내 글 전부, 공개 범위 무관) ② 공개 글 수가 1 이상인 태그만이어야 한다. 남의 비공개 글에만 쓰인 태그는 나오지 않는다 (22 T-9, C-TAG-1 #5)
- **FR-034**: 후보는 내 태그를 먼저, 그다음 공개 글 수 많은 순으로 최대 10개를 보여 주고, 각 후보에 공개 글 수와 내 태그 여부를 담아야 한다 (22 §7)
- **FR-035**: 화면은 입력이 0.3초 멈출 때만 자동완성을 부르고, 한글 조합 중에는 부르지 않으며, 늦게 온 이전 요청의 응답은 버려야 한다. 불러오는 중에는 아무것도 띄우지 않는다 (22 §7)
- **FR-036**: 자동완성은 회원당 1분에 60번으로 제한해야 한다. 후보 없음·실패·제한 초과는 목록을 띄우지 않고 태그 입력을 막지 않으며, 입력한 이름은 Enter로 그대로 새 태그가 된다 (22 §7)

**블로그 안 태그 필터**

- **FR-037**: 개인 블로그 페이지는 그 블로그 글에 쓰인 태그와 글 수를 글 수 많은 순으로 처음 10개 보여 주고 [태그 더 보기]를 제공해야 한다. 대상 글은 블로그 목록과 같은 조건이다(공통은 전체 공개 글만, 친구 공개 적용자는 친구가 볼 때 친구 공개 글 포함) (22 §8, 06 R-2)
- **FR-038**: 블로그 태그 필터는 그 태그의 글만 블로그 목록과 같은 카드·9개·[더 보기]로 보여 주고 "#이름 글 N개 [필터 해제]"를 표시해야 한다. 정규화되지 않은 필터 값은 정규화된 주소로 영구 이동한다 (22 §8)

**다른 화면과의 연결**

- **FR-039**: 글 상세에는 태그를 입력 순서대로 `#이름`으로 보여 주고, 누르면 그 태그 페이지로 이동해야 한다. 표시 위치는 → specs/005-post-reading. 목록 카드에는 태그를 보여 주지 않는다 (22 §9, 40 §2, 10 §7)
- **FR-040**: 검색어 전체가 `#`으로 시작하는 한 단어이고 정규화를 통과하면 검색 대신 그 태그 페이지로 이동해야 한다. `#` 뒤 띄어쓰기, `#`만, 정규화 실패는 보통 검색이다 → specs/012-trending-search (22 T-11)
- **FR-041**: AI 태그 추천 결과도 같은 정규화를 거쳐야 하고, 실패한 추천은 조용히 버리며, 이미 붙은 태그는 빼고, 남은 자리(최대 개수 − 현재 개수)만큼만 제안한다 → specs/013-ai-tag-suggest (22 §13)

### Key Entities *(include if feature involves data)*

- **태그**: 정규화된 이름(유일, 1~30자), 처음 쓰인 시각. 쓰는 글이 없어져도 남는다
- **글-태그 연결**: 글과 태그의 다대다 연결, 글 안에서의 입력 순서(0부터, 한 글 안에서 중복 없음). 글이 완전히 지워지면 함께 지워진다
- **공개 글 수**: 태그별로 "발행·전체 공개·휴지통 아님·숨김 아님·작성자 탈퇴 신청 아님"인 글의 수. 태그 페이지 머리말·전체 태그 목록·자동완성 정렬에 쓴다
- **태그 정규화 규칙**: 발행·자동완성·주소·검색·AI 추천이 함께 쓰는 하나의 규칙 (FR-002)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 22 §2-1 예시 입력 전체가 기대한 태그 또는 오류와 100% 일치한다
- **SC-002**: `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그 주소가 실제 보안 설정을 거쳐 100% 정상으로 열린다
- **SC-003**: 같은 새 태그로 동시에 10건을 발행해도 그 태그는 정확히 1개다
- **SC-004**: 권한 매트릭스 테스트에서 태그별 목록·전체 태그 목록·자동완성·태그 글 수에 비공개·임시·휴지통·관리자 숨김·탈퇴 신청 작성자의 글이 0건 나온다
- **SC-005**: 비공개 글에만 쓰인 태그의 페이지 응답과 아무도 쓰지 않은 태그의 페이지 응답이 구별되지 않는다 (차이 0)
- **SC-006**: 태그 검증에 실패한 발행 한 번으로 문제가 있는 태그 전부를 확인할 수 있다 (고치고 다시 발행할 때마다 새 오류가 하나씩 드러나는 경우 0)
- **SC-007**: 태그별 목록은 글 1만 건 기준 0.3초 안에 응답한다 (02 §6)
- **SC-008**: 자동완성이 실패하거나 제한되어도 태그 입력과 발행이 막히는 경우가 0건이다

## Assumptions

- 이 기능은 공통 Tier B(C-TAG-1)이며 공통 ERD의 다대다 설계 비교 포인트다
- 태그 최대 개수는 설정값이다. 공통 기본 10개, 강성찬은 5개로 쓸 수 있다 (01 §1·§3 원칙 7, 05 P-5)
- 05 §4의 태그 검증(소문자·공백 제거·중복 제거·1~30자)을 22가 구체화했다(허용 문자·NFKC·공백 → `-`·금칙어 추가, `TAG_TOO_LONG`·`TAG_BANNED_WORD` 추가). 기존 결정 변경이 아니라 구체화로 본다 (22 §13)
- 자동완성 비회원 권한은 2026-10-07 회의에서 401로 통일되었으므로 42 §10-2의 "비회원: 공개 글의 태그" 칸보다 우선한다
- 22 §5·§6의 목록 조건에는 관리자 숨김 제외가 빠져 있으나, 2026-10-07 회의 H1 공용 조건(삭제·숨김·탈퇴 제외)을 따른다
- [태그 더 보기]가 몇 개를 더 보여 주는지는 원문에 없다. 나머지 태그를 펼친다고 보고 구체 방식은 plan에서 정한다
- 이미 쓰이고 있는 태그 이름이 나중에 금칙어 목록에 추가되는 경우의 처리는 원문에 없으며 이 spec 범위 밖이다
- 의존: 금칙어 필터(→ specs/001-account-auth, 09 §4), 발행 흐름·"수정됨"(→ specs/002-post-authoring), 공용 공개 조건·권한(→ specs/004-visibility-permission), 목록 카드·커서·블로그 페이지·글 상세(→ specs/005-post-reading), 완전 삭제 시 연결 삭제(→ specs/006-manage-delete), 검색·트렌딩(→ specs/012-trending-search), AI 태그 추천(Tier C, → specs/013-ai-tag-suggest)

## Implementation Notes (for /speckit-plan)

원문의 기술 결정을 요약한다. 위 본문에는 넣지 않은 내용이다.

- **정규화 클래스** ([22 §2](../../docs/22-tag.md)): `TagNormalizer.normalize(raw)` → 이름 또는 `TagRejectedException(code)`. `ALLOWED = [가-힣a-z0-9._+#-]{1,30}`, `HAS_WORD = [가-힣a-z0-9]`, NFKC, `Locale.ROOT` 소문자(터키어 i 문제), 보이지 않는 문자 목록은 12 §7-4, 금칙어는 09 §4-2 변형 4가지. 발행·자동완성·태그 주소·검색(33)·AI 추천(34)이 같은 클래스를 쓴다
- **테이블** ([51 §2·§3 tag·post_tag](../../docs/51-erd-unified.md)): `tag(id, name varchar(30) UNIQUE, created_at)`, `ck_tag_name CHECK (name ~ '^[가-힣a-z0-9._+#-]{1,30}$' AND name ~ '[가-힣a-z0-9]')`, `ix_tag_name_prefix (name varchar_pattern_ops)`(collation이 `C`가 아니어도 `LIKE 'spr%'`가 인덱스를 탐). `post_tag(post_id, tag_id, position smallint)` PK `(post_id, tag_id)`, `uq_post_tag_position (post_id, position)`, `ck_post_tag_position (0~99)`, `fk_post_tag_post … CASCADE`, `fk_post_tag_tag … RESTRICT`, `ix_post_tag_tag (tag_id, post_id)`
- **저장** ([22 §4](../../docs/22-tag.md), 05 §7 ①·⑤): 검증은 트랜잭션 밖. 발행 트랜잭션에서 `INSERT INTO tag … ON CONFLICT (name) DO NOTHING` → id 조회 → `DELETE FROM post_tag WHERE post_id = …` → 순서대로 `INSERT`. 태그 전용 이벤트 없음(검색 색인은 `PostEdited`·`PostWentPublic`)
- **설정값**: `blog.post.max-tags`(기본 10)
- **API** ([22 §5~§8](../../docs/22-tag.md)): `GET /api/tags/{name}/posts?cursor=…`(10 §4-2 응답 형식), `GET /api/tags?limit=100` → `[{ name, postCount }]`, `GET /api/tags/suggest?q=…` → `[{ name, postCount, mine }]`, `GET /api/members/{handle}/tags`, `GET /api/members/{handle}/posts?tag=…&cursor=…`
- **목록 쿼리**: 22 §5·§6 SQL 대신 06 R-2의 `VisibilityFilter` 공용 조건(`status = 'PUBLISHED' AND visibility = 'PUBLIC' AND deleted_at IS NULL AND hidden_at IS NULL AND 작성자 withdrawn_at IS NULL`)을 쓴다(H1). 원문 SQL의 `m.profile_image_url`은 2026-10-07 결정으로 삭제된 컬럼이라 `image` JOIN(`purpose = PROFILE`, `status = ATTACHED`, `detached_at IS NULL`)으로 바꾼다. 커서 `(first_public_at, id)`, 10개 조회해 9개 반환. 태그 하나의 공개 글이 수천 개를 넘으면 `post_tag`에 `first_public_at` 복사 컬럼 검토(1만 건 기준에서는 불필요)
- **캐시**: 전체 태그 목록 Redis `tags:top` TTL 10분, 캐시가 없으면 바로 계산 (FR-029 NEEDS CLARIFICATION 참고)
- **자동완성**: 앞부분 일치 `LIKE 'q%'`, 사용자당 1분 60번(Redis), 비회원 401 `LOGIN_REQUIRED`
- **주소·라우팅** ([22 §5-1](../../docs/22-tag.md)): `UriUtils.encodePathSegment`로 링크 생성, Spring 6은 경로 끝 확장자 잘라내기가 없어 `node.js` 그대로 받음, Spring Security `StrictHttpFirewall`이 `%23`·`%2B`·한글 인코딩을 통과하는지 MockMvc + 실제 Security 필터로 테스트. 정규화 안 된 주소는 301
- **검색창 `#태그`**: 검색 Controller가 `q`를 보고 `302 /tags/{인코딩된 이름}`, SPA는 검색창이 같은 규칙으로 바로 이동 (22 §13)
- **오류 형식**: 원문 22 §2-2의 오류 항목 `{ field: "tags[2]", code, value }`는 2026-10-07 O8 공통 형식 `{ code, message, errors: [{ field, code, message }], details }`에 맞춘다(필드는 `tags[2]`처럼 위치 표시)
- **화면 이벤트**: 자동완성 호출은 입력 0.3초 정지 후, `compositionstart`~`compositionend` 동안 호출 안 함, 요청 번호로 늦은 응답 폐기
