## Clarifications

### Session 2026-10-08

- Q: 비공개·친구 공개 글도 외부 AI로 보낼까? → A: 보내지 않는다. 그 글에 저장된 공개 범위가 `PRIVATE`·`FRIENDS`면 늘 자체 AI(Ollama)로만 추천하고, 자체 AI가 없거나 바쁘면 추천하지 않는다. 동의 문구에 "비공개·친구 공개 글은 외부로 보내지 않아요"를 더한다 (FR-007·FR-030) (민서 확정 2026-10-08)
- Q: AI 동의 문구가 바뀌면 다시 동의를 언제 받을까? → A: AI 버튼을 누를 때 처음 동의와 같은 창을 다시 띄운다. 로그인 재동의 화면은 약관·처리방침만 본다 (FR-009) (민서 확정 2026-10-08)
- Q: 자체 AI(Ollama)를 배포 환경에 어떻게 둘까? → A: 앱과 같은 Docker Compose에 넣는다. 배포 서버 메모리(2~4GB 추가)는 배포 담당이 확인한다 (FR-017~FR-021, Assumptions) (민서 확정 2026-10-08)
- Q: AI를 불렀는데 실패한 요청도 하루 20회에 셀까? → A: 세지 않는다. AI가 답을 돌려준 요청만 센다(검사에서 다 걸러져 0개여도 셈). 시간 초과·형식 오류·한도 초과·자체 AI 혼잡은 세지 않는다 (FR-023·FR-027) (민서 확정 2026-10-08)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버튼을 눌러 태그 추천을 받고 골라서 붙이기 (Priority: P1)

글 작성자가 에디터에서 [AI 태그 추천]을 누르면, 지금 쓰고 있는 제목과 본문을 바탕으로 태그가 최대 5개 추천된다. 작성자는 원하는 추천을 눌러야만 태그에 추가할 수 있다. AI가 실패해도 글쓰기·자동 저장·발행은 그대로 된다.

**Why this priority**: 세 팀원 문서 공통 원칙("AI는 제안만 한다, 실패해도 발행 성공")을 그대로 담은 핵심 흐름이다(01 §2-3, 01 §3 원칙 5). 이 흐름만 있어도 가치가 전달된다.

**Independent Test**: 동의를 마친 이메일 인증 회원이 100자 이상 쓴 자기 글에서 버튼을 눌러 추천이 오고, 추천을 누르기 전에는 태그가 바뀌지 않으며, AI를 일부러 실패시켜도 저장·발행이 성공하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그 `spring`을 이미 붙인 글, **When** [AI 태그 추천]을 누르면, **Then** `spring`을 뺀 추천이 최대 5개(글당 태그 상한에서 남은 자리만큼) 보이고, 아직 태그 목록은 바뀌지 않는다 (34 완료 기준 1).
2. **Given** 추천 `jpa`가 보일 때, **When** `(+ jpa)`를 누르면, **Then** 그때 `jpa`가 태그에 추가된다 (A-4).
3. **Given** 정리 후 본문이 100자 미만인 글, **When** 버튼을 누르면, **Then** AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"가 보인다.
4. **Given** 모든 AI 공급자가 실패할 때, **When** 버튼을 누르면, **Then** "지금은 추천할 수 없어요"만 보이고, 이어서 자동 저장·수동 저장·발행이 정상 동작한다 (34 완료 기준 6).
5. **Given** AI가 `JPA`, `N+1 문제`, 금칙어, 이미 붙인 태그를 돌려줄 때, **When** 결과를 보여주면, **Then** 태그 규칙으로 정규화되고 금칙어·규칙 위반·이미 붙인 태그는 빠진다. 남는 것이 없으면 "추천할 태그를 찾지 못했어요"가 보인다 (34 완료 기준 5).
6. **Given** 남의 글이거나 이메일 인증 전 회원일 때, **When** 추천을 요청하면, **Then** 남의 글은 없는 글과 같은 응답을, 인증 전 회원은 이메일 인증 안내를 받는다 (→ specs/004-visibility-permission, C-OWN-1, C-AUTH-1).

### User Story 2 - 처음 쓸 때 외부 전송에 동의하기 (Priority: P1)

작성자가 처음으로 [AI 태그 추천]을 누르면, 글 제목과 본문 앞부분이 외부 AI 서비스(Google Gemini 무료 등급)로 전송되고 Google이 이를 서비스 개선에 쓰거나 사람이 검토할 수 있다는 안내와 함께 동의를 묻는다. 동의하지 않으면 아무것도 전송되지 않는다.

**Why this priority**: 개인정보·기밀 노출 위험이 있는 외부 전송의 전제 조건이라 추천 기능과 같은 P1이다(A-11).

**Independent Test**: 동의 기록이 없는 회원으로 버튼을 눌러 동의 창이 뜨고, [취소] 시 외부·자체 AI 어디로도 요청이 나가지 않는지, [동의하고 추천받기] 시 동의가 기록되고 추천이 진행되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** AI 동의 기록이 없는 회원, **When** 버튼을 누르면, **Then** 34 §7-2의 동의 문구가 보이고 추천은 진행되지 않는다 (34 완료 기준 2).
2. **Given** 동의 창이 열려 있을 때, **When** [취소]를 누르면, **Then** 글 내용이 어디에도 전송되지 않는다.
3. **Given** 동의 창이 열려 있을 때, **When** [동의하고 추천받기]를 누르면, **Then** 동의 시각과 동의 문구 버전이 기록되고 추천이 진행된다.
4. **Given** 동의한 회원, **When** 설정 화면에서 AI 동의를 취소하면, **Then** 다음에 버튼을 누를 때 다시 동의를 묻는다.

### User Story 3 - 같은 내용 반복 요청은 다시 묻지 않기 (Priority: P2)

작성자가 같은 글에서 버튼을 여러 번 누르거나, 태그 하나를 붙인 뒤 다시 누르거나, 오타 몇 개만 고친 뒤 다시 누르면 AI를 다시 부르지 않고 저장해 둔 추천으로 바로 답한다. 이때는 하루 사용 횟수가 줄지 않는다. [다시 추천]을 누르면 새로 묻는다.

**Why this priority**: 외부 무료 한도와 자체 AI 자원이 작아 재사용이 필수(A-8)지만, 추천 자체(P1)가 먼저 있어야 한다.

**Independent Test**: 같은 글에서 ① 그대로 다시 누름 ② 태그 하나 붙이고 누름 ③ 오타 2개 고치고 누름 ④ 문단 절반을 바꾸고 누름을 차례로 해, ①~③은 AI 호출 0번·횟수 차감 없음, ④만 호출 1번인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 정리된 내용으로 이미 추천을 받았을 때, **When** 다시 누르면, **Then** AI를 부르지 않고 저장된 추천으로 답하며 오늘 남은 횟수가 그대로다 (34 완료 기준 4).
2. **Given** 추천 중 하나를 태그로 붙였을 때, **When** 다시 누르면, **Then** AI를 부르지 않고 저장된 추천에서 붙인 태그만 뺀 결과가 보인다.
3. **Given** 같은 글에서 오타 2개만 고쳤을 때(거의 같은 내용), **When** 다시 누르면, **Then** 저장된 추천을 재사용한다.
4. **Given** 거의 같은 내용으로 재사용이 일어나는 상황, **When** [다시 추천]을 누르면, **Then** 거의 같은 내용 재사용을 건너뛰고 새로 추천을 받는다.

---

### User Story 4 - 외부 한도가 다 되면 자체 AI로 이어서 추천 (Priority: P2)

외부 AI의 무료 한도가 다 되거나 한도 초과 응답이 오면, 같은 요청이 곧바로 우리 서버의 AI로 처리되고 한도가 초기화될 때까지 자체 AI를 쓴다. 자체 AI는 느리므로 "자체 AI로 추천 중이라 조금 걸려요"를 보여준다.

**Why this priority**: 무료 등급 한도가 작고 수시로 줄어서(34 §3-1) 전환이 없으면 기능이 자주 멈춘다. 다만 사용자가 보는 흐름은 US1과 같다.

**Independent Test**: 외부 공급자의 오늘 호출 수를 설정 한도까지 채우거나 한도 초과 응답을 흉내 내, 같은 요청이 자체 AI로 처리되고 이후 요청도 초기화 시각까지 자체 AI로 가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 외부 AI가 하루 한도 초과 응답을 줄 때, **When** 추천을 요청하면, **Then** 같은 요청이 바로 자체 AI로 처리되고, 다음 한도 초기화 시각까지 모든 요청이 자체 AI로 간다 (34 완료 기준 3).
2. **Given** 오늘 외부 호출 수가 설정한 하루 한도에 이르렀을 때, **When** 추천을 요청하면, **Then** 한도 초과 응답을 받기 전에 자체 AI로 전환된다.
3. **Given** 외부 AI가 10초 안에 답하지 않을 때, **When** 추천을 요청하면, **Then** 그 요청은 "지금은 추천할 수 없어요"로 끝나고, 이후 60초 동안의 요청은 자체 AI로 간다.
4. **Given** 자체 AI가 이미 최대 동시 처리 수만큼 일하고 있을 때, **When** 추천을 요청하면, **Then** "잠시 후 다시 시도해 주세요"가 보인다.

---

### Edge Cases

- 개인 하루 20회를 넘으면 추천이 거부되고 한도 안내가 보인다. 저장된 추천으로 답한 요청은 횟수에 들어가지 않는다.
- 외부 AI가 분당 한도 초과를 알리면 60초 동안 자체 AI로 보낸다. 한도 종류를 알 수 없는 초과 응답은 60초 중단으로 다루되 같은 날 3번 연속이면 하루 소진으로 본다.
- AI 응답 형식이 깨졌으면 실패로 처리하고 저장하지 않는다. 실패·빈 결과·검증에서 모두 걸러진 결과는 재사용 저장소에 남기지 않는다.
- [다시 추천]을 눌렀는데 저장된 "완전히 같은 내용" 결과가 자체 AI가 만든 것이고 지금 외부 AI를 쓸 수 있으면, 외부 AI로 다시 만든다.
- 다른 사람이 같은 글을 복사해 올려 정리된 내용이 완전히 같으면, 사용자와 상관없이 저장된 추천이 재사용된다. 저장소에는 내용이 아니라 내용의 해시만 열쇠로 남는다.
- 글이 아주 길면 외부 AI에는 앞 8,000자, 자체 AI에는 앞 2,000자만 보내고, 화면에 "본문 앞부분을 보고 추천했어요"를 보여준다.
- 기능 스위치가 꺼져 있으면 버튼이 보이지 않고, 요청이 와도 사용할 수 없음 응답을 준다.
- 캐시·횟수 저장소가 멈추면 AI 추천은 사용할 수 없음으로 응답하고, 글쓰기는 영향을 받지 않는다 (02 §2-1 H8).
- 비공개·친구 공개 글로 추천을 요청하면 자체 AI로만 처리하고, 자체 AI를 쓸 수 없으면 추천하지 않는다 (FR-030).

## Requirements *(mandatory)*

### Functional Requirements

**범위·호출 (A-1~A-4)**

- **FR-001**: System MUST AI 기능 범위를 **태그 추천만**으로 한정해야 한다 (A-1).
- **FR-002**: System MUST 사용자가 [AI 태그 추천] 또는 [다시 추천] 버튼을 누를 때만 추천을 요청해야 하며, 입력·저장·발행 중 자동으로 요청하지 않아야 한다 (A-2, 34 완료 기준 1).
- **FR-003**: System MUST 추천을 최대 5개, 글당 태그 상한(기본 10개, → specs/008-tag)에서 이미 붙인 태그를 뺀 남은 자리만큼만 보여주어야 한다 (A-4).
- **FR-004**: System MUST 추천을 사용자가 하나씩 눌렀을 때만 태그에 추가하고, 태그는 기존 규칙대로 발행할 때 확정되어야 한다 (A-4, → specs/002-post-authoring).
- **FR-005**: System MUST 추천을 그 글의 작성자 본인에게만 허용해야 한다. 남의 글이면 없는 글과 같은 응답(404), 이메일 인증 전 회원이면 인증 안내(403), 비회원이면 로그인 필요 응답을 준다 (42 §3·§4, 02 §5, C-OWN-1, C-AUTH-1).
- **FR-006**: System MUST 기능 스위치를 두어, 꺼진 경우 버튼을 숨기고 요청에는 사용할 수 없음 응답을 주어야 한다 (A-10, 34 §9).

**동의·개인정보 (A-11, 34 §7)**

- **FR-007**: System MUST 회원이 처음 추천을 요청할 때 다음 내용을 담은 동의 창을 보여주고, 동의하기 전에는 글 내용을 어떤 AI에도 보내지 않아야 한다: 제목과 본문 앞부분이 Google Gemini(무료 등급)로 전송된다는 것, Google이 이를 서비스 개선에 사용하고 사람이 검토할 수 있다는 것, 외부 AI를 쓸 수 없을 때는 자체 서버 AI로 처리하며 그때는 외부로 전송되지 않는다는 것, 비공개·친구 공개 글은 외부로 보내지 않고 자체 서버 AI로만 추천한다는 것, 개인정보·비밀번호·회사 기밀이 들어간 글에는 쓰지 말라는 것 (34 §7-2, 34 완료 기준 2, Clarifications 2026-10-08).
- **FR-008**: System MUST 동의하면 동의 시각과 동의 문구 버전을 회원별로 기록해야 한다 (34 §7-2, 51 `member_agreement` AI, 2026-10-07 회의 E2).
- **FR-009**: System MUST 기록된 AI 동의 문구 버전이 현재 버전과 다르면 다시 동의를 받아야 한다. 다시 묻는 시점은 회원이 [AI 태그 추천]을 누를 때이며, 처음 동의할 때와 같은 창을 띄운다. 로그인 때의 재동의 차단(001)은 이용약관·개인정보 처리방침만 대상으로 하고 AI 동의는 넣지 않는다 (34 §7-2, Clarifications 2026-10-08)
- **FR-010**: Users MUST be able to 설정 화면에서 AI 동의를 취소할 수 있어야 하며, 취소 후에는 동의하지 않은 상태와 같아야 한다 (34 §7-2, 51: 철회 = 동의 기록 삭제).
- **FR-011**: System MUST 개인정보 처리방침에 "외부 AI 서비스(Google Gemini)로의 전송"과 무료 등급의 데이터 사용 방식을 적어야 한다 (34 §7-2).
- **FR-012**: System MUST AI에 해당 글의 제목·정리된 본문, 인기 태그 목록, 이미 붙인 태그(제외 지시용)만 보내고, 다른 사람의 글과 이메일·닉네임 등 회원 정보는 보내지 않아야 한다 (A-3, 34 §7-2).

**입력 정리 (34 §4)**

- **FR-013**: System MUST AI에 보내기 전에 본문을 정리해야 한다: 제목·강조·목록·인용 기호 제거, 이미지 문법은 통째로 제거, 링크는 글자만 남기고 주소 제거, 코드 블록은 언어 이름과 앞 5줄만 남김, 연속 공백·줄바꿈은 하나로, 유니코드 정규화(NFC), 대소문자는 바꾸지 않음 (34 §4 ①~④).
- **FR-014**: System MUST 정리된 입력을 공급자별 최대 길이(외부 AI 8,000자, 자체 AI 2,000자, 설정값)로 잘라야 하고, 잘린 경우 화면에 "본문 앞부분을 보고 추천했어요 · AI 제안이에요"를 보여주어야 한다 (A-3, 34 §4 ⑤, 34 §9).
- **FR-015**: System MUST 정리 후 100자 미만이면 AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"를 보여주어야 한다 (34 §4 ⑥).
- **FR-016**: System MUST AI에게 글에 나오지 않는 기술은 넣지 말고 태그 배열로만 답하라고 지시하고, 기존 표기를 재사용하도록 인기 태그(외부 AI: 상위 50개, 자체 AI: 상위 50개 중 글에 실제로 나오는 것만, 하루 1번 갱신)를 함께 제공해야 한다 (34 §4, §8-3).

**공급자 전환·시간 제한 (A-6, A-9, 34 §3)**

- **FR-017**: System MUST 기본으로 외부 AI(무료 등급)를 쓰고, 다음 경우 자체 서버 AI로 자동 전환해야 한다: 우리가 센 오늘 외부 호출 수가 설정 한도(실제 하루 한도보다 조금 낮게)에 이름, 하루 한도 초과 응답(다음 한도 초기화 시각까지), 분당 한도 초과 응답(60초), 종류를 모르는 한도 초과 응답(60초, 같은 날 3번 연속이면 하루 소진으로) (34 §3-2, 34 완료 기준 3).
- **FR-018**: System MUST 한도 초과 응답을 받은 요청은 같은 요청을 바로 자체 AI로 처리해야 한다 (34 §3-2).
- **FR-019**: System MUST 외부 AI가 시간 초과·서버 오류이면 이후 60초 동안 자체 AI로 보내되, 그 요청 자체는 실패로 답해야 한다 (이미 10초가 지나 자체 AI까지 기다리게 하지 않음) (34 §3-2).
- **FR-020**: System MUST 외부 AI는 10초, 자체 AI는 30초 시간 제한을 두고, 자체 AI로 처리할 때 "자체 AI로 추천 중이라 조금 걸려요"를 보여주어야 한다 (A-9, 34 §3-3).
- **FR-021**: System MUST 자체 AI의 동시 처리 수를 설정값(기본 1)으로 제한하고, 넘으면 "잠시 후 다시 시도해 주세요"로 답해야 한다 (34 §3-2).
- **FR-022**: System MUST 하루 한도·모델 이름 같은 공급자 수치를 코드에 고정하지 않고 설정값으로 두어야 한다 (34 §3-1, 01 §3 원칙 7).

**사용 한도·재사용 (A-7, A-8, 34 §5)**

- **FR-023**: System MUST 회원당 하루 20회까지 AI 호출을 허용하고, 넘으면 하루 한도 안내로 거부하며, 화면에 오늘 남은 횟수를 보여주어야 한다. 횟수는 AI가 답을 돌려준 요청만 세고 실패한 요청은 세지 않는다 (A-7, 34 §9, Clarifications 2026-10-08).
- **FR-024**: System MUST 정리된 입력이 완전히 같으면(프롬프트 형식 버전도 같을 때) 사용자와 관계없이 저장된 추천을 30일 동안 재사용해야 한다 (34 §5-1 ①).
- **FR-025**: System MUST 같은 글에서 지난번 정리된 입력과 지금 입력이 거의 같으면(3글자 단위 유사도 0.9 이상) 저장된 추천을 7일 동안 재사용해야 한다. 글당 하나만 보관한다 (34 §5-1 ②).
- **FR-026**: System MUST 재사용 판정에 이미 붙인 태그와 인기 태그 목록을 넣지 않고, 응답할 때마다 이미 붙인 태그를 빼고 남은 자리만큼만 보여주어야 한다 (34 §5-1).
- **FR-027**: System MUST 저장된 추천으로 답한 요청은 하루 횟수에서 빼지 않고, 저장된 추천으로 답했음을 응답에 표시해야 한다 (A-7, 34 완료 기준 4).
- **FR-028**: System MUST [다시 추천] 때 "거의 같은 내용" 재사용을 건너뛰고, "완전히 같은 내용" 결과는 쓰되 그 결과가 자체 AI가 만든 것이고 지금 외부 AI를 쓸 수 있으면 외부 AI로 다시 만들어야 한다 (34 §5-1).
- **FR-029**: System MUST 실패·빈 결과·검증에서 모두 걸러진 결과는 재사용 대상으로 저장하지 않아야 한다 (34 §5-1, §6).

**응답 검증·실패 (A-5, 34 §6)**

- **FR-030**: System MUST 그 글에 저장된 공개 범위가 비공개(`PRIVATE`)·친구 공개(`FRIENDS`)인 글의 추천 요청은 외부 AI 상태와 상관없이 자체 AI로만 처리해야 한다(본문 앞 2,000자). 자체 AI가 꺼져 있거나 동시 처리 수를 넘으면 외부 AI로 넘기지 않고 "지금은 추천할 수 없어요" 또는 "잠시 후 다시 시도해 주세요"로 답한다. 판단 기준은 요청 시점에 저장된 글의 공개 범위다(임시글도 처음부터 값이 있다, 002 FR-001) (34 후속 제안 F-1, Clarifications 2026-10-08).
- **FR-031**: System MUST 두 공급자 모두에 출력 형식(태그 목록, 최대 5개)을 강제하고, 형식이 깨진 응답은 실패로 처리해야 한다 (A-5, 34 §6).
- **FR-032**: System MUST AI가 돌려준 태그를 태그 정규화 규칙(→ specs/008-tag, C-TAG-1)으로 정리하고, 이미 붙인 태그·금칙어(→ specs/001-account-auth 닉네임 금칙어 필터)·규칙에 맞지 않는 태그를 빼야 한다. 남는 것이 없으면 "추천할 태그를 찾지 못했어요"를 보여준다 (34 §6, 34 완료 기준 5).
- **FR-033**: System MUST 어느 공급자든 실패하면 "지금은 추천할 수 없어요"만 보여주고, 글쓰기·자동 저장·발행에는 영향을 주지 않아야 한다 (A-9, 34 완료 기준 6, 01 §3 원칙 5).
- **FR-034**: System MUST 외부 AI 접속 비밀값은 실행 환경에서만 주입하고, 비밀값과 글 내용을 운영 기록에 남기지 않아야 한다 (34 완료 기준 7).
- **FR-035**: System MUST 회원 탈퇴 익명 처리 시 AI 동의 기록은 다른 동의 기록과 같은 규칙을 따라야 한다 (→ specs/015-withdraw).

### Key Entities *(include if feature involves data)*

- **AI 동의 기록**: 회원별 AI 전송 동의 여부, 동의한 문구 버전, 동의 시각. 이용약관·개인정보 동의와 같은 "회원 동의" 묶음의 한 종류. 철회하면 사라진다.
- **추천 재사용 항목 (같은 내용)**: 정리된 입력의 해시 + 프롬프트 형식 버전 → 추천 태그 목록(이미 붙인 태그를 빼기 전). 30일 보관, 사용자 간 공유.
- **추천 재사용 항목 (같은 글의 비슷한 내용)**: 글별 지난번 정리된 입력(최대 8,000자), 추천, 만든 공급자, 시각. 글당 1개, 7일 보관.
- **공급자 상태**: 오늘 외부 AI 호출 수, 하루 한도 소진 표시(다음 초기화까지), 일시 중단 표시(60초), 자체 AI 동시 처리 수.
- **개인 일일 사용 횟수**: 회원별 오늘 AI 호출 횟수(상한 20).
- **인기 태그 목록**: 공개 글 기준 상위 50개, 하루 1번 갱신 (→ specs/008-tag).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 동의하지 않은 회원의 요청으로 외부·자체 AI에 전송된 글이 0건이다.
- **SC-002**: AI 공급자를 모두 실패시킨 상태에서도 자동 저장·수동 저장·발행 성공률이 AI가 정상일 때와 같다 (100%).
- **SC-003**: 사용자가 추천을 누르지 않은 상태에서 글의 태그가 바뀐 경우가 0건이다.
- **SC-004**: 같은 글에서 같은 내용으로 반복 요청하거나, 태그 하나를 붙이거나, 오타 몇 개만 고친 뒤 요청하면 AI 호출 0번·하루 횟수 차감 0회다.
- **SC-005**: 외부 AI 한도가 소진된 뒤의 추천 요청이 사용자 쪽에서 실패 없이(자체 AI 여유가 있을 때) 처리된다.
- **SC-006**: 자체 AI로 처리할 때 2,000자 입력의 추천이 30초 시간 제한 안에 끝난다 (참고 측정: 5.6~6.9초, 34 §8-2 — 배포 서버에서 다시 잰다).
- **SC-007**: 추천 결과에 금칙어·규칙 위반 태그·이미 붙인 태그가 포함된 경우가 0건이다.
- **SC-008**: 운영 기록에서 외부 AI 비밀값이나 글 내용이 발견되는 경우가 0건이다.

## Assumptions

- **Tier C 기능이다** (01 §2-3 "AI 태그 추천", 강 P2 / 나 MUST / 김 3차). 셋 다 "제안만, 실패해도 발행 성공"이 공통 원칙이다.
- **개인 확장(범위 밖)**: 주제 추천(나 AI-06, 같은 라우터·재사용 저장소를 쓰는 개인 확장), 제목·요약(김 AI-1), 임베딩·관련 글·티저 (A-1).
- 태그 정규화·글당 상한·인기 태그 상위 50개 산출은 specs/008-tag, 금칙어 필터는 닉네임 금칙어(09 §4, → specs/001-account-auth), 작성자·인증 판정은 specs/004-visibility-permission을 따른다.
- 동의 저장은 34 원문의 "회원에 동의 시각 하나"가 아니라 2026-10-07 회의 E2·H9로 확정된 "회원 동의(종류 AI) + 버전" 구조를 따른다. 철회는 동의 기록 삭제다 (51 §4).
- 개인 하루 20회는 AI가 답을 돌려준 요청만 센다(검사에서 모두 걸러져 0개가 되어도 셈). 저장된 추천으로 답한 요청, 100자 미만으로 AI를 부르지 않은 요청, 시간 초과·형식 오류·한도 초과·자체 AI 혼잡으로 실패한 요청은 세지 않는다 (Clarifications 2026-10-08). "하루"의 경계는 서비스 기준 시간(한국 시간 0시)으로 본다 — 외부 AI 호출 수의 날짜는 공급자 한도 초기화 기준 시간대로 따로 센다(구현 시 확인, 34 §3-2).
- 외부 AI 모델 이름·하루 한도(기본 450)는 공급자 화면에 보이는 값에 맞춰 설정으로 조정하며, 2026년 중 여러 번 줄었다는 점을 전제로 한다 (34 §3-1).
- 자체 AI(Ollama)는 앱과 같은 Docker Compose에 넣어 함께 띄운다(Clarifications 2026-10-08). 배포 서버 메모리(약 2~4GB 추가), 외부 AI 키 관리 주체, 처리방침 문구는 팀(배포)이 확인한다 (34 "맞출 것").
- 자체 AI 성능 수치는 개발용 노트북 측정값이며 배포 서버에서 다시 잰다 (34 §8).
- 다른 사용자와 "완전히 같은 내용" 추천을 공유하는 것은 원문이 의도한 동작이다 (34 §5-1).

## Implementation Notes (for /speckit-plan)

- 구조: [34 §2](../../docs/34-ai-tag-suggest.md) — `TagSuggestService` → `TagSuggesterRouter` → `GeminiTagSuggester` / `OllamaTagSuggester` / `DisabledTagSuggester` (`TagSuggester` 인터페이스 `List<String> suggest(TagSuggestInput)`).
- 설정값: [34 §2](../../docs/34-ai-tag-suggest.md) `blog.ai.tag-suggest.*` — `enabled`, `prompt-version`(올리면 캐시 키가 바뀜), `gemini.model`(예 `gemini-flash-lite`), `gemini.daily-limit=450`, `gemini.timeout=10s`, `gemini.max-input-chars=8000`, `ollama.base-url`, `ollama.model=qwen2.5:1.5b`, `ollama.num-thread=4`(성능 코어 수 이하, 기본값은 약 140배 느림 §8-1), `ollama.timeout=30s`, `ollama.max-input-chars=2000`, `ollama.max-concurrency=1`. `GEMINI_API_KEY`는 환경 변수로만.
- Redis 키: [34 §3-2·§5-1](../../docs/34-ai-tag-suggest.md) — `ai:gemini:count:{날짜}`, `ai:gemini:exhausted`, `ai:gemini:cooldown`(60초), `ai:ollama:inflight`, `ai:tag:v{prompt-version}:{SHA-256(정리된 입력)}`(30일), `ai:tag:post:{postId}`(7일, 3-gram Jaccard ≥ 0.9), `ai:tag:popular:{날짜}`(하루). SimHash 방식은 짧은 글에서 실패해 기각(§5-3).
- 프롬프트: [34 §4](../../docs/34-ai-tag-suggest.md) — 고정 지시문 → 인기 태그 → 이미 붙인 태그 → 제목+본문 순(앞부분 재사용 유리), 최대 출력 토큰 100. 출력은 JSON 스키마 `{ "tags": [string] }`(Gemini 응답 스키마, Ollama `format`). Ollama는 스키마 `description`을 전달하지 않으므로 설명은 지시문에 넣는다(§6).
- API: [34 §9](../../docs/34-ai-tag-suggest.md) — `POST /api/posts/{postId}/tag-suggestions` `{ title, contentMd, currentTags, refresh }` → `{ tags, provider, cached, truncated, remainingToday }`. 오류: 409 `AI_CONSENT_REQUIRED`, 422 `CONTENT_TOO_SHORT`, 429 `AI_DAILY_LIMIT`, 503 `AI_UNAVAILABLE`(두 공급자 실패·Ollama 동시 처리 초과·기능 꺼짐·Redis 장애 [02 §2-1](../../docs/02-architecture.md) H8). 원문은 남의 글·인증 전을 모두 403으로 적었으나, 남의 글은 [02 §5](../../docs/02-architecture.md)·[42 §4](../../docs/42-permission-matrix.md)의 404 원칙을 따른다(인증 전은 403 `EMAIL_NOT_VERIFIED`).
- 동의 저장: 원문 `member.ai_consent_at`은 통합 V1에서 `member_agreement(member_id, type='AI', version, agreed_at)`으로 바뀌었다 ([51 §2·§4](../../docs/51-erd-unified.md), [07 §3-1](../../docs/07-auth.md)). 철회 = 행 삭제. 34 원문의 `ai_consent_version`(개인 확장)은 공통 `version` 컬럼으로 흡수됐다.
- 캐시·횟수·공급자 상태는 테이블 없이 Redis. 보존 데이터와 캐시의 Redis 인스턴스 분리·`maxmemory`는 아키텍처 정리 때(M30).
- 측정 근거: [34 §5-3](../../docs/34-ai-tag-suggest.md)(정리 30% 감소, 유사도 판정 표), [34 §8](../../docs/34-ai-tag-suggest.md)(Ollama 스레드·입력 길이·품질).
