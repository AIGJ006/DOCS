## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글마다 공개 범위를 고르고 바로 바꾸기 (Priority: P1)

작성자는 글마다 "전체 공개" 또는 "나만 보기"를 고른다. 발행할 때 고를 수 있고, 발행한 뒤에도 다시 발행하지 않고 즉시 바꿀 수 있다. 바꿔도 "수정됨" 표시·작업 중인 수정본·댓글·좋아요는 그대로이고, 공개를 껐다 켜도 목록 위치는 처음 공개했을 때 자리다.

**Why this priority**: C-POST-4(Tier A)의 핵심이다. "나만 보려고 쓴 글이 밖으로 새지 않는다"(06 핵심 목표)의 출발점이다.

**Independent Test**: 공개 글을 비공개로, 다시 공개로 바꾸면서 매번 다른 회원의 상세 접근 결과, 홈 목록 위치, "수정됨" 표시, 댓글·좋아요 수를 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자의 전체 공개 발행 글일 때, **When** 공개 범위를 "나만 보기"로 바꾸면, **Then** 다시 발행하지 않아도 즉시 다른 사람에게는 404가 되고, "수정됨" 표시가 생기지 않는다 (06 V-6, §8 #4).
2. **Given** 공개 → 비공개 → 공개로 바꾼 글일 때, **When** 홈 목록을 보면, **Then** 처음 공개되었던 시각의 위치에 있고 맨 위로 올라오지 않는다 (06 §8 #5).
3. **Given** 댓글·좋아요가 있는 공개 글일 때, **When** 비공개로 바꾸면, **Then** 댓글·좋아요는 지워지지 않고 다른 사람에게 함께 숨겨지며, 다시 공개하면 그대로 돌아온다 (06 V-7, §8 #6).
4. **Given** 수정 중인 작업본이 있는 발행 글일 때, **When** 공개 범위를 바꾸면, **Then** 바로 바뀌고 작업본과 편집 버전은 그대로다 (06 §4).
5. **Given** 남의 글, 없는 글, 휴지통 글일 때, **When** 공개 범위 변경을 요청하면, **Then** 404이고 글은 바뀌지 않는다 (06 §4, 13 §2-3).
6. **Given** 처음부터 비공개로 발행한 글일 때, **When** 나중에 처음으로 전체 공개로 바꾸면, **Then** 그 순간이 공개 시각이 되어 홈 목록 맨 위에 나온다 (05 P-3).

### User Story 2 - 볼 수 없는 글은 어디로도 새지 않는다 (Priority: P1)

비공개·임시·휴지통·관리자 숨김·탈퇴 신청한 작성자의 글은 다른 사람에게 존재 자체가 드러나지 않는다. 주소를 열면 없는 글과 똑같은 404 화면과 링크 미리보기 문구가 나오고, 홈·블로그·태그·검색·sitemap·글 수 어디에도 나오지 않는다.

**Why this priority**: C-POST-4·C-READ-2(Tier A) 완료 기준이며 개인 정보 유출을 막는 보안 요구다.

**Independent Test**: 비공개 글 주소와 존재하지 않는 글 주소를 비회원·다른 회원으로 열어 상태 코드·본문·미리보기 문구가 같은지 비교하고, 모든 공개 목록과 글 수에서 빠져 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비공개 발행 글일 때, **When** 작성자가 아닌 사람(관리자 포함)이 상세를 열면, **Then** 404이고 작성자만 볼 수 있다 (06 §8 #1).
2. **Given** 볼 수 없는 글과 존재하지 않는 글일 때, **When** 각각 열면, **Then** 상태 코드·본문·링크 미리보기 문구("볼 수 없는 글이에요" / "친구 공개·비공개 글이거나 삭제된 글입니다.")·검색 엔진 수집 금지 표시가 모두 같다 (06 §3-1, §8 #3).
3. **Given** 공개가 아닌 글일 때, **When** 홈·다른 사람이 보는 블로그 목록·태그 목록·검색·sitemap·블로그 글 수를 확인하면, **Then** 어디에도 나오지 않고 세지도 않는다 (06 §8 #2, C-POST-4).
4. **Given** 관리자가 숨긴 글일 때, **When** 작성자 본인이 자기 블로그 목록을 보면, **Then** 그 글은 나오지 않고, 상세는 작성자에게만 안내와 함께 보이며, 내 글 관리에서 볼 수 있다 (06 §8 #8, H1).
5. **Given** 작성자가 탈퇴를 신청한 상태일 때, **When** 누구든 그 사람의 글을 열거나 목록을 보면, **Then** 상세는 404이고 목록에서 빠진다 (06 R-2a).

### User Story 3 - 남의 글은 바꿀 수 없다 (Priority: P1)

남의 글을 수정·삭제·발행·공개 범위 변경하려는 요청은 화면에서 버튼을 숨긴 것과 상관없이 서버에서 거부되고, 글은 조금도 바뀌지 않는다. 요청에 다른 사람의 작성자 번호를 끼워 넣어도 소용없다. 관리자도 남의 글 내용은 바꿀 수 없다.

**Why this priority**: C-OWN-1(Tier A)이다. 화면 숨김만으로 막으면 주소 직접 입력·요청 조작으로 우회된다 (42 P-1).

**Independent Test**: 회원 B의 로그인으로 회원 A의 글에 대해 수정·저장·발행·공개 범위 변경·삭제 요청을 직접 보내고, 모두 404이며 요청 전후 글의 내용·상태·편집 버전·수정 일자가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 회원 B가 로그인했을 때, **When** A의 글에 수정·삭제·발행·공개 범위 변경을 요청하면, **Then** 404이고 요청 전후 글의 내용·상태·편집 버전·수정 일자가 같다 (42 §12 #1).
2. **Given** 요청에 A의 작성자 번호를 넣었을 때, **When** 서버가 처리하면, **Then** 그 값은 무시되고 결과는 1과 같다 (42 §12 #2).
3. **Given** 관리자일 때, **When** 남의 글이나 댓글을 수정·삭제하려 하면, **Then** 404이고, 관리자는 숨김·숨김 해제만 할 수 있다 (42 P-11, §12 #5).
4. **Given** 글 주인일 때, **When** 자기 글에 달린 남의 댓글을 삭제하려 하면, **Then** 404이고 댓글은 그대로다 (42 P-8, §12 #8).

### User Story 4 - 계정 상태에 맞는 일관된 거부와 안내 (Priority: P2)

비회원·이메일 인증 전 회원·탈퇴 신청 회원·정지 회원은 각자 할 수 없는 일이 정해져 있고, 어느 기능에서든 같은 순서로 판정되어 같은 상황에는 같은 응답과 해결 방법 안내를 받는다.

**Why this priority**: 기능마다 응답이 다르면 화면·테스트가 깨지고 대상의 존재가 새어 나갈 수 있다 (42 P-2·P-3). US1~US3이 있어야 의미가 있다.

**Independent Test**: 같은 비공개 글에 대해 비회원·인증 전 회원·탈퇴 신청 회원으로 쓰기 행동을 보내 각각 로그인 필요·인증 필요·탈퇴 계정 응답이 나오는지, 존재 여부와 상관없이 같은 응답인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원일 때, **When** 로그인이 필요한 행동을 요청하면, **Then** 로그인 필요 응답을 받고 화면은 로그인 화면으로 안내한 뒤 로그인 후 원래 페이지로 돌아온다 (42 §4).
2. **Given** 이메일 인증 전 회원일 때, **When** 글쓰기·댓글·사진 업로드·좋아요·신고를 요청하면, **Then** 이메일 인증 필요 응답과 "인증 메일 다시 보내기" 안내를 받는다 (42 P-5·P-6).
3. **Given** 이메일 인증 전 회원일 때, **When** 자기 글을 휴지통으로 옮기거나 복구하면, **Then** 허용된다 (42 §5-2).
4. **Given** 탈퇴 신청(유예) 회원일 때, **When** 로그인하면, **Then** 복구 화면(복구하기 / 로그아웃)만 보이고, 다른 요청은 탈퇴 계정 응답으로 거부된다 (42 P-12).
5. **Given** 관리자가 회원을 정지했을 때, **When** 정지 직후, **Then** 그 회원의 모든 기기 로그인이 즉시 끊기고, 정지 기간에는 로그인하면 "정지된 계정이에요 (~11월 1일까지). 사유: …"만 보이며, 이미 쓴 글·댓글은 그대로 보인다 (42 P-7, §12 #4-1).
6. **Given** 인증 전이면서 존재하지 않는 글에 쓰기를 요청할 때, **When** 서버가 판정하면, **Then** 대상 확인보다 계정 상태 확인이 먼저라 존재하는 글과 같은 응답을 받는다 (42 §3).

### User Story 5 - 새 글의 기본 공개 범위 (Priority: P2)

회원은 설정에서 새 글이 시작할 공개 범위(기본 "전체 공개")를 정해 둔다. [새 글]로 만든 글은 이 값으로 시작하고, 글마다 발행 설정에서 바꿀 수 있다.

**Why this priority**: 매번 공개 범위를 바꾸는 수고를 줄이지만, 없어도 US1로 글마다 바꿀 수 있다.

**Independent Test**: 기본 공개 범위를 "나만 보기"로 바꾼 뒤 [새 글]을 만들어 발행 설정의 초기값이 "나만 보기"인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 처음 가입한 회원일 때, **When** 기본 공개 범위를 확인하면, **Then** "전체 공개"다 (06 V-4).
2. **Given** 기본 공개 범위가 "나만 보기"인 회원일 때, **When** [새 글]을 만들면, **Then** 그 글의 공개 범위는 "나만 보기"로 시작하고 발행 설정에서 바꿀 수 있다 (06 §8 #7).
3. **Given** 다른 회원일 때, **When** 남의 기본 공개 범위를 바꾸려 하면, **Then** 그런 경로가 없다 (본인만 설정 화면에서 변경, 06 §5).

### User Story 6 - 화면에는 할 수 있는 행동만 보인다 (Priority: P2)

글 상세의 [수정]·[삭제]·[공개 범위]는 작성자에게만, [좋아요]·[신고]는 작성자가 아닌 사람에게 보인다. 비회원·인증 전 회원에게도 [좋아요]·[신고]·[팔로우]·댓글 입력창은 보이지만, 누르면 로그인 또는 이메일 인증 안내가 나온다.

**Why this priority**: 서버 판정(US3·US4)을 보조하는 사용성 규칙이다 (42 §11, 2026-10-07 H6).

**Independent Test**: 같은 공개 글을 작성자·다른 회원·인증 전 회원·비회원·관리자로 열어 보이는 버튼과 누른 결과를 비교한다.

**Acceptance Scenarios**:

1. **Given** 작성자가 자기 글 상세를 볼 때, **When** 화면을 보면, **Then** [수정]·[공개 범위]·[삭제]가 보이고 [좋아요]·[신고]·[팔로우]는 없으며 좋아요 수만 보인다 (42 §11, 40 §7 #13).
2. **Given** 비회원이 공개 글을 볼 때, **When** [좋아요]나 [신고]를 누르면, **Then** 로그인 안내가 나오고 로그인 후 원래 글로 돌아오며 자동으로 눌리지 않는다 (2026-10-07 H6, 30 K-2).
3. **Given** 인증 전 회원일 때, **When** 댓글 입력창을 보면, **Then** "이메일 인증 후 댓글을 쓸 수 있어요 [인증 메일 다시 보내기]"가 보인다. 비회원에게는 "로그인하고 댓글 쓰기"가 보인다 (42 §11).

### User Story 7 - 관리자 화면 주소 숨기기 (Priority: P3)

관리자 화면 주소는 비회원에게는 있는 주소든 없는 주소든 똑같이 로그인을 요구하고, 로그인한 일반 회원에게는 없는 페이지로 보인다.

**Why this priority**: 관리자 기능(Tier C 신고·숨김)의 존재를 숨기는 보조 장치다.

**Independent Test**: 비회원으로 실제 관리자 주소와 존재하지 않는 관리자 하위 주소를 열어 응답이 같은지, 일반 회원으로 열면 404인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원일 때, **When** 관리자 화면의 있는 주소와 없는 주소를 열면, **Then** 둘 다 로그인 필요 응답(로그인 화면)이다 (42 P-10, §12 #6).
2. **Given** 로그인한 일반 회원일 때, **When** 관리자 화면 주소를 열면, **Then** 404다.

### User Story 8 - (선택 구현) 친구 공개 (Priority: P3)

`FRIENDS` 규격을 적용한 사람만, 글을 "친구 공개"로 발행해 작성자와 수락된 친구만 읽게 할 수 있다. 공통 기본값은 비활성이다.

**Why this priority**: 공통 규격만 정하고 구현은 선택이다 (06 V-1, 2026-10-07 M1). 적용하는 사람끼리 규칙이 같아야 비교할 수 있다.

**Independent Test**: `FRIENDS`를 적용한 환경에서 친구 공개 글을 작성자·수락된 친구·요청 중 상대·비회원으로 열고, 친구가 보는 블로그 목록과 홈 목록을 비교한다. 적용하지 않은 환경에서는 친구 공개 지정이 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `FRIENDS`를 적용하지 않은 환경일 때, **When** 공개 범위를 "친구 공개"로 지정하면, **Then** 잘못된 공개 범위로 거부된다 (06 §4).
2. **Given** 적용 환경의 친구 공개 글일 때, **When** 수락된 친구가 열면 보이고, 비회원·친구가 아닌 회원·요청 중 상대가 열면 404이며, 홈·태그·검색·sitemap에는 나오지 않는다 (06 §3).
3. **Given** 친구 관계를 끊었을 때, **When** 상대가 그 친구 공개 글을 열면, **Then** 404이고 목록에서도 사라진다 (06 §6-2).
4. **Given** 기본 공개 범위가 친구 공개인데 친구가 없을 때, **When** 발행 설정을 열면, **Then** "아직 친구가 없어서 지금은 나만 볼 수 있어요. [친구 초대] [전체 공개로 바꾸기]"가 보인다 (06 §5).

### Edge Cases

- 같은 공개 범위 값으로 다시 변경을 요청하면 아무것도 바뀌지 않고 성공한다 (06 §4).
- 임시글의 공개 범위를 바꾸면 값만 저장되고(발행할 때 쓸 값) 노출에는 영향이 없다. 임시글은 공개 범위와 상관없이 작성자만 본다 (06 §2).
- 휴지통 글은 작성자에게도 상세가 404이고 휴지통 목록에서만 보이며, 저장·발행·공개 범위 변경은 작성자라도 404다 (42 §5-2, 13 §2-3).
- 수정 중(작업본 있음)인 글을 누가 보든 마지막 발행본이 보인다 (42 §5-1).
- 한 사람이 여러 행위자에 해당하면 판정 순서상 먼저 걸리는 쪽이 적용된다. 예: 인증 전인 작성자가 발행하면 인증 필요 응답 (42 §2).
- 정지 회원은 로그인할 수 없으므로 정지 기간에는 자기 글 삭제·프로필 수정·탈퇴도 할 수 없다. 로그인 전 기능인 비밀번호 재설정은 가능하다 (42 §5-2, §9).
- 정지된 계정에서 쓰기 요청이 서버에 도달하면 정지 계정 응답으로 거부된다 (2026-10-07 H7).
- 관리자도 자기 글에서는 작성자로 판정된다 (42 §2).
- 화면에 이미 떠 있는 글이 그 사이 비공개로 바뀌면, 다음 요청부터 404다.
- 관리자가 숨긴 글은 작성자가 다시 발행하거나 공개 범위를 바꿔도 숨김이 유지된다 (43 §4-1, → [specs/014-report-hide](../014-report-hide/spec.md)).
- 세션 저장소 장애로 로그인 정보를 읽지 못하면 비회원으로 처리되어 공개 글 읽기는 계속되고, 로그인이 필요한 요청은 로그인 필요로 응답한다 (02 §2-1).

## Requirements *(mandatory)*

### Functional Requirements

**공개 범위 값과 의미 (06 §1·§2)**

- **FR-001**: System MUST 공통 공개 범위로 `PUBLIC`(전체 공개, 비회원 포함 누구나)과 `PRIVATE`(나만 보기, 작성자만)를 제공한다. `FRIENDS`(친구 공개, 작성자 + 수락된 친구)는 공통 규격이며 선택 구현이고 기본 비활성이다. 값 이름으로 `PROTECTED`는 쓰지 않는다 (C-POST-4, 06 V-1·V-3).
- **FR-002**: 공개 범위는 발행된 글에만 의미가 있다. 임시글은 공개 범위와 상관없이 작성자만 보며, 임시글에 저장된 값은 "발행할 때 쓸 공개 범위"다 (06 §2).
- **FR-003**: 휴지통에 있는 글은 공개 범위와 상관없이 아무에게도(작성자 포함) 상세가 보이지 않고 휴지통 목록에서만 보인다 (06 §2, 13 §2-6).
- **FR-004**: 관리자가 숨긴 글은 공개 범위와 상관없이 어떤 목록에도 나오지 않는다(작성자 본인이 보는 블로그 목록 포함). 상세는 작성자 본인에게만 안내와 함께 보이고, 작성자는 내 글 관리에서도 본다 (06 §2, 43 §4-1, 2026-10-07 H1).
- **FR-005**: 운영자·관리자도 남의 `PRIVATE`(·`FRIENDS`) 글을 볼 수 없다. 신고 처리는 신고 시점 스냅샷만 본다 (06 §2, 42 P-11, → [specs/014-report-hide](../014-report-hide/spec.md)).

**노출 규칙 (06 §3)**

- **FR-006**: System MUST `PUBLIC`이 아닌 글을 홈 최신 글·인기 글, 다른 사람이 보는 개인 블로그 목록, 블로그 글 수, 태그별 목록·태그 글 수·인기 태그, 검색·AI 추천·관련 글, 피드, sitemap·RSS 어디에도 내보내지 않고 글 수에도 세지 않는다 (C-POST-4, 06 §8 #2).
- **FR-007**: 작성자 본인의 블로그 페이지에도 자기 비공개 글은 나오지 않고 내 글 관리에서만 보인다 (06 V-8).
- **FR-008**: 탈퇴를 신청한(유예 중인) 작성자의 글은 상세 404이고 모든 목록에서 빠진다 (06 R-2a, 13 §3-2).
- **FR-009**: 모든 공개 목록은 하나의 공용 노출 조건 "발행됨 + 전체 공개 + 휴지통 아님 + 숨김 아님 + 작성자가 탈퇴 신청 상태 아님"만 쓰며, 목록마다 조건을 따로 만들지 않는다. 목록 조건에는 작성자 본인 예외를 넣지 않는다 (06 R-2·R-2a·R-2b, 2026-10-07 H1).
- **FR-010**: 글 하나를 읽을 수 있는지는 한 곳에서만 판정한다. 판정은 휴지통 여부를 가장 먼저 확인하고, 작성자 본인 예외(임시·비공개·숨김 글을 볼 수 있음)는 상세 판정과 내 글 관리에만 둔다 (06 R-1·R-2a, 02 §4-2).
- **FR-011**: 댓글·좋아요를 보고 쓰는 것은 그 글을 읽을 수 있는 사람만 할 수 있다. 읽을 수 없는 글의 댓글·좋아요 요청은 404다 (06 §3).
- **FR-012**: 사진은 공개 범위와 상관없이 주소를 알면 볼 수 있다 (06 §3, 04 결정 2). 세부와 `FRIENDS` 적용 시 재검토 문제는 → [specs/003-image-upload](../003-image-upload/spec.md).

**볼 수 없을 때의 응답 (06 V-5, §3-1, R-4·R-5)**

- **FR-013**: System MUST 볼 수 없는 글(남의 비공개·임시 글, 휴지통 글, 남이 보는 숨긴 글, 탈퇴 신청 작성자의 글)과 존재하지 않는 글에 똑같은 404를 준다. 상태 코드, 본문, 링크 미리보기 문구("볼 수 없는 글이에요" / "친구 공개·비공개 글이거나 삭제된 글입니다."), 검색 엔진 수집 금지 표시가 모두 같아야 한다 (C-READ-2, 01 §3-3).
- **FR-014**: "없음"과 "권한 없음"을 구분하는 응답 내용·메시지를 사용자에게 보내지 않는다 (06 R-4).
- **FR-015**: `PUBLIC`이 아닌 글의 응답은 어디에도(브라우저·중간 캐시·CDN) 저장되지 않게 한다 (06 R-5).

**공개 범위 바꾸기 (06 §4)**

- **FR-016**: 작성자는 발행한 글의 공개 범위를 다시 발행하지 않고 즉시 바꿀 수 있어야 한다. 수정 중인 작업본이 있어도 바꿀 수 있고, 작업본과 편집 버전에는 영향이 없다.
- **FR-017**: 공개 범위를 바꿔도 "수정됨" 기준 일자(재발행 일자)는 바뀌지 않는다 (06 V-6).
- **FR-018**: 최초 공개 일자는 글이 처음으로 "발행됨 + 전체 공개"가 되는 순간에만 기록하고 이후 바뀌지 않는다. 공개 범위 변경·다시 발행 모두 같은 규칙을 따른다 (05 §3, 06 §4).
- **FR-019**: 비공개로 바꿔도 댓글·좋아요는 지우지 않고, 글을 읽을 수 없게 된 사람에게 함께 숨긴다. 다시 공개하면 돌아온다 (06 V-7).
- **FR-020**: 공개 범위 변경 요청 결과: 성공하면 바뀐 공개 범위와 최초 공개 일자를 돌려준다. 모르는 값이거나 `FRIENDS`를 적용하지 않았는데 `FRIENDS`를 보내면 잘못된 공개 범위로 거부한다. 없는 글·남의 글·휴지통 글은 404다. 같은 값이면 아무것도 바꾸지 않고 성공한다. 임시글은 값만 저장한다. 동시에 여러 요청이 와도 한 번에 하나씩 반영된다 (06 §4).
- **FR-021**: 공개 범위가 바뀌면 변경이 확정된 뒤 "공개 범위 변경" 사건(글, 이전 값, 새 값)을 알려 검색 색인·sitemap 갱신 등이 따라 붙을 수 있게 한다 (06 §4, → [specs/011-notification](../011-notification/spec.md), [specs/012-trending-search](../012-trending-search/spec.md)).
- **FR-022**: 다시 발행하면서도 공개 범위를 `PUBLIC` ↔ `PRIVATE`로 바꿀 수 있다 (05 §8, 발행 절차는 → [specs/002-post-authoring](../002-post-authoring/spec.md)).

**기본 공개 범위 (06 V-4, §5)**

- **FR-023**: 회원마다 기본 공개 범위가 있고 처음 값은 `PUBLIC`이다. [새 글]로 만든 임시글은 이 값으로 시작하고, 발행 설정에서 글마다 바꿀 수 있다 (C-POST-4).
- **FR-024**: 기본 공개 범위는 본인만 설정 화면에서 바꿀 수 있다. 비회원은 로그인 필요, 이메일 인증 전 회원은 허용 (42 §9).

**권한 판정 원칙 (42 §1~§4)**

- **FR-025**: System MUST 모든 읽기·쓰기 권한을 서버에서 매번 검사한다. 화면에서 버튼을 숨기는 것은 보조일 뿐이다 (C-OWN-1, 42 P-1).
- **FR-026**: 현재 사용자는 로그인 정보에서만 얻고, 요청에 담긴 작성자 번호는 무시한다 (02 §5, 42 §12 #2).
- **FR-027**: 행위자는 비회원, 인증 전 회원(이메일 가입이고 인증하지 않음, 소셜 가입은 가입 시 인증된 것으로 봄), 회원(작성자가 아닌 다른 회원), 작성자(대상의 작성자 = 현재 사용자; 글이면 블로그 주인, 댓글이면 댓글 쓴 사람), 관리자, 정지 회원, 탈퇴 유예 회원으로 나눈다 (42 §2).
- **FR-028**: 모든 요청은 ① 로그인 필요 → ② 계정 상태 → ③ 대상을 볼 수 있나 → ④ 이 행동을 할 권한 → ⑤ 업무 규칙 순서로 검사하고 처음 걸린 단계의 응답을 준다. 계정 상태 검사(②)는 대상 확인(③)보다 먼저 해서 대상의 존재를 드러내지 않는다 (42 P-2, §3).
- **FR-029**: 응답 종류를 하나로 통일한다 (42 P-3, §4):
  - 로그인이 필요한데 비회원 → 로그인 필요(401), 화면은 로그인 화면으로 이동하고 로그인 후 원래 페이지로 돌아온다.
  - 계정 상태 때문에 할 수 없음(이메일 인증 전, 탈퇴 유예, 정지) → 계정 상태 거부(403) + 이유 + 해결 방법 안내(인증 메일 다시 보내기 / 복구 화면).
  - 대상 없음·볼 수 없음·내 것이 아님·관리자 전용(로그인한 일반 회원) → 404, 이유를 세분화하지 않는다.
  - 요청이 업무 규칙에 어긋남(자기 것 신고 등) → 규칙 위반(400) + 해당 위치 안내.
  - 상태 충돌(편집 버전 충돌, 닉네임 변경 제한 등) → 충돌(409).
  - "남의 것이라서 안 됨"에는 계정 상태 거부(403)를 쓰지 않는다 (42 P-4).
- **FR-030**: 정지 회원은 로그인할 수 없고, 정지하는 순간 모든 기기에서 로그아웃된다. 로그인 시도에는 "정지된 계정이에요 (~날짜까지). 사유: …"를 보여준다. 정지 회원은 사이트에서 비회원과 같고, 이미 쓴 글·댓글은 그대로 보인다. 정지 계정에서 온 쓰기 요청은 정지 계정 거부(403)로 응답한다 (42 P-7, 2026-10-07 H7).
- **FR-031**: 탈퇴 유예 회원은 로그인하면 복구 화면(복구하기 / 로그아웃)만 보고, 그 밖의 모든 요청은 탈퇴 계정 거부(403)로 응답한다 (42 P-12, 2026-10-07 H7).
- **FR-032**: 이메일 인증 전 회원은 글 만들기·저장·발행·변경 취소·공개 범위 변경, 댓글 쓰기·수정, 사진 업로드(프로필 사진 변경 포함), 좋아요, 신고가 막히고(계정 상태 거부), 자기 글 삭제·복구·영구 삭제, 자기 댓글 삭제, 닉네임·소개 수정, 비밀번호 변경, 기본 공개 범위 변경, 회원 탈퇴, 팔로우, 내 글 관리, 자기 알림 보기는 할 수 있다 (42 P-6, §5~§10, 07 L-2).

**글 권한 매트릭스 (42 §5)**

- **FR-033**: 글 상세 보기는 다음을 따른다 (42 §5-1):

  | 글 상태 | 비회원 | 인증 전·회원 | 작성자 | 관리자 |
  |---|:-:|:-:|:-:|:-:|
  | 발행 · 전체 공개 | 보임 | 보임 | 보임 | 보임 |
  | 발행 · 나만 보기 | 404 | 404 | 보임 (비공개 표시) | 404 |
  | 수정 중 | 마지막 발행본 | 마지막 발행본 | 마지막 발행본 + "수정 중" 안내 | 마지막 발행본 |
  | 임시글 | 404 | 404 | 보임 ("임시저장" 표시) | 404 |
  | 휴지통 | 404 | 404 | 404 (휴지통 목록에서만) | 404 |
  | 관리자 숨김 | 404 | 404 | 보임 + "운영 정책에 따라 숨겨진 글이에요" | 관리자 화면(신고 스냅샷)에서만 |
  | 작성자가 탈퇴 유예 | 404 | 404 | 복구 화면만 | 404 |

- **FR-034**: 글 쓰기 행동은 다음을 따른다 (42 §5-2):

  | 행동 | 비회원 | 인증 전 | 회원(남의 글) | 작성자 | 관리자(남의 글) |
  |---|:-:|:-:|:-:|:-:|:-:|
  | 새 글 만들기 | 401 | 403 | — | 허용 | — |
  | 자동 저장·수동 저장 | 401 | 403 | 404 | 허용 | 404 |
  | 발행·다시 발행 | 401 | 403 | 404 | 허용 | 404 |
  | 변경 취소(작업본 삭제) | 401 | 403 | 404 | 허용 | 404 |
  | 공개 범위 변경 | 401 | 403 | 404 | 허용 | 404 |
  | 삭제(휴지통으로) | 401 | 허용 | 404 | 허용 | 404 |
  | 복구·영구 삭제 | 401 | 허용 | 404 | 허용(휴지통 글만, 아니면 404) | 404 |
  | 숨김·숨김 해제 | 401 | 404 | 404 | 404 | 허용 |

  휴지통 글에 대한 저장·발행·공개 범위 변경은 작성자라도 404다.
- **FR-035**: 관리자는 남의 글·댓글을 숨기거나 숨김 해제만 할 수 있고, 내용 수정·삭제는 할 수 없다. 관리자도 자기 글에서는 작성자다 (42 P-11).

**다른 기능의 권한 (42 §6~§10, 세부 규칙은 각 기능 스펙)**

- **FR-036**: 댓글 (→ [specs/007-comment](../007-comment/spec.md)): 보기는 글을 볼 수 있는 사람만(아니면 404). 쓰기·답글은 비회원 401, 인증 전 403, 회원·관리자 허용. 수정은 댓글 작성자만(인증 전 403, 숨긴 댓글은 작성자도 불가). 삭제는 댓글 작성자만(인증 전 회원도 본인 것은 가능). 글 주인도 남의 댓글에 대해서는 일반 회원과 같아 수정·삭제할 수 없다(404). 숨긴 댓글에는 아무도 답글을 달 수 없다(규칙 위반) (42 §6, P-8).
- **FR-037**: 좋아요 (→ [specs/009-like-view](../009-like-view/spec.md)): 좋아요 수는 글을 볼 수 있으면 누구나 본다. 누르기·취소는 비회원 401, 인증 전 403, 볼 수 없는 글 404, 자기 글은 규칙 위반 400(2026-10-07 결정, 42 P-9), 이미 그 상태여도 성공. 판정 순서는 로그인 → 계정 상태 → 볼 수 있나 → 자기 글 → 요청 횟수다(42 §3) (42 §7).
- **FR-038**: 신고 (→ [specs/014-report-hide](../014-report-hide/spec.md)): 글·댓글 신고는 비회원 401, 인증 전 403, 회원·관리자는 볼 수 있는 것만, 자기 것은 규칙 위반. 같은 대상을 다시 신고하면 새로 만들지 않고 성공. 신고 목록 보기·처리는 관리자만, 그 외 404 (42 §8).
- **FR-039**: 프로필·계정 (→ [specs/001-account-auth](../001-account-auth/spec.md), [specs/015-withdraw](../015-withdraw/spec.md)): 블로그·프로필 보기는 누구나(탈퇴 유예·익명 처리된 주소는 404). 닉네임·소개 수정, 비밀번호 변경, 기본 공개 범위, 탈퇴는 본인만(인증 전 허용). 프로필 사진 변경은 인증 전 403. 남의 프로필을 수정하는 경로는 없다. 남이 올린 사진을 프로필·글에 지정하면 규칙 위반. 회원 정지·해제는 관리자만(자기 자신은 불가), 그 외 404 (42 §9·§10).
- **FR-040**: 내 글 관리는 로그인 필요(비회원 401)이고 로그인 정보로 본인 글만 보여준다. 관리자에게도 남의 글 관리 화면은 없다. 사진 업로드는 비회원 401, 인증 전 403 (42 §10, → [specs/006-manage-delete](../006-manage-delete/spec.md)).
- **FR-041**: 팔로우·피드 (→ [specs/010-follow-feed](../010-follow-feed/spec.md)): 팔로워·팔로잉 수·목록 보기는 누구나. 팔로우·언팔로우는 비회원 401, 인증 전 허용, 자기 자신은 규칙 위반. 피드는 로그인 필요. 없는 블로그·탈퇴 유예 블로그 대상은 404. 탈퇴 유예 회원은 남의 팔로워·팔로잉 목록과 수에서 빠지고, 피드는 FR-009 공용 조건을 쓴다 (42 §10-1).
- **FR-042**: 태그 (→ [specs/008-tag](../008-tag/spec.md)): 태그별 목록·전체 태그 목록은 누구나 보고 공개·발행 글만 센다(숨김 제외 포함). 태그 자동완성은 로그인 필요(비회원 401)다 (2026-10-07 결정, 42 §10-2 수정). 태그 붙이기는 발행 권한을 따른다.
- **FR-043**: 알림 (→ [specs/011-notification](../011-notification/spec.md)): 목록·안 읽은 수·읽음 처리·삭제는 받은 사람 본인만(비회원 401, 인증 전도 본인 것은 허용), 다른 회원과 관리자는 404. 알림 주소에 회원 번호를 넣지 않는다. 탈퇴 유예 회원에게는 알림을 만들지 않는다 (42 §10-3).
- **FR-044**: 관리자 화면 주소 전체는 로그인을 요구해 비회원에게는 있는 주소·없는 주소 모두 로그인 필요(401)이고, 로그인한 일반 회원에게는 404다 (42 P-10).

**화면 표시 (42 §11, 2026-10-07 H6)**

- **FR-045**: 화면은 서버 판정과 별개로 다음 조건에서만 버튼을 보여준다: 글 상세 [수정]·[삭제]·[공개 범위]는 작성자에게만. [좋아요]·[신고]는 작성자가 아닐 때(비회원·인증 전 회원 포함) 보이고, 작성자에게는 좋아요 수만 보인다. 비회원·인증 전 회원이 [좋아요]·[신고]·[팔로우]를 누르거나 댓글 입력창을 쓰려 하면 로그인 또는 이메일 인증 안내가 나오고, 로그인 후 원래 글로 돌아오되 자동으로 실행되지 않는다. 댓글 입력창은 비회원에게 "로그인하고 댓글 쓰기", 인증 전 회원에게 "이메일 인증 후 댓글을 쓸 수 있어요 [인증 메일 다시 보내기]". 댓글 [수정]·[삭제]는 댓글 작성자에게만, 숨긴 댓글의 [수정]·[답글]은 보이지 않는다. 작성자 카드의 [팔로우]는 내 글이 아닐 때만. 댓글 [신고]는 댓글 작성자가 아닐 때. [숨김]·[숨김 해제]는 관리자에게만.
- **FR-046**: 내 글 관리에서는 작성자에게 공개 범위 표시(🌐 전체 공개 / 👥 친구 공개 / 🔒 나만 보기)를 보여준다 (06 §3, → [specs/006-manage-delete](../006-manage-delete/spec.md)).

**자동 검증 (06 §8, 42 §12)**

- **FR-047**: 공개 범위(`PUBLIC`/`PRIVATE`, 적용자는 `FRIENDS` 추가) × 보는 사람(비회원/다른 회원/친구/작성자) × 노출되는 곳(상세/홈/블로그 목록/블로그 글 수/태그/검색/sitemap/댓글)의 모든 조합과, 행위자 × 대상 상태 × 행동(FR-033~FR-044)의 모든 칸을 실제 데이터 저장소를 쓰는 자동 통합 테스트로 확인해야 한다.

**(선택 구현) 친구 공개 `FRIENDS` (06 §6-1·§6-3)**

- **FR-048**: `FRIENDS`를 적용한 사람에게만: 친구 공개 글은 작성자와 수락된 친구만 읽고, 그 밖의 사람에게는 404 + 검색 엔진 수집 금지다. 친구가 보는 개인 블로그 목록과 블로그 글 수에만 포함되고, 홈·인기 글·태그·검색·AI 추천·sitemap·RSS에는 나오지 않는다. 친구가 보는 블로그 목록은 최초 발행 일자 최신순(같으면 번호 큰 순)으로 정렬한다(친구 공개 글은 최초 공개 일자가 없음). 친구 관계를 끊으면 그 순간부터 상대는 상세 404, 목록에서 사라진다. 친구 공개 → 전체 공개로 바꾸면 그 순간이 최초 공개 일자가 되어 홈 맨 위에 나온다. 기본 공개 범위가 친구 공개인데 친구가 없으면 발행 설정에 "아직 친구가 없어서 지금은 나만 볼 수 있어요. [친구 초대] [전체 공개로 바꾸기]"를 보여준다.
- **FR-049**: `FRIENDS`를 적용하지 않은 환경은 `FRIENDS` 값을 받지 않는다(잘못된 공개 범위). 친구 맺기(요청·수락)와 친구에게 보이는 최근 활동은 `FRIENDS` 적용 여부와 무관한 공통 기능이며 → [specs/001-account-auth](../001-account-auth/spec.md)가 맡는다 (06 §6-2·§6-4, C-FRIEND-1·C-ACT-1).

### Key Entities *(include if feature involves data)*

- **글의 공개 범위**: 글마다 하나. `PUBLIC` / `PRIVATE`(적용자는 `FRIENDS` 추가). 발행된 글에만 노출 의미가 있고, 임시글에서는 발행할 때 쓸 값이다.
- **최초 공개 일자**: 글이 처음 "발행됨 + 전체 공개"가 된 일자. 한 번 정해지면 바뀌지 않으며 목록 정렬 기준이 된다. 전체 공개로 발행된 글에는 반드시 있다.
- **회원의 기본 공개 범위**: 회원마다 하나, 처음 값 `PUBLIC`. 새 글의 시작 값.
- **행위자(계정 상태)**: 회원의 권한(일반/관리자), 상태(정상/정지/탈퇴 유예), 이메일 인증 여부, 탈퇴 신청 일자. 권한 판정의 입력이다.
- **글 노출 상태**: 글 상태(임시/발행), 휴지통 일자, 관리자 숨김 일자, 작성 중 작업본 유무. 공개 범위와 함께 읽기 판정의 입력이다.
- **친구 관계** (참조): 두 회원 사이 한 쌍에 하나, 요청 중/수락됨. `FRIENDS` 판정에 쓰이며 정의는 → [specs/001-account-auth](../001-account-auth/spec.md).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 공개 범위 × 보는 사람 × 노출되는 곳, 행위자 × 대상 상태 × 행동의 권한 매트릭스 자동 테스트가 모든 칸에서 100% 통과한다.
- **SC-002**: 볼 수 없는 글과 존재하지 않는 글에 대한 응답(상태 코드·본문·미리보기 문구)을 비교했을 때 구별 가능한 차이가 0건이다.
- **SC-003**: 남의 글·댓글에 대한 수정·삭제·발행·공개 범위 변경 요청 후 바뀐 데이터가 0건이다.
- **SC-004**: `PUBLIC`이 아닌 글이 다른 사람이 보는 공개 화면(홈·블로그·태그·검색·피드·sitemap)과 글 수에 나타나는 경우가 0건이다.
- **SC-005**: 공개 범위 변경은 다시 발행 없이 다음 요청부터 반영되고, 공개 → 비공개 → 공개를 반복해도 목록 위치가 바뀌는 경우가 0건이다.
- **SC-006**: 회원 정지 직후 그 회원의 모든 기기 로그인이 즉시 끊기고, 정지 기간 중 로그인 성공이 0건이다.
- **SC-007**: 비회원이 관리자 화면의 있는 주소와 없는 주소를 열었을 때 응답 차이가 0건이다.
- **SC-008**: 같은 상황(행위자·대상 상태·행동)에서 기능마다 다른 응답 종류가 나오는 경우가 0건이다.

## Implementation Notes (for /speckit-plan)

- **읽기 판정** ([02 §4-2](../../docs/02-architecture.md), [06 §7](../../docs/06-visibility.md)): `PostAccessPolicy.canRead(post, viewer)` 하나. 순서: 존재 & `deleted_at IS NULL` → 작성자 본인이면 표시(임시·비공개·숨김 포함) → 아니면 `status = PUBLISHED AND visibility = PUBLIC AND hidden_at IS NULL AND 작성자 withdrawn_at IS NULL`. 공개 범위 값마다 `VisibilityRule { visibility(); canRead(post, viewer); listCondition(viewer, authorId) }` Bean(공통은 PUBLIC·PRIVATE, 적용자는 `FriendsVisibilityRule`). 목록은 `PostQueryRepository`의 `VisibilityFilter.forViewer(viewer, author)`만 사용. 오류는 `PostNotFoundException`(→404) 하나.
- **공용 조건 = 인덱스 조건** (06 R-2b, 2026-10-07 H1): `ix_post_feed (first_public_at DESC, id DESC)`·`ix_post_blog (author_id, first_public_at DESC, id DESC)` 모두 `WHERE status = 'PUBLISHED' AND visibility = 'PUBLIC' AND deleted_at IS NULL AND hidden_at IS NULL`. 쿼리는 여기에 `member.withdrawn_at IS NULL`을 더한다. Testcontainers 통합 테스트에서 홈·블로그 대표 쿼리 EXPLAIN에 두 인덱스가 나오는지 확인. 휴지통 누락 방지로 `Post`에 `@SQLRestriction("deleted_at IS NULL")`(13 §2-6).
- **공개 범위 변경 API** ([06 §4](../../docs/06-visibility.md), PATCH → PUT은 plan R-20): `PUT /api/posts/{postId}/visibility { "visibility": "PRIVATE" }` → `200 { visibility, firstPublicAt }` / `400 INVALID_VISIBILITY` / `404`. 행 잠금(`SELECT … FOR UPDATE`) 후 `UPDATE post SET visibility = :to, first_public_at = CASE WHEN first_public_at IS NULL AND status = 'PUBLISHED' AND :to = 'PUBLIC' THEN now() ELSE first_public_at END, updated_at = now() WHERE id = :postId AND author_id = :me AND deleted_at IS NULL`. 커밋 후 `PostVisibilityChanged(postId, from, to)`. 메서드는 O8([02 §5-1](../../docs/02-architecture.md) "상태 지정은 PUT·DELETE")과 맞춰 계획에서 확정.
- **캐시** (06 R-5, 40 R-9): `PUBLIC`이 아닌 글 응답 `Cache-Control: private, no-store`, CDN 캐시 키에 넣지 않음. 404 화면 OG: `og:title "볼 수 없는 글이에요"`, `og:description "친구 공개·비공개 글이거나 삭제된 글입니다."`, `<meta name="robots" content="noindex">`.
- **스키마** ([51](../../docs/51-erd-unified.md)): `post.visibility`(`ck_post_visibility` PUBLIC/PRIVATE), `post.first_public_at`(`ck_post_public_at`: 공개 발행이면 NOT NULL), `post.edited_at`, `post.hidden_at`, `post.deleted_at`, `member.default_visibility`(기본 `'PUBLIC'`, `ck_member_default_visibility`), `member.role`(USER/ADMIN), `member.status`(ACTIVE/SUSPENDED/WITHDRAWN), `member.withdrawn_at`, `auth_identity.email_verified_at`, `friendship`(V1 포함, `ck_friendship_order`).
- **`FRIENDS` 적용 마이그레이션** ([06 §6-1](../../docs/06-visibility.md)): `V{n}__friends.sql` — `ck_post_visibility`·`ck_member_default_visibility`를 `('PUBLIC', 'FRIENDS', 'PRIVATE')`로 교체, `CREATE INDEX ix_post_blog_friends ON post (author_id, published_at DESC, id DESC) WHERE status = 'PUBLISHED' AND visibility IN ('PUBLIC', 'FRIENDS') AND deleted_at IS NULL AND hidden_at IS NULL`. 친구 판정 `member_a_id = LEAST(:author, :viewer) AND member_b_id = GREATEST(:author, :viewer) AND status = 'ACCEPTED'`. 친구 블로그 커서 `k = (published_at, id)`.
- **응답 코드·이유 코드** ([42 §4](../../docs/42-permission-matrix.md), [02 §5·§5-1](../../docs/02-architecture.md)): 401 `LOGIN_REQUIRED`, 403 `EMAIL_NOT_VERIFIED`·`ACCOUNT_WITHDRAWN`·`ACCOUNT_SUSPENDED`, 404 `NOT_FOUND`(하나로), 400 `CANNOT_LIKE_OWN_POST`·`CANNOT_REPORT_OWN`·`CANNOT_FOLLOW_SELF`·`INVALID_PROFILE_IMAGE`·`REPLY_TARGET_UNAVAILABLE`, 409 `VERSION_CONFLICT`·`NICKNAME_CHANGE_TOO_SOON`. 오류 본문 `{ code, message, errors: [{ field, code, message }], details }`.
- **인증·세션** ([02 §5](../../docs/02-architecture.md)): 현재 사용자는 Spring Security 세션(Spring Session + Redis, `HttpOnly`·`Secure`·`SameSite=Lax` 쿠키 + CSRF 토큰, 저장 방식 M17)에서만. 소유 검사는 Service에서 `author_id = currentUserId` 조건 조회 → 없으면 404(③·④를 한 번에). 정지·탈퇴·비밀번호 변경 시 그 회원의 Redis 세션 삭제. `/admin/**` 전체 인증 필요(Spring Security 기본 설정), 일반 회원 404. Redis 장애 시 세션 조회 실패는 비로그인 처리(02 §2-1).
