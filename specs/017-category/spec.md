## Clarifications

### Session 2026-10-08

- Q: 블로그는 회원과 따로 두는가(01 §2-4의 `blog` 분리)? → A: 이번 기능에서는 블로그 = 회원 한 명(공통 `/@handle`)으로 두고, 카테고리는 회원에게 딸린다. 블로그 분리는 범위 밖 (FR-001) (민서 확정 2026-10-08, 추천안)
- Q: 글의 카테고리는 언제 저장되는가? → A: 글쓰기 화면에서 고르는 즉시 저장한다. 공개 범위 변경(004)과 같은 "상태 지정" 방식이며 발행·자동 저장·작업본 버전과 무관하다. 발행한 글도 바로 반영된다 (FR-020~023) (민서 확정 2026-10-08, 추천안)
- Q: 상위 카테고리를 누르면 하위 카테고리의 글도 보이는가? → A: 보인다. 상위 카테고리 글 수도 하위 글을 포함한다(티스토리와 같음) (FR-029·FR-031) (민서 확정 2026-10-08, 추천안)
- Q: 하위 카테고리가 있는 카테고리를 지우면? → A: 지우지 않고 409 `CATEGORY_HAS_CHILDREN`. 하위를 먼저 옮기거나 지워야 한다. 지운 카테고리의 글은 "분류 없음"이 된다 (FR-014·FR-015) (민서 확정 2026-10-08, 추천안)
- Q: 글이 없는 카테고리도 블로그 사이드바에 보이는가? → A: 보인다(글 수 0). 주인이 만든 블로그 구조이기 때문이다 (FR-028) (민서 확정 2026-10-08, 추천안)
- Q: 순서는 어떻게 바꾸는가? → A: 같은 상위 안에서 [위로]·[아래로] 버튼으로 바꾼다. 다른 상위로 옮기기는 수정에서 상위 카테고리를 고른다. 끌어 놓기는 범위 밖 (FR-010·FR-012) (민서 확정 2026-10-08, 추천안)
- Q: 티스토리의 비공개 카테고리·"분류 없음" 필터·글 관리 화면의 카테고리 필터도 넣는가? → A: 이번 범위 밖. 다음 확장으로 남긴다 (Assumptions) (민서 확정 2026-10-08, 추천안)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 카테고리 만들고 정리하기 (Priority: P1)

블로그 주인은 "카테고리 관리" 화면에서 최상위 카테고리와 그 아래 하위 카테고리를 만들고, 이름을 바꾸고, 순서를 바꾸고, 다른 상위로 옮기고, 지운다. 카테고리는 2단계까지다.

**Why this priority**: 카테고리가 있어야 글을 분류하고 블로그에서 모아 볼 수 있다. 나머지 이야기가 모두 이것에 기대고 있다.

**Independent Test**: 로그인한 회원이 "개발"·"일상"을 만들고 "개발" 아래 "Spring"·"React"를 만든 뒤, 이름 바꾸기·순서 바꾸기·옮기기·지우기를 해 보고 관리 화면과 API 응답의 나무 모양이 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 카테고리가 없는 회원, **When** "개발"을 만들면, **Then** 최상위 맨 아래에 "개발"이 생긴다
2. **Given** "개발", **When** 상위를 "개발"로 골라 "Spring"을 만들면, **Then** "개발" 아래 맨 아래에 생긴다
3. **Given** "개발 > Spring", **When** "Spring" 아래에 카테고리를 만들려고 하면, **Then** 400 `CATEGORY_DEPTH_EXCEEDED`로 거부된다
4. **Given** "개발" 아래 "Spring", **When** "개발" 아래에 "spring "(대소문자·앞뒤 공백만 다름)을 만들면, **Then** 409 `CATEGORY_NAME_DUPLICATED`로 거부된다. "일상" 아래의 "Spring"은 만들 수 있다
5. **Given** 빈 이름 또는 31자 이름, **When** 만들거나 바꾸면, **Then** 400 `VALIDATION_FAILED`(칸 `name`, `CATEGORY_NAME_REQUIRED`·`CATEGORY_NAME_TOO_LONG`)다
6. **Given** "개발"·"일상" 순서, **When** "일상"의 [위로]를 누르면, **Then** "일상"·"개발" 순서가 된다. 다시 불러와도 그 순서다
7. **Given** "개발 > Spring", **When** "Spring"의 상위를 "일상"으로 바꾸면, **Then** "일상" 아래 맨 아래로 옮겨진다. 상위를 "없음"으로 바꾸면 최상위가 된다
8. **Given** 하위가 있는 "개발", **When** "개발"을 다른 카테고리 아래로 옮기려 하면, **Then** 400 `CATEGORY_DEPTH_EXCEEDED`다
9. **Given** 하위가 있는 "개발", **When** 지우면, **Then** 409 `CATEGORY_HAS_CHILDREN`이고 아무것도 지워지지 않는다
10. **Given** 글 3개가 있는 "Spring", **When** 지우기를 누르면, **Then** "글 3개는 분류 없음이 돼요" 확인 창이 뜨고, 확인하면 지워지며 그 글들은 분류 없음이 된다
11. **Given** 카테고리 100개(설정값)를 가진 회원, **When** 하나 더 만들면, **Then** 400 `TOO_MANY_CATEGORIES`다
12. **Given** 남의 카테고리 번호, **When** 바꾸거나 지우려 하면, **Then** 404다(없는 번호와 같은 응답)

### User Story 2 - 글에 카테고리 고르기 (Priority: P1)

작성자는 글쓰기 화면 제목 위의 "카테고리" 선택에서 내 카테고리 하나(또는 "분류 없음")를 고른다. 고르는 즉시 저장된다.

**Why this priority**: 글이 카테고리에 들어가야 블로그에서 카테고리별로 볼 수 있다.

**Independent Test**: 임시글과 발행 글에서 각각 카테고리를 고르고 새로고침해 유지되는지, 남의 카테고리 번호를 보내면 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 임시글의 글쓰기 화면, **When** "개발 > Spring"을 고르면, **Then** 즉시 저장되고 새로고침해도 "개발 > Spring"이 골라져 있다
2. **Given** 발행한 글, **When** 카테고리를 바꾸면, **Then** 다시 발행하지 않아도 블로그의 카테고리 목록에 바로 반영되고 "수정됨"은 붙지 않는다
3. **Given** "분류 없음"을 고르면, **Then** 글의 카테고리가 비워진다
4. **Given** 남의 카테고리 번호 또는 없는 번호, **When** 지정하면, **Then** 400 `INVALID_CATEGORY`다
5. **Given** 남의 글·휴지통 글·없는 글, **When** 카테고리를 지정하면, **Then** 404다. 비회원은 401, 이메일 인증 전·정지·탈퇴 유예 회원은 403이다(004 판정 순서)
6. **Given** 카테고리가 하나도 없는 회원, **Then** 선택에는 "분류 없음"과 [카테고리 관리] 링크만 보인다
7. **Given** 저장이 실패하면, **Then** 선택이 이전 값으로 돌아가고 "카테고리를 저장하지 못했어요"가 보인다. 글쓰기·자동 저장은 막히지 않는다

### User Story 3 - 블로그에서 카테고리별로 보기 (Priority: P1)

독자는 개인 블로그의 카테고리 목록(사이드바)에서 "분류 전체보기"와 각 카테고리의 공개 글 수를 보고, 카테고리를 누르면 그 카테고리 글만 블로그 목록과 같은 카드·9개·[더 보기]로 본다.

**Why this priority**: 티스토리형 블로그의 핵심 탐색 방식이다.

**Independent Test**: 공개·비공개·임시·휴지통·숨김 글을 여러 카테고리에 넣고 비회원으로 블로그를 열어 카테고리 글 수·목록에 공개 글만 나오는지, 상위 카테고리가 하위 글을 포함하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "개발"(직접 1개) > "Spring"(공개 2개)·"React"(공개 1개), **When** 블로그를 열면, **Then** 사이드바에 "분류 전체보기 (전체 공개 글 수)", "개발 (4)", 그 아래 "Spring (2)", "React (1)"이 관리 화면 순서대로 보인다
2. **Given** 같은 카테고리의 비공개·임시·휴지통·관리자 숨김 글, **Then** 글 수와 목록 어디에도 나오지 않는다. 주인이 봐도 같다(블로그 목록과 같은 조건)
3. **Given** "개발" 카테고리, **When** 누르면, **Then** 주소가 `/@handle?category={번호}`가 되고, 머리에 "개발 · 글 4개 [전체 보기]"와 "개발"·"Spring"·"React" 글이 최신순 카드로 보인다
4. **Given** "Spring", **When** 누르면, **Then** "Spring" 글만 보인다
5. **Given** 없는 번호·다른 블로그의 카테고리 번호·숫자가 아닌 값, **When** `?category=`로 열면, **Then** 찾을 수 없음(404)이다(페이지 주소는 서버가 404 화면)
6. **Given** 글이 없는 카테고리, **When** 누르면, **Then** "이 카테고리에는 아직 공개된 글이 없어요"가 보인다
7. **Given** 카테고리가 하나도 없는 블로그, **Then** 사이드바를 그리지 않는다. 주인에게는 [카테고리 만들기] 링크가 보인다
8. **Given** 375px 화면, **Then** 카테고리 목록은 글 목록 위에 접힌 "카테고리" 버튼으로 보이고, 가로 스크롤이 없다

### User Story 4 - 글 상세에서 카테고리 경로 보기 (Priority: P2)

독자는 글 상세 제목 위에서 "개발 › Spring" 같은 카테고리 경로를 보고, 누르면 블로그의 그 카테고리 목록으로 간다.

**Why this priority**: 독자가 같은 주제의 다른 글로 이어 가게 해 주지만, 없어도 글 읽기는 된다.

**Independent Test**: 하위·최상위·분류 없음 글의 상세를 열어 경로 표시와 링크를 확인한다.

**Acceptance Scenarios**:

1. **Given** "개발 > Spring" 글, **Then** 제목 위에 "개발 › Spring"이 보이고 각 이름은 그 카테고리 블로그 목록 링크다
2. **Given** 최상위 "일상" 글, **Then** "일상"만 보인다
3. **Given** 분류 없는 글, **Then** 경로가 보이지 않는다
4. **Given** 카테고리 조회가 실패하면, **Then** 경로 없이 글은 정상으로 보인다(원칙 V)

### Edge Cases

- 카테고리 이름은 글자로만 다룬다(HTML·Markdown 해석 없음). `<b>개발</b>`은 그 글자 그대로 보인다(원칙 IV)
- 이름의 앞뒤 공백은 지우고, 안쪽 연속 공백은 하나로 줄인다. 중복 비교는 정리한 이름의 소문자(`Locale.ROOT`)로 한다
- 같은 상위 아래에서만 이름이 겹치면 안 된다. 다른 상위 아래에는 같은 이름이 있어도 된다
- 두 탭에서 동시에 순서를 바꾸면 늦게 보낸 쪽이 지금 목록과 다를 수 있다 → 409 `CATEGORY_ORDER_STALE`, 화면은 새로 불러온다
- 동시에 같은 이름을 만들면 하나만 성공한다(DB 유일 인덱스)
- 카테고리를 지우는 순간 그 카테고리를 고르고 있던 글쓰기 화면은, 다음에 열 때 "분류 없음"으로 보인다
- 상위 카테고리를 다른 상위 아래로 옮기려면 하위가 없어야 한다(2단계 유지)
- 자기 자신을 상위로 고를 수 없다(400 `CATEGORY_DEPTH_EXCEEDED`와 같은 이유로 거부 — 자기 아래로 들어가는 것도 깊이를 깨기 때문이다)
- 회원이 탈퇴 후 30일이 지나 익명 처리되면 그 회원의 카테고리는 모두 지워진다(015 정리 단계)
- 글을 완전 삭제해도 카테고리는 남는다
- 친구 공개 규격을 적용한 사람이라면 카테고리 글 수·목록은 블로그 목록과 같은 조건(`VisibilityFilter.forViewer`)을 쓴다

## Requirements *(mandatory)*

### Functional Requirements

**카테고리**

- **FR-001**: 카테고리는 회원(블로그 주인) 한 명에게 딸려야 한다. 블로그를 회원과 따로 두지 않는다 (Clarifications)
- **FR-002**: 카테고리는 최상위와 하위의 2단계까지만 있어야 한다. 하위 아래에는 만들 수 없다 → 400 `CATEGORY_DEPTH_EXCEEDED`
- **FR-003**: 이름은 앞뒤 공백을 지우고 안쪽 공백 묶음을 한 칸으로 줄인 뒤 1~30자(유니코드 코드 포인트)여야 한다 → 칸 `name` `CATEGORY_NAME_REQUIRED`·`CATEGORY_NAME_TOO_LONG` (400 `VALIDATION_FAILED`)
- **FR-004**: 같은 상위(최상위끼리 포함) 아래에서 이름은 대소문자를 무시하고 겹치면 안 된다 → 409 `CATEGORY_NAME_DUPLICATED`. 동시 요청에도 DB가 막아야 한다
- **FR-005**: 한 회원의 카테고리 수는 설정값(`blog.category.max-count`, 기본 100) 이하여야 한다 → 400 `TOO_MANY_CATEGORIES`
- **FR-006**: 카테고리 이름은 글자로만 다루어야 한다(원칙 IV)

**카테고리 관리 (주인만)**

- **FR-007**: 시스템은 내 카테고리 나무(순서대로, 각 카테고리의 내 글 수 — 공개 범위·발행 여부 무관, 휴지통 제외)를 돌려주어야 한다
- **FR-008**: 만들기: 이름과 상위(없으면 최상위)를 받아 그 상위의 맨 아래에 붙여야 한다. 상위가 내 최상위 카테고리가 아니면(없음·남의 것) 400 `INVALID_CATEGORY`, 하위면 400 `CATEGORY_DEPTH_EXCEEDED`
- **FR-009**: 수정: 이름과 상위를 바꿀 수 있어야 한다. 상위가 바뀌면 새 상위의 맨 아래로 간다. 하위가 있는 카테고리는 다른 카테고리 아래로 갈 수 없다
- **FR-010**: 순서: 같은 상위 아래 카테고리 번호 전체를 새 순서로 받아 저장해야 한다. 보낸 번호 묶음이 지금 그 상위의 하위 묶음과 다르면 409 `CATEGORY_ORDER_STALE`
- **FR-011**: 지우기: 하위가 있으면 409 `CATEGORY_HAS_CHILDREN`. 지우면 그 카테고리의 글은 "분류 없음"이 되어야 한다(글은 그대로)
- **FR-012**: 관리 API는 로그인 필요(401), 계정 상태는 글쓰기와 같은 기준(이메일 인증 전·정지·탈퇴 유예 403 — 001 `AccountStatusGuard` `CONTENT_WRITE`), 남의 카테고리와 없는 카테고리는 같은 404여야 한다(원칙 III). 읽기(FR-007)는 로그인만 필요하다
- **FR-013**: 관리 화면은 나무 모양 목록, [추가], 이름 바꾸기, 상위 바꾸기, [위로]·[아래로], [삭제](글이 있으면 "글 N개는 분류 없음이 돼요" 확인)를 제공해야 한다. 내 글 관리 화면과 블로그(주인일 때)에서 이 화면으로 갈 수 있어야 한다
- **FR-014**: 하위가 있는 카테고리의 [삭제]는 이유를 알려 주어야 한다("하위 카테고리를 먼저 옮기거나 지워 주세요")
- **FR-015**: 카테고리를 지워도 글의 내용·발행 상태·"수정됨"은 바뀌지 않아야 한다

**글의 카테고리**

- **FR-020**: 글은 카테고리 하나를 가지거나 "분류 없음"이어야 한다. 최상위와 하위 어느 것이든 고를 수 있다
- **FR-021**: 글의 카테고리 지정은 발행과 별도의 즉시 저장이어야 한다(작업본 버전·자동 저장·"수정됨"과 무관). 판정 순서: 401 → 403(`CONTENT_WRITE`) → 404(없음·남의 글·휴지통) → 400 `INVALID_CATEGORY`(내 카테고리가 아님·없음)
- **FR-022**: 작성자는 글쓰기 화면에서 내 글의 현재 카테고리를 읽을 수 있어야 한다(남의 글은 404)
- **FR-023**: 글쓰기 화면은 제목 위에 카테고리 선택(분류 없음 + 나무 순서, 하위는 들여 씀)과 [카테고리 관리] 링크를 두고, 실패하면 이전 값으로 돌리고 알려야 한다

**블로그에서 보기**

- **FR-028**: 블로그 카테고리 목록은 누구나 볼 수 있어야 하며(블로그를 볼 수 있으면), 모든 카테고리를 순서대로, 각 카테고리의 공개 글 수(블로그 목록과 같은 노출 조건 `VisibilityFilter.forViewer`)와 "분류 전체보기" 수를 보여야 한다. 글 0인 카테고리도 보인다
- **FR-029**: 최상위 카테고리의 글 수는 그 카테고리와 하위 카테고리 글의 합이어야 한다
- **FR-030**: 블로그 글 목록은 `category` 조건을 받아 그 카테고리 글만 블로그 목록과 같은 카드·순서·9개·커서로 보여 주어야 한다. 커서는 그 조건 안에서만 쓸 수 있다(다른 목록 커서 400 `INVALID_CURSOR`)
- **FR-031**: 최상위 카테고리 조건은 하위 카테고리 글을 포함해야 한다
- **FR-032**: 없는 번호·다른 블로그의 카테고리·형식이 맞지 않는 값은 404여야 한다. 블로그 페이지 주소 `/@handle?category=`도 서버가 404 화면을 준다
- **FR-033**: 블로그 화면은 데스크톱에서 글 목록 옆에, 375px에서는 글 목록 위 접힌 버튼으로 카테고리 목록을 보여 주고, 고른 카테고리는 강조와 머리 "이름 · 글 N개 [전체 보기]"로 보여야 한다. 태그 필터와 카테고리 필터는 함께 쓰지 않는다(하나를 고르면 다른 하나는 풀린다)
- **FR-034**: 카테고리 목록·카테고리 글 목록은 카테고리·카드마다 따로 조회하지 않아야 한다(N+1 금지)

**글 상세**

- **FR-040**: 글 상세 응답은 카테고리 경로(상위가 있으면 상위 → 자기, 각 번호·이름)를 담고, 분류 없음이면 `null`이어야 한다. 조회가 실패하면 `null`로 계속 응답한다(원칙 V)
- **FR-041**: 글 상세 화면은 제목 위에 경로를 보여 주고, 각 이름은 `/@handle?category={번호}` 링크여야 한다

**탈퇴**

- **FR-050**: 탈퇴 30일 정리 때 그 회원의 카테고리를 모두 지워야 한다(015 정리 단계, 글 삭제 단계 뒤)

### Key Entities *(include if feature involves data)*

- **카테고리**: 주인(회원), 상위 카테고리(없으면 최상위), 이름(1~30자), 같은 상위 안 순서, 만든·바꾼 시각. 같은 주인·같은 상위 안에서 소문자 이름이 유일하다
- **글의 카테고리**: 글 → 카테고리 하나 또는 없음(nullable 컬럼). 카테고리가 지워지면 비워진다
- **카테고리 공개 글 수**: 블로그 목록 노출 조건을 만족하는 그 카테고리(최상위면 하위 포함) 글의 수

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2단계를 넘는 카테고리가 만들어지는 경우가 0건이다(만들기·옮기기 모두)
- **SC-002**: 권한 테스트에서 남의 카테고리를 바꾸거나 지우거나 내 글에 붙이는 데 성공하는 경우가 0건이고, 남의 카테고리·없는 카테고리 응답이 구별되지 않는다
- **SC-003**: 블로그 카테고리 글 수·카테고리 목록에 비공개·임시·휴지통·숨김 글이 0건 나온다
- **SC-004**: 블로그 카테고리 목록은 SQL 2번 이하, 카테고리 글 목록은 카테고리 확인 1번 + 카드 1번으로 끝난다(카테고리·카드 수와 무관)
- **SC-005**: 카테고리 글 목록은 글 1만 건 기준 0.3초 안에 응답한다(02 §6)
- **SC-006**: 375px 화면에서 블로그·카테고리 관리·글쓰기 화면에 가로 스크롤이 없다

## Assumptions

- 블로그 = 회원 한 명이다. 01 §2-4의 `blog` 테이블 분리는 이 기능에 넣지 않는다
- 공통 ERD는 바꾸지 않는다: 새 테이블 `category`와 `post.category_id`(nullable) 컬럼, 인덱스만 Flyway로 더한다(원칙 I, 02 §7)
- 비공개 카테고리, "분류 없음"만 모아 보기, 글 관리 화면의 카테고리 필터·일괄 이동, 끌어 놓기 순서 바꾸기, 카테고리별 RSS는 범위 밖이다
- 카테고리 이름에는 금칙어 검사를 하지 않는다(주인 블로그 안의 분류 이름이며 원문에 규칙이 없다)
- 공통 스펙 001~016 문서는 고치지 않는다. 글 상세 응답에 `category` 필드가 더해지는 것은 005 계약의 확장(필드 추가)이다
- 의존: 계정 상태·블로그 주인 조회(→ 001), 공개 조건 `VisibilityFilter`·권한 판정 순서(→ 004), 블로그 목록·카드·커서·글 상세·페이지 셸(→ 005), 휴지통(→ 006), 탈퇴 정리 단계(→ 015)
